# FC0305 · 코드 형식 규칙의 일관성

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0323](FC0323.md) · [다음 FC: FC0307 →](FC0307.md)

## 검토 질문

- [ ] 팀의 공백·들여쓰기·괄호 규칙을 일관되게 적용하고 자동화할 수 있는가?

**직접 작성한 예시**

```java
if (isReady) {
    process();
}
```

**적용 설명:** 팀의 괄호·들여쓰기·공백 규칙을 자동 포맷터와 맞춘다. 스타일 차이를 기능 결함과 구분한다.

## 구체적인 검토 사례

- [ ] 코드 전반에서 컨벤션에 맞지 않는 부분을 확인해 달라고 요청했다. (개선 제안)
  - 조건: 별도의 전반 점검 요청이며, 댓글 본문에서 구체적인 컨벤션 항목을 지정하지는 않았다.

- [ ] 로그인 요청 처리를 풀어서 구현하는 대신 스트림 방식으로 작성한 이유를 질문했다. (설계 질문)
  - 조건: 대상 코드는 Optional 연쇄 호출이며 대화에서는 이를 스트림으로 지칭한다. 작성자는 개인적으로 가독성이 더 좋다고 생각해 가능한 경우 사용하는 편이라고 설명했다. 리뷰어가 해당 방식을 결함으로 지적하거나 변경을 요구한 것은 아니다.

- [ ] OrderRequest의 orderLineItemRequests 필드명에 문제가 있어 보인다고 지적했다. (관찰)
  - 조건: 인라인 대상으로 필드는 식별되지만, '마찬가지로'가 참조하는 이전 지적은 이 단위에 없다. 구체적인 문제 이유나 대체 이름은 확인할 수 없다.
