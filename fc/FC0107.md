# FC0107 · 비동기 전환의 목적과 실패 처리

[소속 분야: 비동기·동시성](../05-concurrency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0102](FC0102.md)

## 검토 질문

- [ ] 동기 작업을 비동기로 옮긴 이유가 명확하고 완료·실패·자원 제한·경쟁 조건을 처리하는가?

**직접 작성한 예시**

```java
CompletableFuture<Void> renewal = CompletableFuture.runAsync(
    () -> cache.extendTtl(key, ttl), ioExecutor);
renewal.exceptionally(error -> { recordRenewalFailure(error); return null; });
```

**적용 설명:** 가상 동기 캐시 호출을 별도 실행기로 옮긴 예다. 실패 관측·실행기 제한·갱신 전 만료 경쟁을 검토하며 API 이름만으로 비동기를 판단하지 않는다.

## 구체적인 검토 사례

- [ ] **상황:** 완료를 기다리지 않으려고 비동기로 바꾼다.
  - **판단 기준:** 실패 관측과 수명·취소 계약을 정한다.

- [ ] **상황:** 캐시 갱신이 늦게 완료된다.
  - **판단 기준:** 갱신 전 만료나 오래된 쓰기 경쟁을 처리한다.
