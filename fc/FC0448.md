# FC0448 · 테스트 데이터 준비 경로의 일관성

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0443](FC0443.md) · [다음 FC: FC0449 →](FC0449.md)

## 검토 질문

- [ ] 유사 테스트의 준비 경로가 일관되며 준비 과정 자체의 실패를 검증 대상 실패와 구분하는가?

**직접 작성한 예시**

```java
Customer customer = customers.save(sampleCustomer());
Order order = orders.save(sampleOrder(customer.id()));
```

**적용 설명:** 여러 테스트의 준비 경로를 일관되게 한다. 저장소 자체의 결함을 가릴 수 있으므로 준비 실패와 검증 실패를 구분한다.

## 구체적인 검토 사례

- [ ] 해당 테스트뿐 아니라 다른 테스트의 데이터 준비에도 Repository를 사용하도록 함께 정리할 것을 제안한다. (개선 제안)
  - 조건: 작성자는 테스트 데이터 설정이 필요한 부분을 모두 jdbcTemplate에서 Repository로 대체했다고 보고했다. 실제 변경 내용은 제공되지 않았다.

- [ ] 서비스 테스트에서 메모리 DB뿐 아니라 Repository를 모킹하는 방식도 일부 테스트에 시도해보도록 제안한다. (개선 제안)
  - 조건: 다음 단계에서 다양한 테스트 방식을 경험하자는 제안이다. 현업의 환경과 제약이 다를 수 있다는 이유를 들었으며, 현재 메모리 DB 방식이 잘못되었다고 단정하지 않았다.

- [ ] Repository 테스트에 @SpringBootTest보다 적합한 테스트 환경이 있는지 검토하도록 묻는다. (설계 질문)
  - 조건: 작성자는 @DataJpaTest를 사용해 보았고 더 빨라졌다고 보고했으며, 단일 스레드라는 이유로 해당 환경의 @Transactional을 위험하게 느끼지 않는다고 설명했다. 리뷰 참여자는 @DataJpaTest 사용을 긍정적으로 평가했지만, 속도나 트랜잭션 안전성에 관한 작성자의 설명을 별도로 검증하지는 않았다.
