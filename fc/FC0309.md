# FC0309 · 클래스 이름을 명사형으로 표현하도록 CheckAdminInterceptor 대신 AdminCheckInterceptor를 제안했다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0315](FC0315.md) · [다음 FC: FC0300 →](FC0300.md)

- [ ] 클래스 이름을 명사형으로 표현하도록 CheckAdminInterceptor 대신 AdminCheckInterceptor를 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 클래스는 명사형, 메서드는 동사와 명사의 조합으로 명명하는 관례를 근거로 들었다. 작성자는 해당 기준을 확인했으며, 실제 이름 변경 여부는 답변만으로 확정하지 않는다.

- [ ] RequestCreateSectionInfo의 Info 접미사 대신 클래스 역할을 더 잘 드러내는 이름을 사용하도록 제안했다. (개선 제안)
  - 조건: 작성자는 서비스에서 필요한 정보라는 의미로 Info를 붙였다고 설명하며 명명 방식을 질문했다. 리뷰어는 Request/Response 또는 Command/Result를 대안으로 제시했으며 특정 이름으로의 변경 결과는 확인되지 않는다.

- [ ] 클래스 선언의 public class와 클래스 이름 사이에 줄바꿈이 들어간 점을 지적했다. (관찰)
  - 조건: 제공된 코드에서 SpringChessApplication 선언이 두 줄로 나뉘어 있다. 동작상의 결함을 주장한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
final class AdminAccessInterceptor {
    void check(Actor actor) { requireAdmin(actor); }
}
```

**적용 설명:** 클래스가 제공하는 역할을 이름으로 표현한다. check의 실제 접근 정책 구현은 생략했다.
