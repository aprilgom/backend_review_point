# FC0462 · 파싱 경계와 내부 인자 타입

[소속 분야: 타입·타입 테스트](../24-type-safety.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0457](FC0457.md)

## 검토 질문

- [ ] 문자열 변환을 외부 입력 경계에서 처리하고 내부 API는 검증 가능한 구체 타입을 받는가?

**직접 작성한 예시**

```java
void run(int port) {
    if (port < 1 || port > 65535) throw new IllegalArgumentException("port");
    server.bind(port);
}
```

**적용 설명:** 문자열 변환은 CLI·설정 경계에서 처리한다. 테스트용 자동 포트 0을 허용할지는 별도 계약이다.

## 구체적인 검토 사례

- [ ] 포트 번호가 정수만 허용한다면 run이 문자열을 받아 변환하기보다 정수 타입으로 받는 방안을 제안했다. (조건부 제안)
  - 조건: 리뷰 참여자는 설계에 따라 달라질 수 있으므로 작성자가 결정하도록 했다. 작성자는 int를 받으면 기본 포트 지정 책임이 User Service로 이동한다고 반론하며, 그 책임을 Web Server에 두기 위해 null을 허용하는 Integer로 변경했다고 보고했다. 해당 선택에 대한 후속 검증은 없다.

- [ ] ChessDto가 사용되는 곳이 있다면 gameOver를 String 대신 boolean 등 의미에 맞는 타입으로 관리할 것을 제안한다. (조건부 제안)
  - 조건: DTO를 유지하여 사용하는 경우에 한한 제안이다. 실제 사용처와 타입 변경 결과는 제시되지 않았다.

- [ ] 경로 조회의 type 요청 매개변수를 String 대신 Enum으로 받을 수 있다고 제안했다. (개선 제안)
  - 조건: 작성자는 문자열 요청 매개변수를 Enum.valueOf()로 변환해 주는 방식으로 이해했다고 답했다. 변환 방식에 관한 이 설명은 작성자의 이해이며, 실제 변경 여부는 확인되지 않는다.
