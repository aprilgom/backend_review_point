# FC0150 · 실행 대상 인스턴스의 생성 시점

## 검토 질문

- [ ] 호출 대상의 타입만 보관할지 인스턴스를 보관할지 수명·생성 비용·상태 격리 관점에서 결정했는가?

**직접 작성한 예시**

```java
record HandlerMethod(Object target, Method method) {
    Object invoke(Object argument) throws ReflectiveOperationException {
        return method.invoke(target, argument);
    }
}
```

**적용 설명:** 클래스 타입뿐 아니라 호출 대상 인스턴스를 보관하는 대안이다. 생성 시점과 수명 관리 책임을 정한다.

## 구체적인 검토 사례

- [ ] 컨트롤러의 실제 인스턴스를 만들지 않고 클래스 타입만 보관하도록 구현한 이유를 질문한다. (설계 질문)
  - 조건: 컨트롤러 탐색 결과의 보관 방식에 대한 설계 이유를 묻는 질문이며, 즉시 인스턴스화해야 한다는 요구나 현재 방식의 결함 보고는 아니다. 작성자의 설명은 제공되지 않았다.

- [ ] HandlerExecution이 인스턴스를 직접 생성하지 않고 외부에서 주입받도록 선택한 이유와 두 방식의 장단점을 질문했다. (토론)
  - 조건: 작성자는 내부 생성의 캡슐화와 결합도, 외부 주입의 유연성을 비교한 뒤 현재 미션에서는 DI 컨테이너 구현이 의도된 바가 아니라고 판단해 내부 생성으로 리팩터링했다고 보고했다. 리뷰 참여자는 선택 근거가 있으면 어느 방식도 가능하며 현재 단계에서 DI 컨테이너 구현은 필수가 아니라는 의견에 동의했다. 내부 생성으로 바꾸라는 확정 요구는 아니었다.

- [ ] Handler를 static으로 관리할 수도 있는데 인스턴스 필드로 둔 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 인스턴스 필드를 선호하며 서로 다른 컨텍스트가 정적 리소스를 처리하는 방식도 달라질 수 있다고 설명했다. 다만 생성자 내부에서 직접 생성하여 의도가 약해졌다고 보고 DI 방식으로 리팩터링하겠다고 답했다. DI는 작성자가 제시한 대응이며 실제 변경 여부는 확인되지 않는다.
