# FC0098 · 요청마다 스레드를 새로 생성하는 방식에서 어떤 문제가 생길 수 있는지 고민해 보도록 권했다.

[소속 분야: 비동기·동시성](../05-concurrency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0103](FC0103.md) · [다음 FC: FC0104 →](FC0104.md)

- [ ] 요청마다 스레드를 새로 생성하는 방식에서 어떤 문제가 생길 수 있는지 고민해 보도록 권했다. (설계 질문)
  - 조건: 문제 탐색을 위한 질문이며 구체적인 장애나 성능 저하를 확정해 보고한 것은 아니다. 리뷰 참여자는 반영을 강제하지 않았다.

- [ ] 실행 스레드 수만 제한되고 대기 요청 수는 제한되지 않으므로 요청이 많이 몰릴 때의 동작을 추가로 고민해 보자는 제안이다. (개선 제안)
  - 조건: 관련 내용을 인라인에도 남겼다고 했지만 이 댓글 자체에도 대기 요청 수가 제한되지 않는다는 관심사가 명시되어 있다. 이번 미션은 머지한다고 했으므로 후속 고민을 권한 것이며, 머지를 문제 해결의 근거로 보지 않는다.

- [ ] 세션마다 만료 처리용 스레드를 생성하면 사용자 증가에 따라 스레드도 계속 늘어날 위험이 있어 스레드 풀 활용을 검토하자고 제안했다. (위험 지적)
  - 조건: 리뷰 참여자가 작성자의 질문을 인용한 뒤 스레드 증가 우려와 스레드 풀 아이디어를 직접 제시했다. 실제 서비스는 아니라는 전제를 두었고, 스스로 스레드 경험이 부족하며 구체적인 구현 아이디어는 명확하지 않다고 밝혔다. 스레드 풀이 문제를 해결한다는 결론이나 구현 결과는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
ExecutorService pool = new ThreadPoolExecutor(
    4, 4, 0, TimeUnit.SECONDS, new ArrayBlockingQueue<>(64),
    new ThreadPoolExecutor.AbortPolicy());
```

**적용 설명:** 요청마다 새 스레드를 만드는 대신 작업 수·대기열을 제한한다. 거절 응답 처리와 종료 시 shutdown도 필요하다.
