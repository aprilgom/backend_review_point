# FC0180 · 데이터 접근 계약의 추상화

## 검토 질문

- [ ] 데이터 접근 인터페이스가 대역 교체·기술 분리·업무 역할을 명확히 하는 실질적 이점을 가지는가?

**직접 작성한 예시**

```java
interface AuditLog { void append(AuditEvent event); }
AuditLog log = new MemoryAuditLog();
```

**적용 설명:** 대역 교체나 저장 기술 분리가 실제 이점인지 확인하는 작은 계약 예시다.

## 구체적인 검토 사례

- [ ] DAO를 인터페이스로 분리해 어떤 이점을 얻었는지 질문했다. (설계 질문)
  - 조건: 작성자는 테스트용 fake 객체를 만들기 위해 도입했으며 Service가 저장 구현과 무관하게 인터페이스에 의존하고 구현을 교체할 수 있다는 이점을 설명했다. 런타임 교체 가능성은 작성자의 설명이며 실제 구현으로 검증된 사항은 아니다.

- [ ] DAO를 인터페이스로 선언한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 테스트 용이성과 JDBC, JdbcTemplate, JPA 등 구현 변화로부터 내부 코드를 분리하려는 목적이라고 설명했다. 작성자가 추가로 논의한 DAO와 Repository의 명칭 구분 및 인터페이스 이름 변경 계획은 리뷰어의 별도 명명 요구로 보지 않는다.

- [ ] 서비스가 DAO 인터페이스를 선언하고 직접 객체를 생성하지 않아도 구현체를 사용할 수 있는 이유를 설명하도록 묻는다. (설계 질문)
  - 조건: 작성자는 구현체가 빈으로 등록되어 있고 IoC 컨테이너가 이를 찾아 주입하기 때문이라고 설명했다. 코드 결함이나 직접 객체 생성을 요구하는 지적은 아니다.
