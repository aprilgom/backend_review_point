# FC0215 · 예약 저장 시 과거 날짜뿐 아니라 이미 지난 예약 시간도 검증해야 하는지 검토를 요청했다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [다음 FC: FC0216 →](FC0216.md)

- [ ] 예약 저장 시 과거 날짜뿐 아니라 이미 지난 예약 시간도 검증해야 하는지 검토를 요청했다. (설계 질문)
  - 조건: 날짜 검증 호출에 대한 코멘트로 과거 시간 검증의 필요성을 물었다. 구체적인 허용 정책이나 실제 검증 누락의 영향은 대화에 제시되지 않았다.

- [ ] 예약 날짜가 오늘이더라도 시간이 현재보다 과거이면 예약이 가능한 동작을 보고하고, 시간까지 검증하도록 수정할 필요가 있는지 검토를 요청했다. (문제 보고)
  - 조건: 리뷰어가 로컬 테스트에서 확인했다고 보고한 문제다. 작성자는 예약 생성·수정 로직에 시간 검증을 추가했다고 답했고, 리뷰어는 수정 및 테스트 추가를 확인했다고 후속 발언했다. 제공된 대화만으로 실제 구현을 독립적으로 검증한 것은 아니다.

- [ ] 현재 시점보다 이전인 예약 날짜와 시간이 들어오는 경우를 검토하고 검증을 추가하도록 요청했다. (개선 제안)
  - 조건: 과거 시점 입력에 대한 검증 요구이며, 경계 시각이나 판정 방식까지 지정하지는 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
LocalDateTime requested = LocalDateTime.of(day, time);
if (!requested.isAfter(LocalDateTime.now(clock))) throw new PastSlot();
```

**적용 설명:** 날짜만 비교하면 같은 날 이미 지난 시간을 놓친다. 해당 업무 시간대와 정확히 현재 시각인 경우의 정책을 정한다.
