# FC0053 · 항상 기본값만 사용하는 것으로 보이는 whiteName과 blackName을 요청 파라미터로 받는 이유를 질문했다.

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [다음 FC: FC0054 →](FC0054.md)

- [ ] 항상 기본값만 사용하는 것으로 보이는 whiteName과 blackName을 요청 파라미터로 받는 이유를 질문했다. (설계 질문)
  - 조건: 리뷰 참여자는 별도 이름 입력 요청이 없다는 이해를 전제로 WHITE와 BLACK을 직접 전달하는 대안을 제시하고 오해 가능성을 열어 두었다. 작성자는 방 입장 후 입력한 팀 이름을 받으며, 입력하지 않았을 때만 기본값을 사용한다고 설명했다. 리뷰 참여자의 명시적 철회는 없다.

- [ ] 로그인 사용자를 조회하는 searchLoginMember에서 LoginMember를 반환하지 않는 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 DTO 통합 과정의 혼동이었다고 설명하고, 서비스·인터셉터·인자 리졸버가 LoginMember로 상호작용하도록 변경했다고 보고했다. AuthService 분리와 LoginResponse 정의도 작성자가 함께 보고한 변경이며, 리뷰어가 이 모든 변경을 요구한 것은 아니다.

- [ ] Reflections 생성 시 basePackage 전체가 아니라 basePackage[0]만 사용하는 이유를 물었다. (설계 질문)
  - 조건: 작성자는 급하게 구현하면서 놓친 부분이라고 설명하고 basePackage 전체를 받도록 변경했다고 보고했다. 변경된 코드는 대화에 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record StartInput(int rounds) {}
Game game = Game.start(input.rounds(), DEFAULT_PLAYER_NAMES);
```

**적용 설명:** 항상 고정된 이름이라면 요청 계약에서 제외하는 대안이다. 사용자 지정 요구가 있다면 입력을 유지한다.
