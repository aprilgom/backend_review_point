# FC0250 · 서버 실패의 응답 계약 검증

[소속 분야: 예외·실패 계약](../13-errors.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0247](FC0247.md) · [다음 FC: FC0251 →](FC0251.md)

## 검토 질문

- [ ] 예상하지 못한 서버 장애를 잘못된 요청으로 응답하지 않는지 테스트하는가?

**직접 작성한 예시**

```java
assertEquals(500, callEndpointWithFailingStorage().status());
```

**적용 설명:** 저장소 장애가 400으로 잘못 분류되지 않는지 확인하는 테스트 형태다.

## 구체적인 검토 사례

- [ ] 일반 Exception 처리 응답을 500에서 400으로 바꾼 이유와 예상치 못한 서버 오류를 클라이언트의 잘못된 요청으로 응답하는 것이 적절한지 확인한다. (설계 질문)
  - 조건: 리뷰 참여자는 일반 Exception 처리를 예상치 못한 오류 처리로 본다는 관점을 제시했다. 작성자는 다른 핸들러를 변경하다 실수로 함께 변경했다며 서버 오류 응답으로 수정하겠다고 답했으나 실제 수정 결과는 확인되지 않는다.

- [ ] 처리되지 않은 IllegalArgumentException이 클라이언트에 500 응답으로 전달될 가능성을 짚고, 해당 상황에 적절한 HTTP 오류 코드를 질문한다. (설계 질문)
  - 조건: 리뷰어는 500 응답이 발생할 것으로 예상했으며, 실제 재현 결과는 제시하지 않았다. 작성자는 존재하지 않는 예약 ID의 삭제 요청을 예로 들어 404 Not Found가 적절하다는 의견을 밝혔다.

- [ ] 예상하지 못한 예외도 처리하고, 해당 오류에 대해 일반적으로 사용하는 HTTP 500 응답을 고려하도록 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 409 수정과 함께 수행할 작업으로 제안했다. 409 수정의 구체적인 내용은 이 댓글에 없으며, 예상하지 못한 예외 처리의 실제 반영 결과도 확인되지 않는다.
