# FC0070 · 자동 생성 코드의 접근 제어

## 검토 질문

- [ ] 도구가 생성하는 생성자·메서드의 접근 수준이 의도한 객체 생성 계약과 일치하는가?

**직접 작성한 예시**

```java
@NoArgsConstructor(access = AccessLevel.PROTECTED)
class LedgerEntity {
    private Long id;
}
```

**적용 설명:** Lombok을 사용 중인 경우의 접근 수준 예시다. 기본 생성자가 필요한지와 영속화 도구의 제약을 먼저 검토한다.

## 구체적인 검토 사례

- [ ] Member의 @NoArgsConstructor에 생성자 접근 수준 설정이 빠져 있다고 지적한다. (문제 보고)
  - 조건: 리뷰 참여자는 accessLevel 누락을 지적했으나 구체적으로 어떤 접근 수준을 사용해야 하는지는 명시하지 않았다. 작성자는 반영했다고 보고했으며 실제 변경 내용은 확인되지 않는다.

- [ ] 클래스 내부에서만 사용하는 JdbcTemplate 메서드들의 공개 범위를 줄이도록 접근제어자를 변경해 달라고 요청했다. (개선 제안)
  - 조건: 작성자는 라이브러리 사용자가 다양한 시그니처를 선택하도록 의도적으로 public으로 열었다고 설명했다. 다만 현재 직접 설계한 UserDao에서는 params를 받는 형태만 사용할 것으로 보아 필요한 메서드만 공개하도록 수정하겠다고 답했다. 라이브러리의 확장 가능한 공개 API라는 반론이 있었으며, 실제 변경 결과는 제시되지 않았다.

- [ ] InterfaceControllerAdapterTest의 어댑터 필드에 명시적인 접근 제어자가 없는 이유를 질문했다. (설계 질문)
  - 조건: 리뷰 참여자가 접근 제어자 관련 질문을 직접 인용하고 ditto로 해당 필드에도 적용했다. 이 단위에는 작성자의 답변이나 변경 보고가 없다.
