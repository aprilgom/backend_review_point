# FC0455 · 배열 스트림 API의 요소 의미

[소속 분야: 타입·타입 테스트](../24-type-safety.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0465](FC0465.md) · [다음 FC: FC0457 →](FC0457.md)

## 검토 질문

- [ ] 배열 종류에 따라 스트림 요소 타입과 개수가 달라지는 API 차이를 이해하고 선택했는가?

**직접 작성한 예시**

```java
int[] ids = {1, 2};
assertEquals(2, Arrays.stream(ids).count());
assertEquals(1, Stream.of(ids).count());
```

**적용 설명:** primitive 배열에서 두 호출의 요소 타입·개수가 다름을 보여준다. 참조형 배열과 혼동하지 않는다.

## 구체적인 검토 사례

- [ ] 배열을 스트림으로 변환할 때 Stream.of와 Arrays.stream 중 무엇을 선택할지, 입력 타입 변경을 감지할 수 있는지를 고려해 논의한다. (토론)
  - 조건: 작성자는 Stream.of가 내부에서 Arrays.stream을 호출하므로 스타일의 차이라고 설명했다. 리뷰 참여자도 스타일 차이를 인정하면서, 배열이 List로 바뀌고 후속 처리에서 Object를 받는 극단적인 조건에서는 Stream.of가 타입 변경을 드러내지 않을 수 있어 Arrays.stream을 선호한다고 설명했다. 작성자는 일관된 정적 팩토리 사용과 편리성을 근거로 반론을 제시하고 타입 안전성과의 절충으로 정리했다. 작성자가 언급한 힙 오염은 작성자의 해석이며, 확인된 결함으로 취급하지 않는다.

- [ ] ManualHandlerMapping의 반환 타입을 Object 대신 Controller로 명시해 컴파일 단계에서 반환 객체의 타입을 보장하는 방안에 대한 의견을 물었다. (토론)
  - 조건: 리뷰 참여자는 어댑터에서 타입 확인과 캐스팅을 하더라도 구체적인 반환 타입을 선호한다고 밝혔다. 작성자는 각 HandlerMapping이 서로 다른 객체를 반환하므로 매핑은 Object를 반환하고 어댑터가 캐스팅하는 것이 맞다고 반론했다. 어느 쪽이 채택되었는지는 확인되지 않는다.

- [ ] Product의 getPrice 반환 타입을 price 필드 타입인 int와 일치시키자고 제안한다. (개선 제안)
  - 조건: 제시된 코드에서는 price 필드는 int이고 getPrice의 반환 타입은 Integer이다. 리뷰 참여자는 타입 일치를 제안했으며, 구체적인 실행 오류나 변경 결과는 언급하지 않았다.
