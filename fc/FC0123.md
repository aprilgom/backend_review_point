# FC0123 · 구간을 변경할 때 기존 구간을 삭제하고 두 구간을 삽입하는 대신, 하나는 삽입하고 하나는 갱신하는 방식을 검토하자는 제안이다.

[소속 분야: 쿼리·데이터 조작](../07-data-query.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0124](FC0124.md) · [다음 FC: FC0126 →](FC0126.md)

- [ ] 구간을 변경할 때 기존 구간을 삭제하고 두 구간을 삽입하는 대신, 하나는 삽입하고 하나는 갱신하는 방식을 검토하자는 제안이다. (개선 제안)
  - 조건: 작성자는 현재 과정에서 삭제가 한 번, 삽입이 두 번 실행된다고 설명했다. 삽입과 갱신을 조합하는 방식으로 실제 변경했는지는 확인되지 않는다.

- [ ] 주문 처리 중 장바구니 항목을 단건마다 삭제하기보다 모든 주문이 완료된 이후 삭제하는 방향을 제안했다. (개선 제안)
  - 조건: 주문 후 장바구니 항목을 제거하는 동작 자체는 긍정적으로 평가했다. 삭제 시점을 전체 주문 완료 이후로 옮기자는 제안이며, 일괄 SQL 사용이나 트랜잭션·롤백 문제를 명시적으로 지적한 것은 아니다.

- [ ] 구간을 나눌 때 기존 데이터를 갱신하고 하나를 추가하지 않고, 기존 구간을 삭제한 뒤 두 구간을 추가하는 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 삭제 후 추가하는 방식이 더 이해하기 쉬울 것으로 생각했다고 설명하고 수정했다고 보고했다. 구체적인 최종 변경 방식은 답변에 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```sql
BEGIN;
UPDATE segment SET end_id = :middle WHERE id = :segment;
INSERT INTO segment(start_id, end_id) VALUES (:middle, :old_end);
COMMIT;
```

**적용 설명:** 식별자·참조를 유지하는 변경 대안이다. 실제 유일성 제약과 잠금 순서에 맞게 같은 트랜잭션에서 수행한다.
