## 검토 질문

- [ ] 변경 시 식별자·참조·이력을 보존할 필요를 고려해 삭제 후 삽입과 갱신 중 적절한 방식을 택했는가?

**직접 작성한 예시**

```sql
BEGIN;
UPDATE segment SET end_id = :middle WHERE id = :segment;
INSERT INTO segment(start_id, end_id) VALUES (:middle, :old_end);
COMMIT;
```

**적용 설명:** 식별자·참조를 유지하는 변경 대안이다. 실제 유일성 제약과 잠금 순서에 맞게 같은 트랜잭션에서 수행한다.

## 구체적인 검토 사례

- [ ] **상황:** 작은 수정에도 행을 삭제하고 다시 만든다.
  - **판단 기준:** 참조·ID·생성 이력 보존 요구를 확인한다.

- [ ] **상황:** 여러 행의 갱신 순서가 제약에 걸린다.
  - **판단 기준:** 원자성과 제약 검사 시점을 함께 설계한다.
