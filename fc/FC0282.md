# FC0282 · 직렬화 도구의 재사용

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0273](FC0273.md) · [다음 FC: FC0285 →](FC0285.md)

## 검토 질문

- [ ] 설정 비용이 큰 직렬화 도구를 초기 구성 후 안전하게 공유하며 요청마다 설정을 바꾸지 않는가?

**직접 작성한 예시**

```java
final ObjectMapper mapper = new ObjectMapper();
// 초기 설정을 끝낸 뒤 공유하며 요청마다 설정을 바꾸지 않는다.
String body = mapper.writeValueAsString(reply);
```

**적용 설명:** Jackson 사용 조각이다. 재사용할 객체의 설정·확장 모듈도 스레드 안전한지 확인한다.

## 구체적인 검토 사례

- [ ] 요청마다 생성되는 JsonView와 함께 ObjectMapper도 새로 생성하지 말고 재사용하도록 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 생성 비용과 클래스 정보 캐시를 재사용 근거로 들었고, 설정을 마친 뒤에는 여러 요청이 공유해도 된다고 설명했다. 작성자는 생성 시점에 설정을 마친 매퍼를 여러 JsonView에서 재사용하도록 변경하겠다고 답했다. 실제 변경 여부는 이 단위에서 확인되지 않는다.

- [ ] ObjectMapper를 호출마다 생성하지 않고 인스턴스를 재사용할 수 있다는 제안이다. (개선 제안)
  - 조건: 리뷰어는 ObjectMapper가 thread-safe하다는 점을 재사용 근거로 들었다. 작성자는 private static 필드로 분리하고 static 초기화했다고 보고했으며, 실제 변경 내용은 이 대화만으로 검증되지 않는다.

- [ ] JsonView가 생성될 때마다 ObjectMapper를 새로 만드는 대신 static 인스턴스를 재사용하는 방식을 제안했다. (개선 제안)
  - 조건: 인스턴스 재사용에 대한 제안이며, 성능 측정 결과나 작성자의 답변 및 실제 변경 여부는 제시되지 않았다.
