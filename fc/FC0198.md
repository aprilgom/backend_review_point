# FC0198 · 서로 관련 없는 변경을 하나의 커밋에 섞지 않고 커밋 메시지가 실제 작업 범위를 드러내도록 하자는 제안이다.

[소속 분야: 문서·개발·학습 과정](../10-workflow.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0202](FC0202.md)

- [ ] 서로 관련 없는 변경을 하나의 커밋에 섞지 않고 커밋 메시지가 실제 작업 범위를 드러내도록 하자는 제안이다. (개선 제안)
  - 조건: 리뷰어는 repository 테스트 추가라는 메시지의 커밋에 컨트롤러 경로 변경 등 적지 않은 다른 작업도 포함되었다고 지적했다.

- [ ] 커밋 메시지에 어울리는 변경만 하나의 커밋에 담아 변경 내용과 메시지를 일치시키자는 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 해당 변경이 '데이터베이스 적용' 커밋에 어울리지 않는다고 보았다. 작성자는 앞으로 커밋 단위에 더 신경 쓰겠다고 답했으며, 기존 커밋을 수정했는지는 확인되지 않는다.

- [ ] 프로젝트 포맷 적용으로 프론트엔드 변경 내역이 불필요하게 늘지 않도록, 실제 수정한 부분만 diff에 나타나게 하자고 제안했다. (개선 제안)
  - 조건: 프론트엔드 코드의 포맷 변경 범위에 관한 제안이며, 기능 동작의 결함을 지적한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```sh
git diff --stat
git diff --cached
# 의도한 한 가지 변경만 준비됐는지 확인한다.
```

**적용 설명:** 서로 관련 없는 수정이 섞였는지 읽기 전용으로 점검한다. 커밋 메시지는 실제 변경 범위를 반영한다.
