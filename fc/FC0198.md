# FC0198 · 변경 단위와 커밋의 응집도

[소속 분야: 문서·개발·학습 과정](../10-workflow.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0202](FC0202.md)

## 검토 질문

- [ ] 서로 관련된 변경을 한 단위로 묶고 커밋 설명이 실제 작업 범위를 드러내는가?

**직접 작성한 예시**

```sh
git diff --stat
git diff --cached
# 의도한 한 가지 변경만 준비됐는지 확인한다.
```

**적용 설명:** 서로 관련 없는 수정이 섞였는지 읽기 전용으로 점검한다. 커밋 메시지는 실제 변경 범위를 반영한다.

## 구체적인 검토 사례

- [ ] **상황:** 기능·서식·정리를 한 커밋에 섞는다.
  - **판단 기준:** 함께 이해하고 되돌릴 변경 단위로 나눈다.

- [ ] **상황:** 커밋 제목이 실제 수정과 다르다.
  - **판단 기준:** 변경 내용을 최종 상태 기준으로 설명한다.
