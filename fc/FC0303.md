# FC0303 · 삭제 후 조회 결과가 비어 있음을 검증할 때 hasSize(0) 대신 isEmpty()로 표현할 수도 있다고 제안했다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0310](FC0310.md) · [다음 FC: FC0301 →](FC0301.md)

- [ ] 삭제 후 조회 결과가 비어 있음을 검증할 때 hasSize(0) 대신 isEmpty()로 표현할 수도 있다고 제안했다. (개선 제안)
  - 조건: 기존 검증이 잘못됐다는 지적이 아니라 대안 표현을 코드 예시로 제시했다. 작성자는 isEmpty로 리팩터링하겠다고 답했으며 실제 반영 여부는 확인되지 않는다.

- [ ] Optional의 존재 여부를 isPresent()의 불리언 결과로 검증하기보다 assertThat(optional).isPresent()로 직접 표현하도록 제안했다. (개선 제안)
  - 조건: 기존 존재 여부 검증의 의미를 유지하면서 단언 표현을 간단히 하는 제안이다. 작성자는 더 간단한 표현이라고 동의하며 반영했다고 보고했다.

- [ ] 직접 null과 비교하는 대신 Objects.isNull 같은 정적 메서드를 사용하는 표현을 선호한다. (의견)
  - 조건: 리뷰 참여자는 가독성에 관한 개인 취향이며 반영하지 않아도 된다고 명시했다. 작성자가 static import 사용 여부를 묻자, 리뷰 참여자는 자신은 사용하는 편이며 null 처리를 위해 제공된 기본 API를 선호한다고 설명했다. 필수 변경이나 결함 지적은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
assertTrue(repository.findAll().isEmpty());
```

**적용 설명:** 삭제 후 비어 있다는 의도를 직접 표현한다. 사용하는 단언 라이브러리의 isEmpty도 가능하다.
