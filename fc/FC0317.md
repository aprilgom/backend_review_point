# FC0317 · import 정리의 일관성

## 검토 질문

- [ ] 사용하지 않는 import를 제거하고 정렬·명시적 사용 규칙을 일관되게 적용하는가?

**직접 작성한 예시**

```java
import java.util.List;
import java.util.Map;
```

**적용 설명:** 실제 사용 타입만 명시적으로 import한다. 저장 시 정리 기능과 빌드 검사를 함께 활용할 수 있다.

## 구체적인 검토 사례

- [ ] 사용하지 않는 import 문을 제거하고 패키지 최상단에서 일괄 정리하는 방법을 활용하라고 제안했다. (개선 제안)
  - 조건: 본문에 정리 요청과 일괄 정리 방법이 직접 설명되어 있다. 작성자는 정리했다고 보고했으며, 첨부 이미지의 구체적인 내용은 근거에 보충하지 않았다.

- [ ] try-with-resources의 마지막 자원 선언 뒤에 붙은 불필요한 세미콜론을 생략하자고 제안했다. (개선 제안)
  - 조건: 참여자는 경고가 표시된다고 설명하면서도 중요도가 낮은 정리 사항이라고 한정했다. ResultSet의 명시적 반환에 대한 언급은 기존 변경을 확인하는 말이며, 별도의 신규 요구로 보지 않는다.

- [ ] slot lock 전환 후 남은 미사용 코드라면 findByIdWithLock을 제거해 락 전략에 대한 혼란을 줄이도록 제안한다. (조건부 제안)
  - 조건: 이전 reservation row lock 구현의 잔재라는 추정이 맞다는 조건이 붙어 있다. 실제 사용 여부나 제거 결과는 대화에서 확인되지 않는다.
