# FC0239 · TokenRequest에 Java Bean Validation을 적용해 null 여부 등의 입력 검증을 수행해보자는 제안이다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0238](FC0238.md) · [다음 FC: FC0236 →](FC0236.md)

- [ ] TokenRequest에 Java Bean Validation을 적용해 null 여부 등의 입력 검증을 수행해보자는 제안이다. (개선 제안)
  - 조건: 구체적인 제약 조건이나 적용 결과는 대화에 제시되지 않았다.

- [ ] 요청의 각 값에 null 여부와 길이 등 필수적인 입력 검증을 수행하도록 제안한다. (개선 제안)
  - 조건: 작성자는 validation 의존성과 Valid, NotNull 등의 어노테이션을 적용했다고 보고했다. 이는 작성자의 변경 설명이며 실제 검증 동작을 확인한 결과는 아니다.

- [ ] 컨트롤러의 요청 처리 단계에서도 null이나 공백 같은 기본 입력값 검증을 수행하는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 InputView의 검증과 비교하며 valid, not null, blank를 힌트로 제시했다. 작성자는 스프링이 제공하는 기능을 알게 되었다고 답했으며, 실제 적용 여부는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record TokenInput(@jakarta.validation.constraints.NotBlank String token) {}
if (!validator.validate(input).isEmpty()) throw new InvalidInput();
```

**적용 설명:** 표준 검증 호출 예시다. 토큰 내용의 유효성·만료·서명 검증을 대체하지 않는다.
