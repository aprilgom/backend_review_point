# FC0239 · 요청 객체의 검증 적용

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0238](FC0238.md) · [다음 FC: FC0236 →](FC0236.md)

## 검토 질문

- [ ] 필수 필드 제약이 선언되어 있을 뿐 아니라 실제로 실행되고 오류가 일관되게 처리되는가?

**직접 작성한 예시**

```java
record TokenInput(@jakarta.validation.constraints.NotBlank String token) {}
if (!validator.validate(input).isEmpty()) throw new InvalidInput();
```

**적용 설명:** 표준 검증 호출 예시다. 토큰 내용의 유효성·만료·서명 검증을 대체하지 않는다.

## 구체적인 검토 사례

- [ ] **상황:** 필수 토큰 필드의 검증이 실행되지 않는다.
  - **판단 기준:** 요청 바인딩 뒤 검증 경로를 확인한다.

- [ ] **상황:** 형식만 맞으면 유효한 토큰으로 본다.
  - **판단 기준:** 서명·만료·권한 검사는 별도로 수행한다.
