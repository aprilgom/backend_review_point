# FC0062 · 쿠키를 세미콜론과 공백 한 개로 분리하면 공백이 없거나 여러 개인 입력을 제대로 파싱하지 못할 수 있으므로 공백을 정리해 처리하도록 제안한다.

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0072](FC0072.md)

- [ ] 쿠키를 세미콜론과 공백 한 개로 분리하면 공백이 없거나 여러 개인 입력을 제대로 파싱하지 못할 수 있으므로 공백을 정리해 처리하도록 제안한다. (개선 제안)
  - 조건: 우려의 조건은 세미콜론 뒤 공백 개수가 달라지는 경우이다. 작성자는 세미콜론으로 분리한 뒤 각 항목과 키·값에 trim()을 적용하도록 변경했다고 설명했다.

- [ ] REDIRECT_PREFIX 상수가 JspView 내부에서만 사용되는 것으로 보여 공개 범위를 줄이는 방향을 시사했다. (개선 제안)
  - 조건: 리뷰 참여자는 내부에서만 사용되는 것 같다고 관찰했으며 구체적인 접근 제어자를 직접 지정하지는 않았다. 작성자는 상수의 접근 제어자를 변경했다고 보고했다.

- [ ] 쿠키를 세미콜론만으로 분리하면 후속 항목에 선행 공백이 남는다며 구분자를 '; '로 바꾸자고 제안한다. (개선 제안)
  - 조건: 리뷰어는 세미콜론 뒤에 공백이 있는 Cookie 헤더와 공백이 남은 파싱 결과를 예시로 들었다. 작성자는 문제를 해결하고 파싱 테스트를 추가했다고 보고했으나, 실제 처리 방식이나 테스트 결과는 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
for (String part : cookieHeader.split(";")) {
    String[] pair = part.trim().split("=", 2);
    if (pair.length == 2) cookies.put(pair[0], pair[1]);
}
```

**적용 설명:** 구분자 주변 공백과 값 안의 등호를 고려한 조각이다. 중복 이름·잘못된 구문·헤더 크기 제한 정책은 별도로 정한다.
