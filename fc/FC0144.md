# FC0144 · JPA 엔티티에 기본 생성자가 필요한 이유를 설명해 달라고 질문했다.

[소속 분야: 데이터 관계·영속성](../08-persistence.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0143](FC0143.md) · [다음 FC: FC0145 →](FC0145.md)

- [ ] JPA 엔티티에 기본 생성자가 필요한 이유를 설명해 달라고 질문했다. (설계 질문)
  - 조건: 작성자는 리플렉션을 통한 객체 생성, 프록시와 지연 로딩을 이유로 설명하고 외부 호출을 막기 위해 protected로 제한했다고 덧붙였다. 리뷰어는 원래 질문은 기본 생성자의 필요 이유였으며 접근 제한자 설명은 추가 답변이라고 명확히 했다. 작성자의 설명을 별도로 검증된 기술적 사실로 취급하지 않는다.

- [ ] JPA 엔티티가 기본 생성자를 필요로 하는 이유를 설명할 수 있는지 질문했다. (설계 질문)
  - 조건: 작성자는 리플랙션을 통한 생성과 지연 로딩 프록시를 학습했다고 답했다. 답변에 포함된 생성자·final 제약 설명은 작성자의 학습 보고이며, 리뷰어가 그 설명의 정확성을 확인한 후속 발언은 없다.

- [ ] JPA 엔티티에 기본 생성자가 필요한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 리플렉션을 통한 객체 생성과 지연 로딩 프록시의 생성자 필요성을 근거로 설명했다. 리뷰어는 Hibernate의 프록시 구현 특성과 연결해 기본 생성자 필요성을 설명했다. 질문을 기본 생성자 자체가 잘못되었다는 지적으로 해석하지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@Entity
class Receipt {
    protected Receipt() {}
    public Receipt(String number) { this.number = number; }
}
```

**적용 설명:** 매핑 도구의 생성 경로와 도메인 생성 경로를 구분한다. ID·필드 매핑은 생략했다.
