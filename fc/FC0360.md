# FC0360 · 공유 인스턴스와 전역 싱글턴의 구분

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [다음 FC: FC0363 →](FC0363.md)

## 검토 질문

- [ ] 객체를 한 번 생성해 재사용하려는 목적을 전역 싱글턴 패턴 없이 조립 단계에서 달성할 수 있는가?

**직접 작성한 예시**

```java
LoginController shared = new LoginController(authenticator);
router.register("/login", shared);
```

**적용 설명:** 조립 단계에서 한 번 만들면 클래스 자체를 전역 싱글턴으로 고정하지 않아도 된다. 가변 요청 상태는 지역 변수로 둔다.

## 구체적인 검토 사례

- [ ] 컨트롤러를 한 번 생성해 재사용하려는 목적이라면 LoginController 자체를 싱글톤으로 구현하는 방안을 논의했다. (토론)
  - 조건: 작성자는 컨트롤러가 WAS 사용자가 구현하는 코드이므로 싱글톤 형식을 강요할 수 없다고 반론했다. 제안자는 웹 애플리케이션 구현을 제한하는 것은 이번 미션의 목표와 거리가 있다는 취지에 동의하며 적용하지 않아도 되는 단순 제안으로 완화했다. 지적 자체를 명시적으로 철회한 것은 아니다.

- [ ] LoginController와 LoginViewController를 분리한 이유를 묻고, 로그인 관련 요청을 하나의 컨트롤러에서 관리하는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 기존에 나뉘어 있던 구조에서 인터페이스 구현만 어노테이션으로 바꾸었다고 설명하고 통합하겠다고 답했다. 실제 통합 여부는 확인되지 않았으며, 로그인 요청은 반드시 하나의 객체에서 처리해야 한다는 보편 규칙으로 제시된 것은 아니다.

- [ ] Application이 Controller 역할까지 맡는 구조에서 컨트롤러가 여러 개 필요해지는 경우를 고려해 보도록 질문했다. (설계 질문)
  - 조건: 컨트롤러가 여러 개 생기는 상황을 가정한 책임 분리 검토이며, 현재 동작의 결함을 확정한 것은 아니다.
