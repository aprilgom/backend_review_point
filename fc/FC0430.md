# FC0430 · 저장소 테스트에 필요한 실행 범위

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0425](FC0425.md) · [다음 FC: FC0434 →](FC0434.md)

## 검토 질문

- [ ] 저장소만 검증하는 테스트에 전체 앱을 띄울 필요가 있으며 DB·주입 객체·슬라이스 구성을 이해하는가?

**직접 작성한 예시**

```java
@org.springframework.boot.test.autoconfigure.jdbc.JdbcTest
class AccountJdbcTest {
    // JDBC 슬라이스 구성으로 저장소 검증
}
```

**적용 설명:** 기존 제외 목록 밖의 혼합 FC이므로 Spring 사례를 유지했다. Boot 3 계열 패키지 기준 조각이며 사용하는 버전·DB 교체·추가 빈 요구에 맞게 확인한다.

## 구체적인 검토 사례

**혼합·경계:** @JdbcTest 외에 테스트 데이터 준비·DB 연결 설정 사례가 포함됨.

- [ ] JDBC 저장소 테스트에서 @SpringBootTest 대신 @JdbcTest 사용을 고려했는지 질문했다. (설계 질문)
  - 조건: 대안 검토를 묻는 발언으로, 현재 설정이 잘못되었다고 확정하거나 변경 결과를 확인한 대화는 아니다.

- [ ] 테스트 데이터 준비에 JdbcTemplate을 직접 사용해야 하는지, 서비스나 Repository로 준비할 수 없는지 질문했다. (토론)
  - 조건: 작성자는 서비스나 Repository 메서드에 의존하면 기능 변경에 테스트가 영향을 받고 조회 기능을 독립적으로 검증하기 어렵다고 보아 직접 SQL을 선택했다고 설명했다. 참여자는 변경으로 테스트가 깨지는 것이 오히려 유용한 피드백일 수 있으며, 어느 방식이든 데이터를 저장한다는 점은 같지 않느냐고 재질문했다. 데이터 준비 방식에 대한 결론은 확인되지 않는다.

- [ ] 테스트에서 주입받는 JdbcTemplate이 연결하는 데이터베이스를 어떻게 설정했는지 질문했다. (설계 질문)
  - 조건: 작성자가 기존 질문의 의미를 이해하지 못하자 리뷰어가 DB 연결 설정에 관한 질문임을 구체화했다. 작성자는 테스트에서 내장 H2를 사용하고 schema.sql로 테이블을 초기화한다고 설명했으며, 설정 오류가 확인된 대화는 아니다.
