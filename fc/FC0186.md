# FC0186 · 양방향 의존의 비대칭 추상화

## 검토 질문

- [ ] 한 방향만 인터페이스로 바꾼 뒤에도 반대 의존으로 결합이나 순환이 남아 있지 않은가?

**직접 작성한 예시**

```java
interface TableAvailability { boolean isOpen(TableId id); }
OrderService service = new OrderService(tableAvailability);
```

**적용 설명:** 한쪽 경계에서 필요한 역할만 추출한다. 반대 방향 의존이 남아 있으면 여전히 순환하는지 확인한다.

## 구체적인 검토 사례

- [ ] Order에서 OrderTable을 향한 의존성은 인터페이스로 끊고 반대 방향 의존성은 남겨 둔 이유를 묻는다. (설계 질문)
  - 조건: 리뷰 참여자가 코드에서 파악한 의존 방향을 전제로 선택 이유를 질문한 것이다. 이 후속 질문에 대한 작성자의 답변은 제공되지 않았으며, 해당 방향 선택을 결함으로 단정하지 않는다.

- [ ] Table에서도 Order를 의존하여 Table 패키지와 Order 패키지 사이에 양방향 의존성이 생겼다고 지적했다. (문제 보고)
  - 조건: TableService의 OrderRepository 의존을 가리킨 지적이다. 이 대화에는 작성자의 답변이나 의존성 해소 결과가 없다.

- [ ] 제시된 그림과 달리 TableService에 table에서 order로 향하는 의존성이 남아 있다고 지적했다. (문제 보고)
  - 조건: 코드에는 kitchenpos.order.dao.OrderDao import가 제시되어 있다. 그림 자체의 내용과 후속 변경 여부는 제공되지 않았으며, 그림과의 불일치는 리뷰 참여자의 보고로 보존한다.
