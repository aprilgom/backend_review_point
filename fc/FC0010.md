# FC0010 · 엔티티 영속 시각을 공통 구조로 래핑하면 개별 엔티티에 @EntityListeners를 선언하지 않아도 되겠다고 관찰했다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0016](FC0016.md) · [다음 FC: FC0019 →](FC0019.md)

- [ ] 엔티티 영속 시각을 공통 구조로 래핑하면 개별 엔티티에 @EntityListeners를 선언하지 않아도 되겠다고 관찰했다. (관찰)
  - 조건: 래핑 구조를 사용하는 경우의 이점을 긍정적으로 언급한 것이며, 추가 변경을 요구한 것은 아니다. 작성자는 이모지로 응답했으며, 해당 구조의 실제 동작을 검증한 결과는 제시되지 않았다.

- [ ] 직접 작성한 확장자별 ContentType 분기 대신 Files.probeContentType()을 활용해 처리를 간소화하는 방안을 제안한다. (개선 제안)
  - 조건: 작성자는 다음 미션의 리팩터링에서 사라질 코드라는 이유로 현재 구현을 유지하겠다고 답했다. 제안의 실제 적용이나 해당 환경에서의 동작은 확인되지 않는다.

- [ ] View 이름을 각 클래스에서 따로 상수화하기보다 Page 같은 공통 클래스에서 관리하는 방식을 긍정적으로 평가한다. (의견)
  - 조건: 작성자가 View 이름을 별도 클래스로 관리하는 방안에 대한 의견을 물었고, 리뷰 참여자는 파일명 변경 시 수정 범위를 줄일 수 있다는 이유로 찬성했다. 반드시 적용해야 한다는 요구나 실제 적용 확인은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@MappedSuperclass
@EntityListeners(AuditListener.class)
abstract class AuditedEntity {
    Instant createdAt;
}
```

**적용 설명:** Jakarta Persistence 부분 코드다. 공통 감사 필드·리스너를 상위 모델에 둘 때 상속과 콜백 중복 여부를 검토한다. AuditListener 구현은 생략했다.
