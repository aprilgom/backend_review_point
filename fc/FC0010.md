# FC0010 · 공통 영속 메타데이터의 관리

## 검토 질문

- [ ] 여러 엔티티에 반복되는 생성·수정 정보와 수명 콜백을 어떤 공통 구조로 관리하는 것이 적절한가?

**직접 작성한 예시**

```java
@MappedSuperclass
@EntityListeners(AuditListener.class)
abstract class AuditedEntity {
    Instant createdAt;
}
```

**적용 설명:** Jakarta Persistence 부분 코드다. 공통 감사 필드·리스너를 상위 모델에 둘 때 상속과 콜백 중복 여부를 검토한다. AuditListener 구현은 생략했다.

## 구체적인 검토 사례

- [ ] **상황:** 여러 엔티티에 감사 필드와 콜백이 반복된다.
  - **판단 기준:** 공통 수명 규칙을 한 곳에서 관리할 수 있다.

- [ ] **상황:** 일부 엔티티만 다른 기록 정책을 가진다.
  - **판단 기준:** 상속으로 모든 정책을 강제하지 않고 예외를 분리한다.
