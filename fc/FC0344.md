## 검토 질문

- [ ] 논리 뷰 선택·모델 전달·실제 출력을 분리하고 프레임워크가 제공하는 처리 흐름과 비교할 수 있는가?

**직접 작성한 예시**

```java
View view = viewResolver.resolve(result.viewName());
view.render(result.model(), request, response);
```

**적용 설명:** 자체 MVC의 논리 뷰 이름 해석과 렌더링을 분리한 개념 코드다. Spring과 비교할 때 선택·모델 전달·출력 책임을 대응시킨다.

## 구체적인 검토 사례

- [ ] **상황:** 컨트롤러가 템플릿을 직접 찾아 출력한다.
  - **판단 기준:** 뷰 선택과 렌더링의 경계를 비교한다.

- [ ] **상황:** 프레임워크 위임 뒤 모델 전달이 사라진다.
  - **판단 기준:** 필요한 데이터와 출력 계약을 유지한다.
