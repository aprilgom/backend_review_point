# FC0012 · 생성자와 차이가 드러나지 않는 of 정적 팩토리 메서드를 별도로 사용하는 이유가 있는지 물었다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0008](FC0008.md) · [다음 FC: FC0005 →](FC0005.md)

- [ ] 생성자와 차이가 드러나지 않는 of 정적 팩토리 메서드를 별도로 사용하는 이유가 있는지 물었다. (설계 질문)
  - 조건: 작성자는 id를 받지 않을 때 0L로 초기화하는 로직 때문에 막연히 정적 팩토리가 적절하다고 생각했다고 설명했다. 이후 인스턴스 재사용과 하위 타입 반환이라는 장점을 찾아봤지만 현재 상황에는 해당하지 않는다고 판단해 수정하겠다고 답했다. 이는 작성자의 판단과 계획이며 정적 팩토리의 일반적인 부적절성이나 실제 변경을 입증하지 않는다.

- [ ] 생성자 대신 정적 팩토리 메서드를 사용하는 이유를 묻고, 다른 객체로부터 생성한다는 설명만으로 사용 근거가 충분한지 재질문했다. (설계 질문)
  - 조건: 작성자는 다른 객체로부터의 변환이라는 의미를 이름으로 명확히 표현하려 했다고 설명했다. 리뷰 참여자는 이것도 생성이라는 점에서 생성자와 의미가 같은 것 아니냐고 반문했다. 작성자는 자신의 사용 맥락에서 필요성을 충분히 이해하지 못했다고 답하고 정적 팩토리 메서드를 제거했다고 보고했다.

- [ ] 재사용되지 않고 독립적인 역할도 뚜렷하지 않아 보이는 getModel()을 별도 메서드로 분리한 이유를 질문했다. (설계 질문)
  - 조건: 메서드 분리의 근거를 묻는 발언으로, 분리가 확정적으로 잘못되었다거나 반드시 합쳐야 한다는 요구는 아니다. 작성자의 설명이나 후속 결과는 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Money a = new Money(500);
Money b = Money.of(500); // 생성자 전달만 한다면 의미 차이가 작다.
Money c = Money.won(500); // 단위 정보를 드러내는 이름
```

**적용 설명:** 팩토리는 캐싱·검증·단위 등 실제 의미를 제공하는지 판단한다. of를 무조건 제거하라는 뜻은 아니다.
