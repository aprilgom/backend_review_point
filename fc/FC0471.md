# FC0471 · 화면 동작에 필요한 식별자

[소속 분야: UI 동작·사용성](../25-ui-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0467](FC0467.md) · [다음 FC: FC0470 →](FC0470.md)

## 검토 질문

- [ ] 표시·선택·수정·목록 키 등 화면의 실제 사용에 필요한 식별자가 응답에 포함되어 있는가?

**직접 작성한 예시**

```java
record ProductReply(long id, String name) {}
```

**적용 설명:** 화면의 선택·수정·목록 key에 ID가 필요한지 실제 사용처를 확인한다. 표시만 한다면 ID가 꼭 필요한 것은 아니다.

## 구체적인 검토 사례

- [ ] ID가 없는 ProductDto로도 화면이 정상적으로 표시되는지 확인한다. (설계 질문)
  - 조건: 작성자는 리뷰 요청 후 ID 누락을 발견하여 수정했으며 리뷰어가 그 이전 코드를 본 것 같다고 설명했다. 리뷰어는 이를 수긍했지만, 화면 정상 동작을 검증한 결과는 대화에 제시되지 않았다.

- [ ] 역 조회 실패 메시지의 '출발역이'를 다른 표현으로 바꾸면 좋겠다. (개선 제안)
  - 조건: 제공된 코드에서는 같은 조회 메서드를 출발역과 도착역에 모두 사용하지만 실패 메시지는 출발역으로 고정되어 있다. 리뷰어는 구체적인 대체 문구까지 지정하지 않았다.

- [ ] 예외 발생 시 사용자에게 StackTrace를 노출할 필요가 있는지 묻는다. (설계 질문)
  - 조건: 사용자에게 보여 주는 오류 정보의 적절성에 관한 질문이다. 작성자는 해당 부분의 변경 필요성과 구조 변경을 포괄적으로 답했으며, StackTrace 노출을 제거했는지는 구체적으로 밝히지 않았다.
