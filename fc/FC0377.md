# FC0377 · HandlerMapping과 HandlerAdapter 각각의 역할과, 두 역할을 하나로 합치지 않고 분리한 이유를 설명해 달라고 요청했다.

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0382](FC0382.md) · [다음 FC: FC0380 →](FC0380.md)

- [ ] HandlerMapping과 HandlerAdapter 각각의 역할과, 두 역할을 하나로 합치지 않고 분리한 이유를 설명해 달라고 요청했다. (토론)
  - 조건: 작성자는 요청에 맞는 핸들러를 찾는 역할과 이를 실행하는 역할을 분리하여 독립적인 확장과 조합이 가능하다고 설명했다. 리뷰 참여자는 개념을 정리하려는 질문이었다고 밝히고, 무엇을 실행할지와 어떻게 실행할지를 나누어 전략 패턴으로 추상화하면 디스패처의 작업이 단순해진다는 자신의 관점을 덧붙였다. 구현 결함이나 두 역할의 통합 요구는 아니다.

- [ ] 이번 구현에서 HandlerAdapterRegistry와 HandlerAdapter가 각각 맡은 역할을 질문했다. (설계 질문)
  - 조건: 작성자는 Registry가 어댑터들을 관리하고 적절한 어댑터를 선택하며, HandlerAdapter는 특정 핸들러를 실행해 요청을 처리한다고 설명했다. 프론트 컨트롤러가 핸들러의 구체적인 종류에 구애받지 않게 된다는 설명도 작성자의 답변이다.

- [ ] 요청에 맞는 대상을 찾는 HandlerMapping과 대상을 실행하는 HandlerAdapter를 분리하는 이유를 논의하고 작성자의 생각을 물었다. (토론)
  - 조건: 리뷰 참여자는 탐색과 실행 방식이 각각 달라질 수 있으므로 한 객체가 모두 처리하면 새 방식마다 기존 코드를 수정해야 하고 실수 가능성이 생긴다는 자신의 해석을 설명했다. 이어 작성자의 견해를 물었으며, 남긴 코멘트의 반영은 필수가 아니라고 밝혔다. 인용된 질문을 작성자의 직접 리뷰 근거로 삼지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Object handler = mapping.find(request.path(), request.method());
HandlerAdapter adapter = adapters.supporting(handler);
return adapter.invoke(handler, request);
```

**적용 설명:** 어떤 핸들러인지와 어떻게 호출할지를 나눈다. 핸들러 종류가 하나뿐이면 분리 비용도 검토한다.
