# FC0437 · 지연 응답과 타임아웃 테스트

## 검토 질문

- [ ] 통제된 지연 응답으로 제한 시간을 검증하고 실행 환경 차이·서버 정리로 인한 불안정성을 줄이는가?

**직접 작성한 예시**

```java
fakeServer.delayNextResponse(Duration.ofMillis(300));
client.setRequestTimeout(Duration.ofMillis(50));
assertThrows(RemoteTimeout.class, client::fetch);
```

**적용 설명:** 가상 테스트 서버 도우미의 개념 코드다. 충분한 시간 차이와 서버 정리로 느린 CI에서 흔들림을 줄인다.

## 구체적인 검토 사례

- [ ] 타임아웃 동작을 확인하고 싶다면 가상 웹 서버로 지연 응답을 만들고, 자동화가 어렵다면 실제 Mock 서버를 띄워 인수테스트하는 방법을 제안했다. (조건부 제안)
  - 조건: 작성자의 타임아웃 테스트 방법 질문에 대한 조건부 제안이다. 리뷰 참여자는 자동화 환경 구축이 까다롭고 시간이 걸릴 수 있으므로 너무 많은 시간을 쓰지 않는 범위에서만 시도하라고 제한했다. 테스트 구현이나 실행 결과는 확인되지 않는다.

- [ ] MockMvc 기반의 `RestAssuredMockMvc`도 참고해 보도록 제안한다. (개선 제안)
  - 조건: 학습로그를 보고 덧붙인 선택적인 학습 제안으로, 기존 테스트 도구를 교체하라는 요구는 아니다. 링크의 내용은 추가 근거로 사용하지 않았다.

- [ ] RestClient 공통 설정을 유지하면서 MockRestServiceServer를 연결하는 테스트 구성 방법을 추가로 탐색해 볼 것을 제안한다. (개선 제안)
  - 조건: 작성자는 RestClient 빈 등록 시 자동 모의 서버 생성에 실패했고, Builder에 직접 모의 서버를 연결한 두 시도에서도 모킹되지 않았다고 보고했다. 리뷰 참여자는 외부 예시와 이슈를 근거로 가능성을 제시했지만 해결을 확정하지 않았으며, 중요도가 높지 않으니 시간이 날 때 탐색하는 선택 과제로 완화했다. 구체적인 해결 방법은 링크 본문에 있어 제공된 대화만으로 확인할 수 없다.
