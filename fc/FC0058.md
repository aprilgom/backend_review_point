# FC0058 · RequestUri의 hasRequestParameters 메서드가 테스트에서만 사용되는 메서드임을 지적했다.

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0057](FC0057.md) · [다음 FC: FC0059 →](FC0059.md)

- [ ] RequestUri의 hasRequestParameters 메서드가 테스트에서만 사용되는 메서드임을 지적했다. (관찰)
  - 조건: 리뷰 참여자가 삭제를 명시적으로 요구한 것은 아니다. 작성자는 해당 메서드를 삭제했다고 답했으며 실제 변경 여부는 별도로 확인되지 않았다.

- [ ] 요청 경로만으로 처리 대상을 결정하는 코드에서 HTTP 메서드 검사도 필요한지 질문했다. (설계 질문)
  - 조건: 메서드 검사 필요성을 묻는 발언이며, 특정 메서드 입력으로 발생한 오류를 보고한 것은 아니다.

- [ ] 리소스 상태를 변경하는 요청에 GET보다 적절한 HTTP 메서드가 있는지 검토하도록 질문했다. (설계 질문)
  - 조건: 리뷰어는 REST 준수 여부와 별개로 클라이언트가 GET의 상태 변경을 일반적으로 예상하지 않는다고 설명했다. 작성자는 start와 end를 PUT으로 변경했다고 답하며 반복 호출 시 응답이 동일하다는 이유를 들었으나, 이 근거의 타당성이나 변경 결과가 검증된 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
assertEquals("blue", parsed.queryParameter("color").orElseThrow());
// 테스트 전용 hasParameters()를 추가하지 않고 공개 동작을 검증한다.
```

**적용 설명:** 관찰용 메서드가 제품 계약에 필요한지 검토한다. 테스트 편의가 공개 API 확대의 유일한 이유인지 확인한다.
