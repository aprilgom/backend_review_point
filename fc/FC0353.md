# FC0353 · 화면 모델과 데이터 응답의 구분

[소속 분야: 렌더링·데이터 로딩](../18-rendering.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0348](FC0348.md) · [다음 FC: FC0349 →](FC0349.md)

## 검토 질문

- [ ] 서버 템플릿을 반환할지 JSON 데이터를 반환할지 소비자와 화면 책임에 맞게 결정했는가?

**직접 작성한 예시**

```java
record TaskResponse(long id, String title) {}
TaskResponse body = new TaskResponse(task.id(), task.title());
```

**적용 설명:** JSON 응답은 화면 템플릿 대신 데이터를 계약으로 제공한다. 실제 직렬화·헤더 설정은 응답 경계에서 수행한다.

## 구체적인 검토 사례

- [ ] Model을 사용하는 응답 방식과 JSON 데이터를 반환하는 방식의 차이를 고민하고 JSON 응답도 고려해 보도록 제안했다. (개선 제안)
  - 조건: 심화 학습 제안으로 제시되었다. 리뷰 참여자는 JSON 응답 방식에서는 form 태그를 사용하지 못하고 추가 JavaScript 작업이 필요할 것이라는 전제를 함께 언급했으며, 구현 전환을 필수로 요구하지는 않았다.

- [ ] 리다이렉트에서는 모델을 request에 추가할 필요가 없으므로 `addModelToRequest` 호출을 리다이렉트 분기 뒤로 옮기자고 제안한다. (개선 제안)
  - 조건: `viewName`이 `redirect:`로 시작하는 경우를 조건으로 한 제안이다. 작성자는 지적에 동의하는 반응을 보였지만, 이 대화에 실제 수정 결과는 제시되지 않았다.

- [ ] JsonView의 응답 생성에 JSONGenerator를 사용하는 방식도 대안으로 공유한다. (개선 제안)
  - 조건: 리뷰 참여자는 response의 PrintWriter를 쓰는 현재 방식을 새롭게 알게 되었다고 하면서 자신의 JSONGenerator 사용 경험을 공유했다. 현재 방식의 결함이나 대체 방식의 우월성을 주장한 것은 아니며, 외부 링크의 세부 구현은 추정하지 않는다.
