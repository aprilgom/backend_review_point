# FC0348 · 직접 render()를 호출하는 대신 Spring Boot의 Handlebars 지원 기능으로 뷰를 반환하는 방식을 제안한다.

[소속 분야: 렌더링·데이터 로딩](../18-rendering.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0347](FC0347.md) · [다음 FC: FC0353 →](FC0353.md)

- [ ] 직접 render()를 호출하는 대신 Spring Boot의 Handlebars 지원 기능으로 뷰를 반환하는 방식을 제안한다. (개선 제안)
  - 조건: 로그인이 없는 답글 참여자가 hbs 파일명을 반환하는 것만으로 뷰를 그린다는 뜻인지 물었고, hongbin-dev가 그렇다고 확인했다. 답글 참여자의 작성자 여부는 확인할 수 없으며, 실제 설정 변경이나 동작 결과도 제시되지 않았다.

- [ ] template engine 개념을 가볍게 학습하도록 제안했다. (학습 제약)
  - 조건: 리뷰 본문에 학습 주제와 참고 링크가 제시되어 있다. 링크나 첨부 이미지의 내용은 근거로 보충하지 않았으며, 후속 답변에서 이 학습 제안 자체를 명시적으로 철회하지는 않았다.

- [ ] 반환하는 뷰 이름에 .html을 붙이지 않아도 index.html이 선택되는 과정을 ViewResolver를 중심으로 알아보자고 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 해당 기능이 있다는 정도로만 가볍게 살펴보도록 학습 깊이를 한정했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@org.springframework.stereotype.Controller
class HomeController {
    @org.springframework.web.bind.annotation.GetMapping("/home")
    String home() { return "home"; }
}
```

**적용 설명:** 기존 20개 제외 목록 밖에 있는 Spring 사례다. Handlebars 연동 리졸버가 구성되어 있다는 전제이며 컨트롤러는 직접 렌더링하지 않고 논리 뷰 이름을 반환한다.
