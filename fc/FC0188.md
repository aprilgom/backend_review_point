# FC0188 · 여러 캐시 구현 중 Caffeine을 선택한 이유를 물었다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0161](FC0161.md) · [다음 FC: FC0191 →](FC0191.md)

- [ ] 여러 캐시 구현 중 Caffeine을 선택한 이유를 물었다. (설계 질문)
  - 조건: 작성자는 시간 제약으로 Caffeine과 Redis만 비교했으며, 복제 지연 대응에는 장기 지속성보다 로컬 접근 속도가 중요하다고 판단했다고 설명했다. 이는 작성자의 선택 근거이며 두 구현의 성능이나 적합성이 검증된 것은 아니다.

- [ ] 글로벌 캐시 대신 로컬 캐시를 선택한 이유와 두 방식의 장단점을 묻는다. (설계 질문)
  - 조건: 작성자는 인스턴스가 적은 현재 범위에서는 글로벌 캐시가 불필요하다고 판단했다고 설명했다. 인스턴스가 많아지면 로컬 캐시의 동기화 비용과 일관성 관리 문제 때문에 글로벌 캐시로 전환할 것으로 예상했다. 글로벌 캐시 도입을 요구한 질문은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
CacheKey key = new CacheKey(accountId, query);
return cache.get(key, () -> repository.search(accountId, query));
```

**적용 설명:** 로컬 캐시 도입의 사용 형태다. 크기 제한·만료·무효화·키에 사용자 범위 포함 여부를 확인한다.
