# FC0281 · 한 요청이 유발하는 쿼리 수

## 검토 질문

- [ ] 조회부터 응답 생성까지 발생하는 추가 쿼리를 관측하고 필요한 시점에만 로딩하는가?

**직접 작성한 예시**

```java
long before = sqlCounter.count();
service.getBooking(id);
long queries = sqlCounter.count() - before;
```

**적용 설명:** 테스트용 카운터로 조회 한 번의 쿼리 수를 관측한다. 지연 로딩으로 응답 직렬화 중 추가되는 쿼리도 포함해 본다.

## 구체적인 검토 사례

- [ ] 예약 하나를 조회할 때 실행되는 쿼리 수와 불필요한 조회 여부를 확인하고, 추가 조회를 필요한 시점에만 수행하는 방법을 검토하도록 요청했다. (설계 질문)
  - 조건: @ManyToOne 매핑에 달린 질문이며, 실제 쿼리 수나 불필요한 조회 발생은 이 대화에서 확인되지 않는다. 작성자는 README에 연결된 다른 리뷰에서 답했다고 했지만 해당 답변 내용은 제공되지 않았다.

- [ ] 예약 존재 여부와 본인 예약 여부를 각각 조회하는 대신 예약을 한 번 가져와 memberId를 확인하여 쿼리를 줄이도록 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 getByDateAndTimeIdAndThemeId로 예약을 조회하면 쿼리를 한 번 줄일 수 있다고 설명했다. 작성자는 예약을 바로 조회하는 방식으로 쿼리 실행을 1회 줄였다고 보고했으며, 실제 실행 횟수나 성능을 별도로 확인한 자료는 없다.

- [ ] 예약 대기별 추가 조회로 쿼리 수가 늘어나는 구조 대신 내역과 번호를 한 번의 쿼리로 조회할 수 있는지 검토하도록 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 항목 수만큼 쿼리가 발생한다고 지적했다. 작성자는 반영했다고 보고했지만, 이 대화만으로 변경 방식이나 실제 쿼리 수 감소는 확인되지 않는다.
