# FC0002 · 모든 테스트에서 반복되는 요청 실행 코드를 메서드로 분리해 중복을 제거하는 방안을 제안했다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0003](FC0003.md) · [다음 FC: FC0001 →](FC0001.md)

- [ ] 모든 테스트에서 반복되는 요청 실행 코드를 메서드로 분리해 중복을 제거하는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 자신의 의견이므로 참고만 해 달라고 밝혀 선택적인 제안으로 제시했다. 작성자는 감사 인사를 남겼지만, 이 대화만으로 실제 반영 여부를 확인할 수는 없다.

- [ ] 여러 인수 테스트에 반복되는 유사한 준비 코드의 중복을 제거할 수 있는지 검토하자는 제안이다. (개선 제안)
  - 조건: 역 생성과 LineRequest 구성 코드에 달린 의견이다. 구체적인 공통화 방식이나 실제 중복 제거 결과는 제시되지 않았다.

- [ ] TypeParser에서 반복되는 처리 구조를 템플릿으로 분리해 중복을 줄이는 방안을 제안한다. (개선 제안)
  - 조건: 대상 코드는 타입별 ResultSet 조회에서 예외 처리 구조가 반복되는 부분이다. 작성자는 내부 함수형 인터페이스와 default 메서드로 템플릿을 만들어 해결했다고 보고했으나, 변경 코드의 타당성이 이 대화에서 확인된 것은 아니다. 이후 작성자가 추가로 보고한 JdbcTemplate 콜백 리팩터링은 별도의 참여자 지적으로 확장하지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Response createLabel(String name) {
    return api.post("/labels", new LabelInput(name));
}
assertEquals(201, createLabel("study").status());
```

**적용 설명:** api는 테스트용 HTTP 도우미다. 요청 구성만 재사용하고 테스트마다 기대 결과는 드러낸다.
