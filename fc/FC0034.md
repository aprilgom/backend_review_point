# FC0034 · 필요하다면 컬렉션을 일급 컬렉션으로 추상화하여 여러 검증 로직을 처리하도록 제안했다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0033](FC0033.md) · [다음 FC: FC0016 →](FC0016.md)

- [ ] 필요하다면 컬렉션을 일급 컬렉션으로 추상화하여 여러 검증 로직을 처리하도록 제안했다. (조건부 제안)
  - 조건: 필요한 경우 적용하는 제안이다. 작성자는 Sections로 거리 계산과 구간 정렬 기능을 옮겼다고 했지만, 등록·삭제 로직은 Line의 stations와 밀접하게 연결되어 옮기지 못했다고 설명했다. 검증 로직까지 이동했는지는 답변에서 확인되지 않는다.

- [ ] Member의 즐겨찾기 컬렉션을 일급 컬렉션으로 구현해 보는 것을 제안했다. (개선 제안)
  - 조건: 작성자는 일급 컬렉션을 적용했다고 답했다. 실제 변경 내용은 이 대화만으로 확인되지 않는다.

- [ ] 컬렉션을 다루는 도메인 로직이 많지 않다면 일급 컬렉션 대신 List를 그대로 사용하는 방안도 고려하자고 제안했다. (조건부 제안)
  - 조건: 일급 컬렉션의 장점은 인정하면서도, 추상화로 복잡성이 증가하면 유지보수 목적에 어긋날 수 있다는 조건부 의견이다. 일급 컬렉션 전반을 제거하라는 요구는 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record Tags(List<String> values) {
    Tags {
        values = List.copyOf(values);
        if (new HashSet<>(values).size() != values.size()) throw new IllegalArgumentException();
    }
}
```

**적용 설명:** 중복 금지와 외부 변경 차단을 컬렉션 경계에 모은다. 단순 목록에 규칙이 없다면 래퍼가 불필요할 수 있다.
