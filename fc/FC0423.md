# FC0423 · 테스트에서만 사용하는 생성자 대신 이미 마련된 정적 팩토리 메서드로 테스트 객체를 생성하는 것을 제안한다.

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0421](FC0421.md) · [다음 FC: FC0426 →](FC0426.md)

- [ ] 테스트에서만 사용하는 생성자 대신 이미 마련된 정적 팩토리 메서드로 테스트 객체를 생성하는 것을 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 해당 생성자가 테스트에서만 사용된다고 보고 제안했다. 작성자는 수정했다고 답했지만 구체적인 변경 코드나 검증 결과는 제시되지 않았다.

- [ ] 테스트에서 필요한 객체를 별도 메서드로 생성하기보다 테스트 메서드 안에서 명시적으로 생성하면 이해하기 쉽겠다고 제안했다. (개선 제안)
  - 조건: 테스트 코드의 이해 용이성을 근거로 한 제안이며, 실제 변경 여부는 제시되지 않았다.

- [ ] 개별 테스트에서만 사용하는 request와 response를 클래스 필드로 두는 것이 적절한지 검토하도록 제안했다. (개선 제안)
  - 조건: 반영은 선택 사항이라고 명시했다. 현재는 메서드가 하나지만 여러 DTO를 사용하게 되면 공통 데이터가 아닌 필드가 무분별하게 늘어날 수 있다는 우려이며, 지적을 철회한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
User user = User.register("reader");
```

**적용 설명:** 제품에서 쓰는 생성 경로로 테스트 객체를 만든다. 테스트 편의를 위해 불변식을 우회하는 생성자를 추가하지 않는다.
