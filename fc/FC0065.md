# FC0065 · JSON 응답에 Content-Type을 지정했을 때와 지정하지 않았을 때의 차이를 질문했다.

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0070](FC0070.md) · [다음 FC: FC0071 →](FC0071.md)

- [ ] JSON 응답에 Content-Type을 지정했을 때와 지정하지 않았을 때의 차이를 질문했다. (설계 질문)
  - 조건: 작성자는 미션 힌트를 따라 지정했으며, 생략하면 헤더는 없지만 크롬과 포스트맨이 JSON을 읽는 것 같다고 보고했다. 리뷰 참여자는 원래 Content-Type이 없으면 브라우저가 JSON을 처리하지 못할 것으로 생각했다고 설명하고, 본문 분석으로 처리하는 듯하다는 불확실한 추정을 덧붙였다. 정확한 처리 원리는 양측 모두 확정하지 않았으며 헤더 생략이 안전하다는 결론도 없다.

- [ ] 알 수 없는 파일 형식의 응답 Content-Type을 기본적으로 text/html로 지정한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 현재 요구사항의 정적 파일이 CSS, JS, HTML뿐이라 그렇게 설정했다고 설명했다. JSON 응답을 처리하지 않은 것 같다는 판단과 수정 계획은 작성자가 추가로 제시한 것이며, 리뷰 참여자가 JSON 결함을 직접 지적한 것은 아니다.

- [ ] 자바스크립트 리소스의 Content-Type 반환값을 "text/javascript;"로 고칠 것을 제안한다. (개선 제안)
  - 조건: 리뷰어는 현재 반환값인 "test/javascript" 대신 제안한 값을 반환해야 테스트가 깨지지 않을 것이라고 예상했다. 실제 테스트 실패나 수정 후 통과 여부는 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"state":"ready"}
```

**적용 설명:** 전송할 본문의 형식을 헤더에 명시한다. 클라이언트가 헤더를 보고 올바른 파서를 선택하는지도 검증한다.
