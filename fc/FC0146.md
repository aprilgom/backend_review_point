# FC0146 · 구현 교체 시 수정 범위

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [다음 FC: FC0149 →](FC0149.md)

## 검토 질문

- [ ] 인터페이스를 두었어도 구현 교체 때 상위 서비스의 분기와 구체 타입 의존을 바꿔야 하지는 않는가?

**직접 작성한 예시**

```java
final class RouteService {
    private final PathFinder finder;
    RouteService(PathFinder finder) { this.finder = finder; }
    Path route(Node a, Node b) { return finder.find(a, b); }
}
```

**적용 설명:** 알고리즘 교체 시 서비스 내부 분기가 바뀌지 않는지 확인한다.

## 구체적인 검토 사례

- [ ] **상황:** 인터페이스를 바꿔도 서비스 분기를 수정해야 한다.
  - **판단 기준:** 구체 구현에 남은 의존을 찾는다.

- [ ] **상황:** 다른 알고리즘이 계약을 만족하지 못한다.
  - **판단 기준:** 공통 인터페이스가 필요한 의미를 표현하는지 검토한다.
