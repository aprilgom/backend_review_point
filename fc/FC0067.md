# FC0067 · 내부 모델과 API 응답의 분리

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0064](FC0064.md) · [다음 FC: FC0060 →](FC0060.md)

## 검토 질문

- [ ] 내부 모델 변경이 의도하지 않은 응답 변경이나 정보 노출로 이어지지 않도록 공개 계약을 분리했는가?

**직접 작성한 예시**

```java
record TaskReply(long id, String title) {}
return new TaskReply(task.id(), task.title());
```

**적용 설명:** 도메인 전체를 직렬화하지 않아 내부 필드 추가가 API 응답에 자동 노출되는 것을 막는다.

## 구체적인 검토 사례

- [ ] **상황:** 도메인 필드 추가가 응답에 자동 반영된다.
  - **판단 기준:** 공개 필드만 선택한 응답 모델을 사용한다.

- [ ] **상황:** 요청만 DTO로 분리하고 응답은 엔티티다.
  - **판단 기준:** 양쪽 경계의 변경 전파와 정보 노출을 검토한다.
