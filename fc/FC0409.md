# FC0409 · 서비스 소유 정책의 테스트

[소속 분야: 테스트 대상·검증](../21-test-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0411](FC0411.md) · [다음 FC: FC0413 →](FC0413.md)

## 검토 질문

- [ ] 서비스가 담당하는 정책과 저장 부작용을 도메인·컨트롤러 테스트에만 맡기지 않고 확인하는가?

**직접 작성한 예시**

```java
assertThrows(DuplicateName.class, () -> service.create(existingName));
assertEquals(1, repository.countByName(existingName));
```

**적용 설명:** 서비스가 소유한 중복 정책과 저장 부작용을 검증한다.

## 구체적인 검토 사례

- [ ] 현재 서비스 테스트가 없으며, 다른 리뷰를 반영하면 서비스에서 검증할 대상이 생길 수 있다고 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 검증할 로직이 없어 테스트하지 않았을 것으로 추측했다. 작성자는 새 테스트 도구·기법 도입을 제한하고 JUnit 단위 테스트에 집중한다는 요구사항을 제시하며 도메인 테스트를 추가했다고 답했다. 리뷰 참여자는 Spring Boot Test도 제한 대상임을 뒤늦게 인지했지만 서비스 테스트에 대한 관심사를 철회하지는 않았다.

- [ ] ThemeService 테스트를 성공 케이스만으로 구성해도 되는지 질문하며 실패 케이스 검증 범위를 검토하도록 했다. (설계 질문)
  - 조건: 리뷰어는 구체적인 실패 시나리오를 지정하지 않았다. 작성자는 ThemeService 실패 테스트와 DTO 검증 및 실패 테스트를 추가했다고 보고했으며, 링크의 실제 테스트 내용이나 충분성은 확인되지 않았다.

- [ ] 금액이 정확히 떨어지는 경우와 반올림·반내림 등 금액 처리 정책별 테스트를 꼼꼼히 작성하는 실무 경험을 공유한다. (관찰)
  - 조건: 정산 및 사후 보정의 어려움을 설명하면서 금액 정책 관련 테스트를 강조한 발언이다. 현재 PR에 특정 테스트가 누락되었다는 보고나 즉시 추가하라는 명시적 요구는 아니다.
