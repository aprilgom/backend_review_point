# FC0104 · 동시성 컬렉션의 보장 범위

[소속 분야: 비동기·동시성](../05-concurrency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0098](FC0098.md) · [다음 FC: FC0101 →](FC0101.md)

## 검토 질문

- [ ] 스레드 안전한 컬렉션을 써도 내부 객체 변경과 여러 연산의 조합까지 안전한지 확인했는가?

**직접 작성한 예시**

```java
ConcurrentMap<String, Session> sessions = new ConcurrentHashMap<>();
Session current = sessions.computeIfAbsent(key, ignored -> new Session());
```

**적용 설명:** 지도 자체의 생성 경쟁을 제어한다. Session 내부의 변경 가능한 필드까지 자동으로 스레드 안전해지는 것은 아니다.

## 구체적인 검토 사례

- [ ] 여러 스레드가 동시에 접근하는 세션 저장소를 ConcurrentHashMap으로 처리해 보자고 제안했다. (개선 제안)
  - 조건: 멀티스레드 환경에서 세션에 동시 접근한다는 점을 근거로 한 우선적인 개선 제안이다. 작성자는 관련 학습을 계속하겠다고 답했으며, 자료구조 변경이나 동시성 안전성 확보가 확인된 것은 아니다.

- [ ] HashMap과 ConcurrentHashMap의 차이 및 세션 저장소를 ConcurrentHashMap으로 바꿀 때의 이점을 질문했다. (설계 질문)
  - 조건: 작성자는 공유 자원인 sessions의 동시 변경 문제를 제어하기 위한 선택이며 조율에 따른 성능 부담도 있다고 이해한다고 답했다. 리뷰어는 그 설명에 동의했지만, 실제 동시성 보장 범위나 성능 측정 결과가 제시된 것은 아니다.

- [ ] 여러 스레드에서 접근할 수 있는 세션 저장소에 ConcurrentHashMap을 사용해 동시성을 고려할 것을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 해당 변수가 다중 스레드에서 접근될 수 있다는 이유를 제시했다. 이 자료구조 변경만으로 모든 세션 연산의 동시성이 보장된다고 단정한 것으로 확대하지 않는다.
