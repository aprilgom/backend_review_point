# FC0190 · 이번 단계부터 Lombok을 도입한 이유를 질문했다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0185](FC0185.md) · [다음 FC: FC0187 →](FC0187.md)

- [ ] 이번 단계부터 Lombok을 도입한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 이전 단계에서는 페어 프로그래밍과 미션 요구사항에 집중했고, 이번 리팩터링에서는 코드를 간결하게 만들기 위해 이전 사용 경험이 있는 Lombok을 도입했다고 설명했다. 도입 자체를 잘못이라고 지적한 것은 아니다.

- [ ] Lombok을 도입한 이유를 물었다. (설계 질문)
  - 조건: 작성자는 특별한 이유보다는 페어와 개발 편의성을 고려해 자연스럽게 사용했다고 설명하고, 도입 과정에서 `annotationProcessor`와 `compileOnly` 설정 이유를 논의한 경험을 언급했다. 리뷰어가 해당 설정의 변경이나 Lombok 제거를 요구한 것은 아니다.

- [ ] Lombok을 도입한 이유와 Lombok 없이 구현하는 대안에 대한 판단을 설명해 달라. (설계 질문)
  - 조건: 작성자는 Lombok 없이도 구현 가능하지만 반복적인 getter·생성자·동등성 관련 코드 등을 줄여 생산성과 가독성을 높이려 했다고 답했다. 또한 직접 구현한 메서드가 예외적인 로직이나 제한 의도를 드러내는 대비 효과를 설명했다. 질문 자체를 Lombok 사용 금지나 의존성 결함 판정으로 해석하지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
public record LabelView(long id, String name) {}
```

**적용 설명:** 반복 코드 감소에는 record 같은 언어 기능도 대안이다. Lombok을 선택했다면 생성되는 코드와 빌드 도구 설정을 이해한다.
