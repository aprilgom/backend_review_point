# FC0301 · 객체 조립 절차의 단계 분리

## 검토 질문

- [ ] 생성자 선택·의존성 해석·인스턴스 생성을 구분해 읽기 쉽고 실패 원인을 찾기 쉬운가?

**직접 작성한 예시**

```java
Constructor<?> constructor = selectConstructor(type);
Object[] arguments = resolveArguments(constructor);
return constructor.newInstance(arguments);
```

**적용 설명:** 자체 객체 조립기의 선택·인자 해석·생성 단계를 분리한다. 예외 처리와 순환 의존 검사는 별도 필요하다.

## 구체적인 검토 사례

- [ ] instantiateBean 메서드도 역할 분리 등의 방법으로 가독성을 개선해 보자고 제안했다. (개선 제안)
  - 조건: initialize에 남긴 피드백과 유사한 취지라고 명시했으며, 이 댓글 자체에서 가독성 개선과 역할 분리라는 관심사를 설명했다.

- [ ] 한 줄에 중첩된 객체 생성이 많으므로 일부 생성 결과를 변수로 분리해 가독성을 높이자고 제안했다. (개선 제안)
  - 조건: 모든 객체 생성을 분리하라는 요구가 아니라 일부를 변수로 빼자는 제안이며, 반영 여부는 알 수 없다.

- [ ] 구현을 분석해야 기능을 파악할 수 있는 메서드들에 대해, 메서드명과 변수명으로 수행 기능을 드러내 가독성을 높이자는 제안이다. (개선 제안)
  - 조건: 리뷰는 해당 메서드들 전반의 명명을 대상으로 한다. 작성자는 그중 메서드 이름을 getAllStationIds로 변경했다고 보고했으며, 전체 명명 개선 여부는 확인되지 않는다.
