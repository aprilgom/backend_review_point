# FC0248 · 검증 실패 시 고정된 예외 메시지 대신 검증 오류가 가진 메시지를 꺼내 전달하는 방식을 제안했다.

[소속 분야: 예외·실패 계약](../13-errors.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0245](FC0245.md) · [다음 FC: FC0253 →](FC0253.md)

- [ ] 검증 실패 시 고정된 예외 메시지 대신 검증 오류가 가진 메시지를 꺼내 전달하는 방식을 제안했다. (개선 제안)
  - 조건: BindingResult에 오류가 있을 때 방 이름 길이 메시지를 직접 작성해 예외를 던지는 코드에 대한 제안이다. 작성자는 수정했다고 답했으나 변경된 코드는 제공되지 않았다.

- [ ] 삭제할 즐겨찾기를 찾지 못했을 때 메시지 없는 IllegalArgumentException 대신 실패 의도를 정확히 전달하는 예외 메시지를 제공하도록 제안했다. (개선 제안)
  - 조건: 클라이언트에 전달할 오류 의미와 메시지에 관한 제안이며, 특정 사용자 정의 예외의 도입을 명시적으로 요구하지는 않았다.

- [ ] 응답 생성 실패를 로그만 남기고 끝내지 말고 해당 예외를 던지도록 제안한다. (개선 제안)
  - 조건: 리뷰어는 응답 생성에 실패하면 아무 응답도 나가지 않을 수 있다는 우려를 근거로 들었다. 작성자는 예외를 던지는 코드를 누락했다며 추가했다고 답했지만, 실제 응답 동작이나 변경 결과는 확인되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
List<String> messages = violations.stream()
    .map(v -> v.getMessage()).distinct().toList();
```

**적용 설명:** 검증 메시지를 전달하되 제한된 공개 메시지인지 확인한다. 검증된 값 자체나 내부 경로를 무분별하게 노출하지 않는다.
