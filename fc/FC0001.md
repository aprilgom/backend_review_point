# FC0001 · 요구사항 변화에 대응하는 책임 분리

## 검토 질문

- [ ] 요구사항의 처리 순서를 그대로 옮긴 코드에서 함께 바뀌는 규칙을 구분하고, 변경 범위를 줄일 수 있는가?

**직접 작성한 예시**

```java
Order order = Order.from(request.lines());
order.apply(pricingPolicy);
store.save(order);
```

**적용 설명:** 계산 규칙은 Order·정책에, 저장 순서 조율은 호출자에 둔 예시다. 짧은 메서드 수보다 변경 책임이 나뉘는지 확인한다.

## 구체적인 검토 사례

- [ ] **상황:** 요구가 늘 때마다 한 절차의 분기가 늘어난다.
  - **판단 기준:** 함께 바뀌는 규칙을 나누어 변경 영향을 제한한다.

- [ ] **상황:** 단계마다 무조건 객체를 추가한다.
  - **판단 기준:** 단계 수보다 변경 이유와 협력 관계를 기준으로 나눈다.
