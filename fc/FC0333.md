# FC0333 · 컬렉션 필드의 도메인 의미

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0339](FC0339.md) · [다음 FC: FC0338 →](FC0338.md)

## 검토 질문

- [ ] 컬렉션 필드 이름이 담긴 원소와 역할을 명확히 설명하는가?

**직접 작성한 예시**

```java
private final List<CartItem> cartItems = new ArrayList<>();
```

**적용 설명:** value보다 컬렉션 원소의 의미를 명시한다.

## 구체적인 검토 사례

- [ ] Cart의 컬렉션 필드 이름을 value보다 내용이 명확한 cartItems로 표현하는 것을 제안했다. (토론)
  - 조건: 작성자는 일급 컬렉션에서 포장 클래스와 필드 이름의 혼동을 피하려고 value를 사용해 왔다고 설명하면서, 현재 Cart에는 원소명 복수형도 적절하다고 답했다. 리뷰 참여자는 해당 일급 컬렉션 상황에서는 자신도 values를 사용하며, 더 명확히 표현할 때 원소명 복수형을 사용한다고 설명했다.

- [ ] CartItemException 코드에 포맷 정리를 요청했다. (개선 제안)
  - 조건: 인라인 코드에는 클래스 선언의 여는 중괄호 앞 공백이 없는 모습이 제시되어 있으나, 요청은 특정 공백 수정으로 한정하지 않은 reformat 요청이다.

- [ ] CartItem의 isCorrectQuantity 메서드가 실제로 사용되는지 확인하는 질문이다. (설계 질문)
  - 조건: 작성자는 검증을 orderService로 옮긴 뒤 남은 메서드를 검토하지 못했다고 설명하고 삭제했다고 보고했다. 삭제 결과를 별도로 확인한 근거는 없다.
