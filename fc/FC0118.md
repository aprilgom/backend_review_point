# FC0118 · 필요 데이터로 직접 접근하는 조회

[소속 분야: 쿼리·데이터 조작](../07-data-query.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0122](FC0122.md) · [다음 FC: FC0124 →](FC0124.md)

## 검토 질문

- [ ] 중간 식별자 목록을 불필요하게 거치지 않고 소유자·조건에 맞는 데이터를 효율적으로 조회하는가?

**직접 작성한 예시**

```sql
SELECT c.id, c.product_id, c.quantity
FROM cart_line c JOIN account a ON a.id = c.account_id
WHERE a.login_name = :name;
```

**적용 설명:** 필요한 소유자 범위로 직접 조회하는 대안이다. 조인과 두 단계 조회 중 선택은 실행 계획·가독성으로 비교한다.

## 구체적인 검토 사례

- [ ] cartIds를 먼저 추출하는 대신 고객 이름으로 고객 ID를 구한 뒤 해당 고객의 장바구니 항목을 직접 조회하는 방식을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 cartIds 추출 이유를 질문하며 대안을 제시했다. 작성자는 추출이 불필요하다고 동의하고 수정했다고 보고했으며, 실제 변경 결과는 확인되지 않는다.

- [ ] 상품 ID마다 개별 조회하는 대신 findAllById를 사용해 상품 목록 조회 코드를 간소화하자는 제안이다. (개선 제안)
  - 조건: 댓글은 ProductRepository#findAllById를 언급하고 예시에서는 productService.findAllById를 호출한다. 제안의 취지는 일괄 조회를 통한 코드 간소화이며, 실제 변경 여부는 제시되지 않았다.

- [ ] 주문 항목 테이블 변경 마이그레이션에 기존 데이터의 컬럼 값도 갱신하는 UPDATE SQL을 추가하면 좋겠다고 제안한다. (개선 제안)
  - 조건: 메뉴 이름과 가격 컬럼을 추가하는 SQL에 대한 의견이다. 기존 데이터 갱신을 권했지만 구체적인 SQL이나 마이그레이션 실패 사례는 제시하지 않았다.
