# FC0336 · HandlerExecution의 declaredObject 필드를 역할이 더 명시적인 handler로 명명하는 방안을 제안한다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0316](FC0316.md)

- [ ] HandlerExecution의 declaredObject 필드를 역할이 더 명시적인 handler로 명명하는 방안을 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 개인적인 의견이므로 반영하지 않아도 된다고 명시했다. 작성자는 handler가 더 깔끔하다고 동의하며 적용했다고 보고했다.

- [ ] QueryCallBack과 execute라는 명명을 JdbcTemplate의 StatementCallback·doInStatement와 비교하며 콜백의 역할을 드러내는 명명 기준을 논의했다. (토론)
  - 조건: 리뷰 참여자는 기존 라이브러리의 명칭을 소개하면서도 현재 명명이 쿼리 실행 시 호출되는 콜백이라는 의미를 더 잘 전달한다는 개인적 감상을 밝혔다. 변경 요구나 지적 철회가 아니며, 작성자는 현재 이름을 유지하겠다고 답했다.

- [ ] handlerKeys 순회 코드의 개행과 들여쓰기가 어색해 보이므로 확인해 달라는 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 자신의 관점에서 어색하다는 주관적 표현을 사용했다. 작성자는 수정했다고 보고했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
private final Object handler;
private final Method handlerMethod;
```

**적용 설명:** 리플렉션 대상 객체와 호출 메서드의 역할을 이름으로 드러낸다. 가능하면 Object보다 더 좁은 계약을 쓴다.
