# FC0143 · 엔티티의 생성 시간과 마지막 수정 시간을 관리해야 한다면 수동 처리 대신 Auditing으로 자동 관리하도록 제안했다.

[소속 분야: 데이터 관계·영속성](../08-persistence.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0142](FC0142.md) · [다음 FC: FC0144 →](FC0144.md)

- [ ] 엔티티의 생성 시간과 마지막 수정 시간을 관리해야 한다면 수동 처리 대신 Auditing으로 자동 관리하도록 제안했다. (개선 제안)
  - 조건: 시간 관리가 필요한 경우라는 조건이 붙은 제안이다. 작성자는 추가했다고 보고했지만 실제 적용 내용이나 동작 검증은 대화에 없다.

- [ ] 엔티티의 생성·최종 수정 시간을 관리해야 한다면 수동으로 설정하는 대신 Auditing으로 자동 기록하자는 제안이다. (개선 제안)
  - 조건: 생성 시간과 마지막 수정 시간을 관리할 필요가 있다는 조건의 제안이며, 실제 반영 여부는 대화에 제시되지 않았다.

- [ ] 엔티티의 생성 시간과 마지막 수정 시간을 관리해야 한다면 수동 설정 대신 Auditing으로 자동 관리할 것을 제안한다. (조건부 제안)
  - 조건: 생성·수정 시간 관리가 필요하다는 조건이 붙은 제안이며, 실제 적용 여부는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@PrePersist void onInsert() { createdAt = Instant.now(); }
@PreUpdate void onUpdate() { updatedAt = Instant.now(); }
```

**적용 설명:** Jakarta Persistence 수명 콜백으로 자동 기록하는 조각이다. 테스트 가능한 시계·벌크 SQL 우회·DB 시각 기준을 별도로 고려한다.
