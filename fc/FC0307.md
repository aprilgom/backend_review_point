# FC0307 · 담긴 데이터를 설명하는 변수명

## 검토 질문

- [ ] result·value 같은 포괄적인 이름 대신 실제 데이터를 설명하는 이름을 사용할 수 있는가?

**직접 작성한 예시**

```java
List<Station> stations = repository.findAll();
```

**적용 설명:** result 대신 실제 담긴 도메인 개념을 사용한다.

## 구체적인 검토 사례

- [ ] result보다 stations처럼 담고 있는 데이터를 드러내는 변수명이 적합한지 고민하도록 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 명명에 취향 차이가 있을 수 있다고 명시했다.

- [ ] dateTime 대신 해당 값의 의미가 드러나는 변수명을 사용하자고 제안했다. (개선 제안)
  - 조건: 작성자는 생성 시점과 예약 시점이 혼동될 수 있다고 해석하여 reservationDateTime으로 변경했다고 보고했다. name을 customerName으로 바꾼 것은 작성자가 같은 취지로 추가 적용했다고 설명한 내용이다.

- [ ] 가변 변수를 사용하지 않고 예약 시각 검증을 구현할 방법을 검토하도록 제안했다. (개선 제안)
  - 조건: 작성자는 객체에 묻는 방식도 가능하다고 답하면서, 현재는 날짜와 시간을 LocalDateTime으로 합쳐 과거 여부를 비교하는 방식을 선택했다고 보고했다. LocalDateTime 사용 자체가 리뷰 참여자가 지정한 해결책은 아니다.
