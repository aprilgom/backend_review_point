# FC0173 · 필드 주입 대신 생성자 주입을 사용하고 그 이유도 함께 고민하도록 요청한다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0180](FC0180.md) · [다음 FC: FC0184 →](FC0184.md)

**혼합·경계:** 생성자 주입은 Spring 없이도 적용할 수 있는 설계 방식.

- [ ] 필드 주입 대신 생성자 주입을 사용하고 그 이유도 함께 고민하도록 요청한다. (개선 제안)
  - 조건: 작성자는 필수 의존성 누락과 NPE 가능성, final 참조 사용, 컨테이너 의존성, 순환 참조 발견 시점 등을 조사해 설명했다. 필드 주입의 내부 방식은 추측이라고 밝혔고 순환 참조는 직접 경험하지 않아 정확히 모른다고 한정했다. 리뷰어는 상세한 확인을 칭찬했지만, 이를 각 기술 주장이나 실제 변경 완료에 대한 검증으로 보지는 않는다.

- [ ] 필드 주입과 생성자 주입의 차이를 추가로 학습해 보도록 제안했다. (개선 제안)
  - 조건: 컨트롤러에서 필드 주입을 사용하는 맥락의 학습 제안이며, 필드 주입을 결함으로 단정하거나 생성자 주입으로 반드시 바꾸라고 요구하지는 않았다.

- [ ] 의존성 주입 방식으로 생성자 주입을 선택한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 필드의 불변성과 테스트 용이성을 직접 체감한 근거로 들었다. 순환 참조 탐지 등 추가로 찾아본 근거도 언급했지만, 리뷰 참여자는 나머지 근거를 이후 미션에서 경험해 보라고 했으며 개별 설명의 정확성을 검증하지는 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
final class InvoiceService {
    private final Invoices invoices;
    InvoiceService(Invoices invoices) { this.invoices = Objects.requireNonNull(invoices); }
}
```

**적용 설명:** 필수 의존성을 생성 시 제공하므로 불완전한 객체 상태를 줄인다.
