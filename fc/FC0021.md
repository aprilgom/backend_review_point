# FC0021 · 거리 구간에 따른 요금 계산을 전략 패턴으로 수행해 보는 방안을 제안한다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0018](FC0018.md) · [다음 FC: FC0023 →](FC0023.md)

- [ ] 거리 구간에 따른 요금 계산을 전략 패턴으로 수행해 보는 방안을 제안한다. (개선 제안)
  - 조건: 작성자는 전략 패턴을 시도하자 로직이 중복되어 거리 요금 정책도 Enum으로 관리했다고 보고했다. 작성자의 시도 의사에 취소선이 있으나 리뷰 참여자가 제안을 철회한 것은 아니며, 이 스레드에는 후속 판단이 없다.

- [ ] 체스판 각 칸의 마크업을 개별 나열하는 대신 pieces 목록을 순회하며 name과 symbol을 출력하도록 템플릿을 단순화하는 것을 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 목록 형태로 데이터를 전달하는 경우를 전제로 예시를 제시했다. '위와 같이'가 가리키는 별도 대화의 세부 내용이나 예시 문법의 기술적 타당성은 이 단위에서 확정하지 않는다.

- [ ] 메뉴 총액 계산에 Map 대신 MenuProduct를 활용하여 복잡한 코드를 간결하게 만드는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자가 직접 제안한 것은 MenuProduct 활용이다. MenuProducts라는 일급 컬렉션을 만들겠다는 구체적인 방향은 작성자가 제시한 응답이며, 리뷰 참여자의 요구나 실제 구현 결과로 확정할 수 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
interface FarePolicy { long fare(int distance); }
long total = farePolicy.fare(distance);
```

**적용 설명:** 요금 정책 교체가 실제 요구일 때 전략으로 분리한다. 거리 경계값·음수·반올림 정책은 각 구현에서 검증한다.
