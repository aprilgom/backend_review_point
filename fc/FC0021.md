# FC0021 · 변경 가능한 계산 정책의 전략화

## 검토 질문

- [ ] 조건별 계산 규칙을 교체 가능한 정책으로 분리하면 변경과 테스트가 쉬워지는가?

**직접 작성한 예시**

```java
interface FarePolicy { long fare(int distance); }
long total = farePolicy.fare(distance);
```

**적용 설명:** 요금 정책 교체가 실제 요구일 때 전략으로 분리한다. 거리 경계값·음수·반올림 정책은 각 구현에서 검증한다.

## 구체적인 검토 사례

- [ ] **상황:** 계산 정책을 바꿀 때 조건문 여러 곳을 수정한다.
  - **판단 기준:** 변경되는 계산을 교체 가능한 전략으로 모은다.

- [ ] **상황:** 한 가지 고정 규칙에 추상화만 늘어난다.
  - **판단 기준:** 변형 가능성과 테스트 이점이 작으면 단순 구현을 택한다.
