## 검토 질문

- [ ] 검증 정규식의 최악 실행 시간·입력 길이·형식 보장 범위를 검토했는가?

**직접 작성한 예시**

```java
if (email.length() > MAX_EMAIL_LENGTH) throw new InvalidEmail();
boolean valid = emailPattern.matcher(email).matches();
```

**적용 설명:** 길이를 제한하고 복잡한 중첩 정규식의 최악 실행 시간을 점검한다. 정규식만으로 실제 주소 유효성을 보장하지 않는다.

## 구체적인 검토 사례

- [ ] 이메일 검증에 정규식을 사용할 때 주의할 점이 무엇인지 질문했다. (설계 질문)
  - 조건: 리뷰어는 주의점을 묻고 참고 링크를 제공했으며, 본문에서 특정 결함이나 해결책을 명시하지 않았다. 작성자는 String.matches()가 호출마다 Pattern을 생성한다는 점을 확인했다며 Pattern을 캐싱하도록 수정했다고 보고했다. 링크의 내용이나 실제 변경 결과는 별도로 확인되지 않았다.

- [ ] 이메일 정규식 검증에 성능상 더 나은 패턴 사용 방법을 찾아 적용해보자고 제안했다. (개선 제안)
  - 조건: 구체적인 최적화 방법은 댓글에 명시되지 않았다. 작성자는 찾아보고 적용하겠다고 답했으며, 실제 적용 결과는 제시되지 않았다.

- [ ] 입력 실패 후 makeCars를 재귀 호출하는 방식이 메모리 누수의 원인이 될 수 있다며 재귀 사용을 자제하도록 요청했다. (위험 지적)
  - 조건: 메모리 누수 가능성은 리뷰어가 제시한 설명이며, 실제 누수 발생이나 기술적 타당성이 대화에서 검증된 것은 아니다.
