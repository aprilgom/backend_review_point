# FC0470 · 상태 전이 결과의 즉시 피드백

## 검토 질문

- [ ] 완료·종료 상태가 된 직후 추가 조작 없이 결과를 보여 주고 이후 잘못된 행동을 제한하는가?

**직접 작성한 예시**

```javascript
const result = await submitMove(move);
renderBoard(result.board);
if (result.finished) showWinner(result.winner);
```

**적용 설명:** 이번 응답에서 종료 상태를 바로 표시한다. 서버도 종료 이후 추가 수를 거절해야 한다.

## 구체적인 검토 사례

- [ ] 킹을 잡아 게임이 종료되었을 때 추가 제출 없이 종료 여부와 우승자를 안내하도록 개선하자는 제안이다. (개선 제안)
  - 조건: 참여자는 킹을 잡은 뒤 안내가 없고 제출 버튼을 한 번 더 눌러야 결과 출력 버튼이 있는 페이지로 이동하는 것 같다고 보고했다. 실제 수정 여부는 확인되지 않는다.

- [ ] 관리자의 수동 처리 지연으로 사용자가 빈 슬롯을 이용하지 못하는 불편을 줄이기 위해 자동 대기 승격을 선호한다. (의견)
  - 조건: 리뷰 참여자는 관리자 입장에서도 자동 승격이 더 좋다는 의견을 제시하고 사용자 이용 지연을 근거로 들었다. 작성자는 수동 방식의 UX 단점에 동의했다. 수동 방식에서 실제 장애가 발생했다거나 자동 방식이 모든 상황에서 필수라는 지적은 아니다.

- [ ] 방 목록의 버튼이 서로 붙어 있어 소속을 구분하기 어렵고 오클릭할 수 있으므로, 표나 구분선·여백 등을 활용해 배치를 개선하도록 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 UI가 미션의 큰 고려사항은 아니라는 전제를 밝혔다. 작성자는 form을 inline으로 바꾸어 한 줄로 배치했다고 보고했으나, 버튼 구분과 오클릭 우려가 해소되었는지는 확인되지 않는다.
