# FC0109 · 여러 API 사이의 공유 자원 경쟁

[소속 분야: 비동기·동시성](../05-concurrency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0108](FC0108.md) · [다음 FC: FC0097 →](FC0097.md)

## 검토 질문

- [ ] 서로 다른 API가 같은 자원을 변경할 때 공통 잠금·원자성 규칙을 적용하는가?

**직접 작성한 예시**

```sql
BEGIN;
SELECT id FROM slot WHERE id = :id FOR UPDATE;
-- 같은 슬롯의 취소와 대기 등록 모두 이 잠금을 먼저 획득
UPDATE reservation SET state = 'CANCELLED' WHERE id = :reservation_id;
COMMIT;
```

**적용 설명:** 서로 다른 API도 공유 자원의 정합성 규칙은 같아야 한다. 대기 승격·등록의 실제 변경 로직은 생략했다.

## 구체적인 검토 사례

- [ ] **상황:** 다른 API가 같은 자원의 상태를 바꾼다.
  - **판단 기준:** 공통 정합성 규칙을 적용한다.

- [ ] **상황:** 각 API 단위 테스트만 통과한다.
  - **판단 기준:** 상호 교차 실행 순서로 경쟁을 재현한다.
