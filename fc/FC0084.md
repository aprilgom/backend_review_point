# FC0084 · 외부 API URL을 코드에 직접 넣지 않고 외부 설정에서 관리하도록 바꾸고 그 장점을 생각해 볼 것을 제안했다.

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0077](FC0077.md) · [다음 FC: FC0081 →](FC0081.md)

- [ ] 외부 API URL을 코드에 직접 넣지 않고 외부 설정에서 관리하도록 바꾸고 그 장점을 생각해 볼 것을 제안했다. (개선 제안)
  - 조건: 작성자는 YAML에서 관리하도록 변경했다고 보고했다. URL을 한눈에 파악하기 쉽고 @Profile을 활용해 운영용과 테스트용 API를 분리할 수 있다는 장점을 작성자 자신의 설명으로 제시했으며, 실제 프로파일 분리까지 구현했다는 보고는 아니다.

- [ ] 외부 API URL을 코드에 고정하지 않고 외부 설정으로 주입해 관리하도록 제안하고 그 이점을 질문했다. (개선 제안)
  - 조건: 작성자는 TossPaymentClientProperties에서 base-url과 secret-key를 관리하도록 리팩터링했다고 보고하고, 코드 변경 없이 환경별 URL을 설정할 수 있어 유연성과 유지보수에 이점이 있다고 설명했다. secret-key 관리에 대한 별도의 보안 지적은 리뷰 참여자의 발언에 없다.

- [ ] 외부 API 호출 URL을 코드에 직접 넣기보다 설정 파일로 분리해 관리하는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 URL 변경과 테스트용 URL 구분에 유리하다고 설명하며 설정 파일로 옮겼다고 보고했다. 리뷰 참여자는 개발 환경에서 실제 결제 API를 호출하지 않는 등 실행 환경별 API 구분에 유용하다고 덧붙였다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
String endpoint = Objects.requireNonNull(System.getenv("PAYMENT_ENDPOINT"));
PaymentClient client = new PaymentClient(URI.create(endpoint));
```

**적용 설명:** 외부 주소를 환경 설정으로 주입하는 예시다. 허용 스킴·호스트 검증과 시작 시 누락 오류 처리도 구현한다.
