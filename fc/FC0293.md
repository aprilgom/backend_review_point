# FC0293 · 생성 유스케이스의 N+1 조회

## 검토 질문

- [ ] 여러 연관 객체를 생성할 때 입력 개수만큼 조회가 늘어나지 않으며 누락 검증도 유지하는가?

**직접 작성한 예시**

```java
List<Product> products = productStore.findAllByIds(input.productIds());
requireAllProductsFound(input.productIds(), products);
```

**적용 설명:** 메뉴 생성 시 N번 조회를 줄이되 누락된 상품 검증을 빼지 않는다.

## 구체적인 검토 사례

- [ ] 메뉴 생성 과정에서 요청한 상품 수만큼 개별 조회 쿼리가 실행되는 N+1 가능성을 지적한다. (위험 지적)
  - 조건: 작성자는 findAllById를 사용하도록 변경했다고 보고했다. 상품별 수량 연결은 애플리케이션에서 스트림으로 찾아 처리하며, 추가 쿼리보다 낫다고 판단했다고 설명했다. 이는 작성자의 구현 및 판단 보고이며 실제 성능이나 쿼리 실행 결과는 확인되지 않는다.

- [ ] 연관 엔티티 조회와 관련해 N+1 문제를 추가로 학습해 보도록 제안했다. (개선 제안)
  - 조건: EAGER를 사용하면 여러 쿼리를 피할 수 있다는 작성자의 설명 뒤에 나온 제안이다. 작성자는 이후 Hibernate 로그에서 JOIN 이후 theme과 reservationTime에 대한 별도 SELECT를 확인했다고 보고했다. 구체적인 N+1 발생 조건이나 해결 구현을 리뷰어가 확정한 것은 아니다.

- [ ] 연관 엔티티 조회에서 N+1 문제가 어떤 상황에 발생하는지 추가로 알아보자는 제안이다. (개선 제안)
  - 조건: 작성자는 다음 단계에서 학습한 뒤 PR 본문에 공유하겠다고 답했다. 현재 코드에서 N+1 문제가 발생한다는 보고나 학습 결과는 제시되지 않았다.
