# FC0343 · 각 테스트에 @DisplayName을 추가해 테스트 설명을 명시하자는 제안이다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0341](FC0341.md) · [다음 FC: FC0340 →](FC0340.md)

- [ ] 각 테스트에 @DisplayName을 추가해 테스트 설명을 명시하자는 제안이다. (개선 제안)
  - 조건: 작성자는 추가했다고 답했다. 실제 테스트 코드의 변경 내용은 이 대화에서 확인되지 않는다.

- [ ] 테스트의 의도를 더 정확히 알 수 있도록 @DisplayName을 사용하자는 제안이다. (개선 제안)
  - 조건: 검증 대상이나 테스트 범위를 추가하라는 요구가 아니라 테스트 설명의 명확성에 관한 제안이다. 작성자는 직접 구현한 모든 테스트 메서드에 적용했다고 보고했다.

- [ ] 다른 테스트 메서드에도 `@DisplayName`을 사용해 어떤 테스트인지 설명하도록 제안했다. (개선 제안)
  - 조건: 작성자는 추가했다고 보고하고 앞으로 일관되게 사용하겠다고 답했다. 테스트 검증 내용의 변경을 요구한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@Test
@DisplayName("빈 이름으로 생성하면 거절한다")
void rejectsEmptyName() {
    assertThrows(InvalidName.class, () -> new Name(""));
}
```

**적용 설명:** JUnit 5 표시 이름 예시다. 메서드 이름과 설명이 서로 다른 동작을 약속하지 않게 한다.
