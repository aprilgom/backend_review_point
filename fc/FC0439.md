# FC0439 · 전체 실행에서 드러나는 테스트 의존

## 검토 질문

- [ ] 개별 성공·전체 실패가 발생할 때 실행 순서·전역 상태·시간·DB 공유를 점검하는가?

**직접 작성한 예시**

```sh
./gradlew test --rerun-tasks
```

**적용 설명:** 개별 테스트 성공 뒤 전체 실행이 실패한다면 순서·전역 상태·시간·DB 공유를 확인한다.

## 구체적인 검토 사례

- [ ] 전체 테스트 실행 시 실패가 발생한다고 보고하고 그 원인을 살펴보도록 요청했다. (문제 보고)
  - 조건: 작성자는 Gradle 실행에서는 실패하지 않았지만 IntelliJ에서는 SubwayApplicationTests 실행 후 지하철역 생성 테스트가 실패했다고 설명했다. 이어 SubwayApplicationTests의 webEnvironment를 RANDOM_PORT로 맞추니 통과했다고 보고했으나, 정확한 실패 원인은 계속 조사 중이라고 밝혔다. 설정 변경이 근본 원인을 해결했는지는 확인되지 않는다.

- [ ] 전체 테스트를 한 번에 실행하면 대부분 실패하는 현상을 확인해 달라고 요청했다. (문제 보고)
  - 조건: 작성자는 테스트를 개별 실행해 전체 실행 실패를 확인하지 못했다고 답했다. 실패 원인이나 전체 실행 성공 여부는 제시되지 않았으며, 이후 승인과 머지만으로 해결을 확정할 수 없다.

- [ ] 개별 실행에서는 통과하지만 전체 테스트를 함께 실행하면 하나가 실패하는 현상을 확인해 달라고 요청했다. (문제 보고)
  - 조건: 최초 보고만으로 테스트 간 간섭 등 원인을 확정할 수 없다. 작성자는 로그인 요청을 POST로 바꾸면서 제대로 처리하지 못한 부분이 있었다고 설명하고 자신의 노트북에서는 모든 케이스가 정상 동작한다고 보고했다. 이후 리뷰 참여자도 실패했던 테스트의 정상 동작을 확인했다고 명시적으로 보고했으나, 구체적인 수정 내용은 이 대화에 제시되지 않았다.
