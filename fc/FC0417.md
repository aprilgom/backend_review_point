# FC0417 · 테스트 대역이 숨기는 저장소 동작

## 검토 질문

- [ ] fake가 DB 제약·쿼리·트랜잭션 오류를 가릴 수 있음을 알고 실제 저장소 테스트로 보완하는가?

**직접 작성한 예시**

```java
users.insert(new User("same"));
assertThrows(DuplicateName.class, () -> users.insert(new User("same")));
```

**적용 설명:** 실제 테스트 DB의 UNIQUE 제약과 예외 변환을 검증한다. 단순 Map fake가 같은 동작을 보장한다고 가정하지 않는다.

## 구체적인 검토 사례

- [ ] **상황:** fake 저장소가 유일성 제약을 생략한다.
  - **판단 기준:** 실제 저장소 테스트로 계약을 보완한다.

- [ ] **상황:** fake를 DB처럼 완벽히 만들려 한다.
  - **판단 기준:** 대역 목적과 필요한 통합 검증을 구분한다.
