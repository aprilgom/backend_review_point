# FC0366 · RequestMapping 클래스를 controller 패키지에 배치한 특별한 이유가 있는지 질문했다.

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0370](FC0370.md) · [다음 FC: FC0357 →](FC0357.md)

- [ ] RequestMapping 클래스를 controller 패키지에 배치한 특별한 이유가 있는지 질문했다. (설계 질문)
  - 조건: 리뷰 참여자는 자신도 패키지 위치를 고민했다며 설계 이유를 물었고, 잘못된 배치라고 단정하지 않았다. 작성자는 컨트롤러 작성 과정에서 패키지를 분리하지 못했다고 설명하며, URI에 대응하는 컨트롤러를 찾는 역할이므로 상위 패키지에 두는 것이 적절하겠다는 의견을 밝혔다. 실제 이동 여부는 확인되지 않는다.

- [ ] ResourceController를 LoginController, HomeController, RegisterController와 다른 패키지에 배치한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 다른 컨트롤러들은 서비스 로직이고 ResourceController는 톰캣에서 매핑할 컨트롤러가 없을 때 리소스를 출력하는 역할이라고 판단해 분리했다고 설명했다. 작성자가 리뷰어의 의견을 다시 물었지만 후속 답변은 제공되지 않아 합의나 변경 여부는 알 수 없다.

- [ ] AbstractController를 그 구현체들과 다른 패키지에 배치한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 로그인·회원가입 기능은 jwp에, Controller·Request·Response 등 웹 통신 기반 클래스는 apache 패키지에 배치하는 기준이라고 설명했다. 패키지 이동을 요구한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
package mvc.mapping;
public @interface Route { String path(); }
```

**적용 설명:** 매핑 표식이 특정 애플리케이션 컨트롤러에 속하는지 프레임워크에 속하는지 구분한다. 리플렉션에 쓰려면 RUNTIME 보존 정책을 추가해야 한다.
