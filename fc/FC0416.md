# FC0416 · 단일 시나리오를 넘는 테스트

## 검토 질문

- [ ] 메서드마다 한 가지 입력만 확인하지 않고 정상·경계·오류·상태별 사례를 검토했는가?

**직접 작성한 예시**

```java
assertEquals(1, new Quantity(1).value());
assertThrows(IllegalArgumentException.class, () -> new Quantity(0));
assertThrows(IllegalArgumentException.class, () -> new Quantity(-1));
```

**적용 설명:** 정상·경계·비정상 사례로 나누어 한 가지 입력만 검증하는 한계를 줄인다.

## 구체적인 검토 사례

- [ ] 각 메서드를 한 가지 상황으로만 테스트하는 것으로 보이는데, 다른 상황도 테스트할 필요가 없는지 질문했다. (설계 질문)
  - 조건: 작성자는 테스트를 추가했다고 답했으나, 추가된 테스트의 내용과 충분성은 이 대화에서 확인되지 않는다.

- [ ] 테스트되지 않은 메서드에 대한 테스트를 리팩터링하면서 추가하도록 요청했다. (개선 제안)
  - 조건: 대상 메서드의 구체적인 이름이나 추가할 검증 시나리오는 제시되지 않았다.

- [ ] 새로 추가한 메서드에 대해서도 테스트를 작성하자는 제안이다. (개선 제안)
  - 조건: GameServiceTest에 남긴 요청이며, 댓글에는 대상 메서드 이름이나 구체적인 검증 시나리오가 명시되지 않았다. 테스트 추가 여부에 대한 답변도 없다.
