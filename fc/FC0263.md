# FC0263 · 디버그 출력과 민감 정보

[소속 분야: 로그·관측](../15-observability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0264](FC0264.md)

## 검토 질문

- [ ] 개발용 출력이 운영에 남아 자격증명·토큰·개인정보를 노출하거나 로그를 오염시키지 않는가?

**직접 작성한 예시**

```javascript
const result = await signIn(credentials);
showSignedInState(result.user);
// credentials나 token을 console.log로 출력하지 않는다.
```

**적용 설명:** 로그인 디버그 출력 제거 예다. 브라우저 로그와 서버 로그 모두 비밀값 노출을 확인한다.

## 구체적인 검토 사례

- [ ] 로그인 처리 코드에 남아 있는 console.log 콘솔 출력을 지적했다. (관찰)
  - 조건: 리뷰 문구는 '콘솔 출력~'이며, 인라인 코드의 회원 확인 로그를 대상으로 한다. 제거 요구나 후속 변경은 명시되어 있지 않다.

- [ ] 회원가입 요청 처리 코드에 System.out.println 출력이 남아 있음을 지적했다. (관찰)
  - 조건: 제시된 코드에는 hello와 hello2 출력이 있다. 삭제나 로거로의 교체를 명시적으로 요구하지 않았으며, 후속 처리 여부도 제시되지 않았다.

- [ ] 디버깅용 출력이 더 이상 필요하지 않으면 제거하고, 계속 사용할 출력이라면 콘솔 출력 대신 로거를 사용하도록 제안했다. (조건부 제안)
  - 조건: 출력의 지속적인 필요 여부에 따라 제거 또는 로거 사용을 제안한 것이다. 작성자는 디버깅 후 지우지 못한 출력 코드가 남아 있었다고 인정했지만, 실제 제거 여부는 대화에서 확인되지 않는다.
