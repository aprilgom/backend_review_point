# FC0386 · OrderService의 사용 중이지 않은 테이블에 대한 주문 검증을 Order 생성 시 도메인에서 수행하도록 옮길 것을 제안했다.

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0385](FC0385.md) · [다음 FC: FC0372 →](FC0372.md)

- [ ] OrderService의 사용 중이지 않은 테이블에 대한 주문 검증을 Order 생성 시 도메인에서 수행하도록 옮길 것을 제안했다. (개선 제안)
  - 조건: 인라인 대상은 orderTable.isEmpty() 검증이다. 작성자는 반영하겠다고 답했으며, 실제 이동 여부는 확인되지 않는다.

- [ ] 비어 있는 주문 테이블에는 주문을 추가할 수 없다는 검증을 서비스가 아니라 Order 도메인에서 수행하도록 제안했다. (개선 제안)
  - 조건: 인라인 대상은 OrderService.validOrderTable의 테이블 비어 있음 검사이다. 댓글의 '동일하게'가 가리키는 다른 논의는 제공되지 않았지만, 이 검증을 Order 도메인으로 옮기자는 제안 자체는 확인된다. 작성자의 답변이나 반영 결과는 없다.

- [ ] 주문 테이블이 비어 있고 그룹에 속하지 않는지 확인하는 검증을 서비스 대신 OrderTable 내부에 둘 것을 제안한다. (개선 제안)
  - 조건: 작성자는 검증을 이동했다고 답했다. 실제 변경 내용은 이 대화만으로 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
static Order create(Table table, List<Line> lines) {
    if (!table.isInUse()) throw new TableNotInUse();
    return new Order(table.id(), List.copyOf(lines));
}
```

**적용 설명:** 생성 경로에서 업무 제약을 보장한다. 외부 상태가 동시에 바뀌는 경우는 저장 트랜잭션에서도 확인한다.
