# FC0298 · verifyLogin이라는 이름만으로 반환하는 값을 예측하기 어려우므로, 반환 동작을 더 직관적으로 드러내는 이름으로 변경하도록 요청한다.

- [ ] verifyLogin이라는 이름만으로 반환하는 값을 예측하기 어려우므로, 반환 동작을 더 직관적으로 드러내는 이름으로 변경하도록 요청한다. (개선 제안)
  - 조건: 작성자는 getResponseBasedOnSession으로 이름을 변경했다고 보고했다.

- [ ] menuQuantityMap처럼 변수명에 자료형을 포함한 명명 방식에 가벼운 우려를 표현한다. (의견)
  - 조건: 리뷰 참여자는 자신도 이름이 떠오르지 않을 때 같은 방식을 사용한다고 덧붙였다. 명시적인 변경 요구나 지적 철회는 아니다.

- [ ] getRank가 저장된 값 대신 rank + 1을 반환하면 getter에 대한 기대와 달라 혼란스러울 수 있으므로 이름 변경이나 다른 표현을 제안했다. (개선 제안)
  - 조건: 참여자는 특정 대안만을 강제하지 않았다. 작성자는 getAdjustedRank로 이름을 바꿨다고 코드와 함께 보고했으며, 그 변경의 적절성에 대한 후속 평가는 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Optional<Actor> authenticate(Credentials credentials) {
    return authentication.check(credentials);
}
```

**적용 설명:** boolean 검증인지 사용자 반환인지 이름과 반환 타입이 함께 설명해야 한다.
