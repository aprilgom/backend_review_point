## 검토 질문

- [ ] 실패 테스트를 좁혀 재현하고 기대값 변경 전에 요구사항·준비 데이터·구현 원인을 확인하는가?

**직접 작성한 예시**

```sh
./gradlew test --tests '*PriceTest' --rerun-tasks
```

**적용 설명:** 실패 테스트를 좁혀 재현하는 명령 예다. 기대값만 바꾸기 전에 실제 계약·준비 데이터·구현을 확인한다.

## 구체적인 검토 사례

- [ ] **상황:** 실패 테스트의 기대값부터 고친다.
  - **판단 기준:** 실제 계약과 준비 조건을 먼저 확인한다.

- [ ] **상황:** 전체 실행만 반복해 원인을 못 찾는다.
  - **판단 기준:** 가장 작은 실패를 재현해 범위를 좁힌다.
