# FC0323 · findVerifiedStationByName이라는 메서드 이름에 어떤 의도를 담았는지 질문했다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0319](FC0319.md) · [다음 FC: FC0305 →](FC0305.md)

- [ ] findVerifiedStationByName이라는 메서드 이름에 어떤 의도를 담았는지 질문했다. (설계 질문)
  - 조건: 작성자는 이름으로 역을 찾고 없으면 생성하여 반환하려는 의도였다고 설명했다. 이후 리팩터링 과정에서 해당 메서드를 제거했다고 보고했다.

- [ ] carEntityRowMapper처럼 명사로 시작하는 메서드 이름이 적절한지 질문했다. (설계 질문)
  - 조건: 작성자는 명명이 잘못되었다고 답했다. 반복 사용과 가독성을 이유로 RowMapper를 필드에 할당하자는 의견은 작성자가 추가한 것이며 리뷰어의 별도 요구는 아니다.

- [ ] UserResultSetParser 메서드 이름을 대문자로 시작한 것이 의도적인지 질문했다. (설계 질문)
  - 조건: 작성자는 오타였다고 답하고 수정했다고 보고했다. 실제 수정 내용은 이 대화에서 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Station requireStationByName(String name) {
    return stations.findByName(name).orElseThrow(StationNotFound::new);
}
```

**적용 설명:** 조회 부재 시 예외를 던진다는 계약을 require로 표현한 예다. verified가 어떤 검증을 뜻하는지 모호하게 남기지 않는다.
