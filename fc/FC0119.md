# FC0119 · 조회 결과에 covid.id와 programmer.id를 모두 포함하기보다 둘 중 하나만 사용해도 된다고 제안했다.

[소속 분야: 쿼리·데이터 조작](../07-data-query.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0121](FC0121.md) · [다음 FC: FC0120 →](FC0120.md)

- [ ] 조회 결과에 covid.id와 programmer.id를 모두 포함하기보다 둘 중 하나만 사용해도 된다고 제안했다. (개선 제안)
  - 조건: 작성자는 제안에 동의하는 반응을 보였으나 실제 변경 여부는 확인되지 않는다. 두 식별자의 동등성이나 하나를 생략해도 요구사항을 충족하는지는 대화에서 검증되지 않았다.

- [ ] 조회 결과가 두 개 이상이어도 첫 번째 행만 반환하는 동작이 사용자의 의도와 어긋나지 않는지 질문했다. (설계 질문)
  - 조건: 작성자는 queryForObject를 별도로 만들지 않고 query가 단일 객체를 반환하도록 의도했다고 설명했다. query는 리스트를 반환하고 queryForObject를 분리하는 편이 나은지 되물었으며, 이에 대한 후속 답변은 없다.

- [ ] 조회 결과를 인덱스로 읽으면 필드를 잘못 매핑할 수 있으므로 필드 이름으로 매핑하는 방식을 제안했다. (개선 제안)
  - 조건: 작성자는 RowMapper에서 매핑하도록 수정했다고 답했다. 이름 기반 매핑의 실제 적용 여부는 이 답변만으로 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```sql
SELECT p.id AS person_id, s.status
FROM person p JOIN person_status s ON s.person_id = p.id;
```

**적용 설명:** 같은 식별자를 중복 반환하지 않는 예다. 외부 조인에서는 양쪽 값이 항상 같다고 가정하면 안 된다.
