# FC0345 · 템플릿 이름과 경로 해석

[소속 분야: 렌더링·데이터 로딩](../18-rendering.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0346](FC0346.md) · [다음 FC: FC0344 →](FC0344.md)

## 검토 질문

- [ ] 논리 뷰 이름의 선행 슬래시·접미사·상대 경로가 실제 템플릿 탐색에 어떤 영향을 주는지 알고 있는가?

**직접 작성한 예시**

```java
String viewName = "home";
Path template = templateRoot.resolve(viewName + ".html");
```

**적용 설명:** 자체 리졸버의 상대 이름 계약이다. 앞의 슬래시가 루트를 바꾸는지 확인하고 임의 사용자 입력을 경로로 쓰지 않는다.

## 구체적인 검토 사례

- [ ] 반환하는 템플릿 이름을 index가 아닌 /index로 지정한 이유를 묻는다. (설계 질문)
  - 조건: 선행 슬래시를 넣은 이유에 대한 질문이며, 오동작이 보고되거나 답변이 제시된 것은 아니다.

- [ ] templates/index.html과 static/index.html을 함께 둔 이유와 두 파일의 차이를 질문했다. (설계 질문)
  - 조건: 작성자는 static/index.html의 삭제를 누락했다고 설명했다. 또한 두 폴더를 정적·동적 페이지 및 뷰 리졸버 경유 여부로 구분한다고 이해하고 있으며, navTemplate을 넣는 동적 부분 때문에 templates의 파일을 남겼다고 답했다. 이 설명의 기술적 타당성과 실제 삭제 여부는 확인되지 않는다.

- [ ] 타임리프가 HTML 파일을 찾아 뷰로 반환하는 동작 원리를 설명해 달라는 질문이다. (설계 질문)
  - 조건: 리뷰어는 static 하위 파일을 전제로 질문했지만, 작성자는 ViewResolver와 템플릿 처리 흐름을 설명하면서 기본 경로를 classpath:/templates/라고 서술했다. 실제 파일 위치나 두 설명의 관계는 대화에서 확인되지 않으며, 작성자의 설명을 검증된 동작으로 확정하지 않는다.
