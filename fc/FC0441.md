# FC0441 · 테스트 전용 생성자를 추가하기보다 객체 생성이 번거로운 경우 픽스처를 활용하는 방안을 제안했다.

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0435](FC0435.md) · [다음 FC: FC0440 →](FC0440.md)

- [ ] 테스트 전용 생성자를 추가하기보다 객체 생성이 번거로운 경우 픽스처를 활용하는 방안을 제안했다. (개선 제안)
  - 조건: 테스트만을 위한 생성자를 선호하지 않는다는 개인적 입장을 밝힌 제안이며, 테스트 전용 생성자를 보편적으로 금지한 것은 아니다.

- [ ] 테스트 준비 과정에서 반복되는 객체 생성 부분을 테스트 픽스처로 추출하자고 제안했다. (개선 제안)
  - 조건: 반복되는 테스트 준비 코드에 대한 선택적 개선 제안이며, 반영 여부는 제시되지 않았다.

- [ ] 테스트를 위해 생성자를 여러 개 추가하는 대신 기존 생성자와 테스트 픽스처를 활용하는 방법을 제안했다. (개선 제안)
  - 조건: 대안 제안이며 생성자 추가를 확정적인 결함으로 지적한 것은 아니다. 작성자는 프로덕션 코드 변경 없이 테스트하도록 픽스처를 만들어 활용했다고 보고했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
User user = UserFixture.active("reader");
```

**적용 설명:** fixture가 제품의 공개 생성·상태 전이 경로를 사용하게 한다. 테스트용 우회 생성자를 제품에 추가하지 않는다.
