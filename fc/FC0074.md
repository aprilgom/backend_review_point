# FC0074 · 의존성의 실제 사용과 빌드 재현

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0075](FC0075.md) · [다음 FC: FC0076 →](FC0076.md)

## 검토 질문

- [ ] 추가한 의존성이 실제로 필요하고 깨끗한 환경에서도 빌드와 테스트가 동작하는가?

**직접 작성한 예시**

```sh
./gradlew dependencies --configuration testRuntimeClasspath
./gradlew clean test
```

**적용 설명:** 테스트 의존성이 실제 해석되는지와 깨끗한 빌드에서 실행되는지를 함께 확인한다. Windows에서는 gradlew.bat를 사용한다.

## 구체적인 검토 사례

- [ ] rest-assured 의존성을 실제로 사용하는지, 해당 모듈이 있는 상태에서 작성자 환경에서도 빌드와 실행이 정상인지 확인하고 싶다. (설계 질문)
  - 조건: 리뷰 참여자는 자신의 환경에서 모듈 충돌로 빌드되지 않았고 의존성을 제거하면 실행됐다고 보고했으며, 높은 버전을 원인으로 추측했다. 작성자는 자신의 환경에서는 동작하지만 컨트롤러 테스트용으로 추가한 뒤 실제로 사용하지 않은 의존성이라고 설명하고 제거하겠다고 답했다. 충돌 원인과 제거 완료 여부는 확인되지 않았다.

- [ ] DispatcherServletInitializer의 패키지 위치 때문에 API가 제대로 동작하지 않는 것으로 보고 위치 수정을 요청했다. (문제 보고)
  - 조건: 참여자는 패키지 위치를 원인으로 추정했으며, 시간이 있으면 이유도 생각해 보라고 권했다. 작성자는 패키지를 app으로 옮겼다고 보고했다. 후속 승인은 있지만 원인 규명이나 수정 후 동작 검증 내용은 제시되지 않았다.

- [ ] 일부 페이지가 정상 동작하지 않으므로 DispatcherServletInitializer의 위치 변경이 영향을 주었는지 재확인해 달라고 요청했다. (문제 보고)
  - 조건: 작성자 외 참여자는 페이지 동작 이상을 보고했지만, 초기화 클래스의 위치 변경은 가능한 원인으로만 제시했다. 구체적인 페이지와 재현 조건은 명시되지 않았으며, 이후 승인만으로 원인이나 수정 완료를 확정할 수 없다.
