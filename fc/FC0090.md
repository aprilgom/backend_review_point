# FC0090 · Redis 설정에 별도의 프로파일을 지정한 이유를 묻는다.

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0094](FC0094.md) · [다음 FC: FC0079 →](FC0079.md)

- [ ] Redis 설정에 별도의 프로파일을 지정한 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 복제 지연 테스트가 목적인 DB와 달리 캐시는 애플리케이션과 테스트의 환경을 분리하고 싶었으며, 우선 떠오른 방법으로 프로파일을 적용했다고 설명했다. 프로파일 사용을 결함으로 지적한 것은 아니다.

- [ ] jar.enabled와 bootJar.enabled를 각각 false로 설정하는 역할을 확인한다. (설계 질문)
  - 조건: 작성자는 jar가 클래스·리소스만 포함하는 plain JAR를, bootJar가 java -jar로 실행 가능한 JAR를 생성하는지 결정한다고 설명하고 관련 기능의 제공 주체에 대한 설명과 링크를 덧붙였다. 리뷰 참여자는 jar Task를 몰랐다고 답했다. 작성자의 기술 설명은 답변 내용으로 보존하며, 링크나 감사 표현으로 정확성을 확정하지 않는다.

- [ ] application.yml에서 spring.jpa.open-in-view를 false로 별도 설정한 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 자신이 추가한 설정이 아니라 구구의 커밋이 미션을 일찍 시작하는 과정에서 섞인 것 같다고 설명했다. 설정의 기술적 의도나 적절성에 대한 답변은 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Cache cache = config.cacheEnabled()
    ? new RemoteCache(config.cacheAddress())
    : new MemoryCache();
```

**적용 설명:** 특정 환경에서 외부 캐시를 쓰는 목적을 드러낸다. 두 구현의 TTL·직렬화·실패 의미가 같다는 보장은 없다.
