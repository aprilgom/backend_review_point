# FC0105 · 스레드별 컨텍스트의 수명

## 검토 질문

- [ ] 스레드 로컬 상태를 작업 종료 시 정리하고 풀 재사용·비동기 경계에서 누출되지 않게 하는가?

**직접 작성한 예시**

```java
try {
    requestContext.set(actor);
    process();
} finally { requestContext.remove(); }
```

**적용 설명:** ThreadLocal을 사용하는 스레드 풀에서는 작업 종료 시 제거한다. 다른 스레드·비동기 작업으로 값이 자동 전달된다고 가정하지 않는다.

## 구체적인 검토 사례

- [ ] 학습 차원에서 ThreadLocal이 무엇인지 설명해 달라고 질문했다. (설계 질문)
  - 조건: 작성자는 각 스레드가 자신만의 독립적인 변수를 가지도록 하는 클래스라고 답했다. 구현 결함을 지적하거나 변경을 요구한 대화는 아니다.

- [ ] ThreadLocal.withInitial(HashMap::new)을 사용해 스레드별 자원 맵을 초기화하는 대안을 제안했다. (개선 제안)
  - 조건: 자원 맵이 null일 때 생성하고 설정하는 코드에 대한 초기화 방식 제안이다. 작성자는 적용하겠다고 답했지만 실제 반영 여부는 확인되지 않는다.

- [ ] 여러 클라이언트가 동시에 난수를 빈번하게 생성할 때 Math.random()의 경합 가능성을 검토하고 ThreadLocalRandom 사용을 제안한다. (조건부 제안)
  - 조건: 처음에는 동시 접속 시 문제가 없는지 질문했고, 후속 발언에서는 다수 스레드의 빠른 난수 생성 시 경합을 줄이는 취지라고 설명하며 Javadoc 확인을 권했다. 인용된 설명은 Math.random()의 다중 스레드 사용 자체는 동기화로 보장된다고 하므로 스레드 안전성 결함으로 해석하지 않는다. 작성자는 ThreadLocalRandom으로 변경했다고 보고했지만 성능 측정이나 변경 코드는 제시되지 않았다.
