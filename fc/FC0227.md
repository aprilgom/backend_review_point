# FC0227 · 주문 준비 검증에 OrderTable이 empty인 경우에 대한 검증을 추가해 달라고 요청했다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0232](FC0232.md) · [다음 FC: FC0234 →](FC0234.md)

- [ ] 주문 준비 검증에 OrderTable이 empty인 경우에 대한 검증을 추가해 달라고 요청했다. (개선 제안)
  - 조건: OrderValidatorImpl.validatePrepare에 대한 요청이다. 원문의 empty가 의미하는 구체적인 상태나 실패 처리 방식은 별도로 설명되지 않았으므로 이를 임의로 확장하지 않는다.

- [ ] OrderItemRequest에 입력 검증을 추가하는 방안을 고려하자고 제안했다. (개선 제안)
  - 조건: 검증할 필드나 구체적인 유효성 조건은 명시되지 않았다. 작성자는 validation을 추가했다고 답했으나 검증 범위와 실제 구현은 확인되지 않는다.

- [ ] 손님 수 변경 시 수행하는 검증을 OrderTable 객체 생성 시에도 적용할 필요가 있다고 제안했다. (개선 제안)
  - 조건: 작성자는 생성 시 검증을 빠뜨렸다고 인정하고 수정했다고 보고했다. 수정된 코드나 검증 결과는 이 대화에 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
if (table.isEmpty()) throw new EmptyTable();
if (!table.isReady()) throw new TableNotReady();
```

**적용 설명:** 서로 다른 거절 이유를 구분해 경계값 테스트를 작성한다.
