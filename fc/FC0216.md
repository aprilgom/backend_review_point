# FC0216 · 요청 데이터 검증 로직이 없는 상태에서 null 저장을 의도한 것인지 질문했다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0215](FC0215.md) · [다음 FC: FC0217 →](FC0217.md)

- [ ] 요청 데이터 검증 로직이 없는 상태에서 null 저장을 의도한 것인지 질문했다. (설계 질문)
  - 조건: 작성자는 해당 경우를 고려하지 못했다고 답하고, Spring 학습 목적도 고려해 validation 의존성을 추가하여 null 검증을 구현했다고 보고했다. 사진에만 있는 구체적인 재현 조건은 이 단위에서 확인되지 않지만, null 검증에 관한 질문 자체는 본문에 명시되어 있다.

- [ ] 본문을 읽은 뒤 Objects.isNull(requestBodyData)로 null을 검사하는 조건이 꼭 필요한지 질문했다. (설계 질문)
  - 조건: null 검사 필요성을 확인하는 질문이다. IOUtils.readData의 반환 보장은 제시되지 않아 해당 조건이 불필요하다고 확정할 수 없다.

- [ ] ModelAndView를 반복해서 null 검사하는 코드에서 실제로 null이 들어오는 상황이 언제인지 질문했다. (설계 질문)
  - 조건: 작성자는 현재 컨트롤러가 ModelAndView를 반환하므로 null 가능성은 낮지만, 프레임워크 차원의 방어를 위해 검사를 유지했다고 설명했다. 개발자 실수 외의 구체적인 null 발생 사례는 제시하지 않았으며, 검사 제거를 요구한 질문은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
String title = Objects.requireNonNull(input.title(), "title").strip();
if (title.isEmpty()) throw new InvalidTitle();
```

**적용 설명:** NULL 허용 여부를 명시하고 저장 전에 검증한다. 경계 예외를 클라이언트 오류 계약에 맞게 변환한다.
