# FC0329 · 테스트 이름을 단순한 단계 번호가 아니라 어떤 내용을 검증하는지 드러나도록 작성하자는 제안이다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0328](FC0328.md) · [다음 FC: FC0341 →](FC0341.md)

- [ ] 테스트 이름을 단순한 단계 번호가 아니라 어떤 내용을 검증하는지 드러나도록 작성하자는 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 이전처럼 테스트 내용을 이름에 나타내는 편이 이해하기 쉽다고 설명했다. 작성자는 기능 명세 역할을 고려해 이름을 수정하겠다고 답했으며, 변경 결과는 확인되지 않는다.

- [ ] 장바구니 수량 변경 테스트의 이름이 실제 검증 내용을 잘 표현하는지 확인하자. (설계 질문)
  - 조건: 작성자는 이름을 '장바구니 수량을 하나 추가하는 기능'으로 수정하겠다고 답했다. 그 이름이 실제 검증과 일치한다는 후속 확인은 없다.

- [ ] 파라미터화 테스트의 표시 이름에 인자의 숫자와 단위를 함께 나타내도록 제안한다. (개선 제안)
  - 조건: 작성자는 테스트 이름을 '운임에 따른 요금을 반환한다. : x km, x 원' 형식으로 수정했다고 보고하고, 인덱스로 각 인자를 지정하는 방식을 설명했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@Test void rejectsBookingInThePast() {
    assertThrows(PastSlot.class, () -> book(yesterday));
}
```

**적용 설명:** 단계 번호보다 상황·기대 결과를 이름에 담는다.
