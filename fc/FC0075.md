# FC0075 · ddl-auto의 create-drop 동작과 다른 옵션을 정리하고, 운영 환경에 적합한 옵션을 검토해 보라고 제안했다.

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0083](FC0083.md) · [다음 FC: FC0074 →](FC0074.md)

**혼합·경계:** Hibernate 스키마 생성 정책과 Spring Boot 설정 표현이 겹침.

- [ ] ddl-auto의 create-drop 동작과 다른 옵션을 정리하고, 운영 환경에 적합한 옵션을 검토해 보라고 제안했다. (개선 제안)
  - 조건: 작성자는 옵션별 동작을 정리하고 운영 환경에서는 validate 또는 none이 안전할 것 같다고 답했다. 현재 인메모리 DB에서는 의미가 크지 않다고 덧붙이면서 학습 적용 차원에서 update로 변경했다고 보고했다. 리뷰 참여자가 update 변경을 요구하거나 운영용으로 승인한 것은 아니다.

- [ ] ddl-auto를 create에서 create-drop으로 변경한 이유를 확인하고, 운영 배포 시 기존 데이터가 사라지지 않도록 환경별 properties 분리를 고려하라고 제안했다. (토론)
  - 조건: 작성자는 잘못 만든 엔티티의 테이블을 정리하려고 일시적으로 변경했다가 되돌리지 않았으며, 로컬·학습 환경에서는 유용할 수 있다고 설명했다. 리뷰 참여자도 로컬 사용은 긍정적으로 보았지만 운영 배포에서의 데이터 손실 가능성을 구분했다. 작성자는 환경별 ddl-auto 옵션을 학습했다고 답했으며, 실제 설정 분리나 변경 완료 여부는 확인되지 않는다.

- [ ] ddl-auto 속성에서 선택할 수 있는 값들을 하나씩 정리해 보는 것이 좋겠다. (개선 제안)
  - 조건: 현재 사용 중인 create-drop에 대한 설명을 받은 뒤 추가 학습을 제안한 것이다. 다른 값으로 변경하라는 요구는 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```properties
# 일회성 테스트 DB에만 사용하는 설정 예
hibernate.hbm2ddl.auto=create-drop
```

**적용 설명:** 생성·삭제 수명에 따른 데이터 손실을 이해하는 예시다. 운영 설정으로 복사하지 않고 운영 스키마 변경은 명시적으로 관리한다.
