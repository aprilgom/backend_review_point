# FC0055 · HandlerExecution이 String뿐 아니라 ModelAndView 등 여러 반환 타입을 지원하도록 바꾸자고 제안했다.

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0063](FC0063.md) · [다음 FC: FC0066 →](FC0066.md)

- [ ] HandlerExecution이 String뿐 아니라 ModelAndView 등 여러 반환 타입을 지원하도록 바꾸자고 제안했다. (개선 제안)
  - 조건: 요구사항 1에서 사용자가 ModelAndView를 반환하는 요청 처리 메서드를 만들 수 있다는 설명과 예시를 근거로 제안했다. 모든 타입을 무제한 지원해야 한다는 요구로 확대하지 않는다.

- [ ] Runnable을 받는 executeTransaction이 반환값이 있는 작업도 처리할 수 있도록 고려할 것을 제안했다. (개선 제안)
  - 조건: 현재 요구사항에는 반환값이 있는 경우가 포함되지 않는다는 점을 명시한 확장 제안이다.

- [ ] scan()을 반복 호출할 때 기존 handlers가 누적되는 동작이 의도인지 확인하고, 의도가 아니라면 초기화하는 방안을 검토하자고 했다. (조건부 제안)
  - 조건: 작성자는 Map이므로 반복 실행해도 누적되지 않는 것 아니냐고 반문했다. 리뷰어는 서로 다른 basePackages로 여러 번 호출하는 상황을 뜻했다고 조건을 명확히 했다. 실제 의도나 변경 결과는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
interface Handler { HandlerResult handle(HttpRequest request); }
sealed interface HandlerResult permits TextResult, PageResult {}
record TextResult(String body) implements HandlerResult {}
record PageResult(String template, Map<String, Object> model) implements HandlerResult {}
```

**적용 설명:** 직접 만드는 핸들러의 결과 타입을 명시적으로 확장한다. 각 결과를 처리하는 렌더러도 필요하다.
