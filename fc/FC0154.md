# FC0154 · 서비스 인터페이스의 도입 기준

## 검토 질문

- [ ] 구현 수만이 아니라 계약 분리·대체·경계의 필요를 기준으로 서비스 인터페이스를 도입하는가?

**직접 작성한 예시**

```java
final class PriceService {
    Money price(Basket basket) { return basket.subtotal(); }
}
```

**적용 설명:** 교체 가능한 계약이 아직 필요하지 않다면 구체 클래스만으로 시작할 수 있다. 구현체 수만으로 인터페이스 필요성을 결정하지 않는다.

## 구체적인 검토 사례

- [ ] **상황:** 구현체 하나마다 인터페이스를 만든다.
  - **판단 기준:** 계약 경계·대체 필요를 설명할 수 있어야 한다.

- [ ] **상황:** 구현체 수가 하나라서 경계 분리를 거부한다.
  - **판단 기준:** 현재의 도메인 격리나 테스트 이점도 고려한다.
