# FC0442 · given().willReturn으로 반환값을 설정하기 전에 orderTable의 setEmpty를 호출하는 편이 더 자연스럽다고 제안했다.

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0437](FC0437.md)

- [ ] given().willReturn으로 반환값을 설정하기 전에 orderTable의 setEmpty를 호출하는 편이 더 자연스럽다고 제안했다. (개선 제안)
  - 조건: 테스트 준비 코드의 순서에 대한 제안이며, 현재 순서가 실행 오류를 일으킨다고 지적한 것은 아니다. 작성자는 SpringBootTest로 변경하여 이 제안에 맞게 처리했는지 모르겠다고 답했다. 변경된 코드나 후속 확인은 제공되지 않았다.

- [ ] 리졸버에 필요한 파라미터를 목으로 구성하고 어떤 값을 넣어야 동작하는지 학습해보는 방법도 제안한다. (개선 제안)
  - 조건: 작성자가 테스트용 컨트롤러를 별도로 만들고 빈으로 등록하는 방식의 적합성을 질문한 데 대한 답변이다. 리뷰 참여자는 현재 방식도 충분하다고 인정하면서, 구현 이해를 위한 선택적인 추가 학습 방법으로 목 구성을 제안했다.

- [ ] 이미 단체 지정된 테이블의 재지정 예외를 재현하려면 기존 TableGroup이 아니라 newTableGroup에 해당 테이블을 설정해야 하는지 확인한다. (설계 질문)
  - 조건: 리뷰 참여자는 이미 지정된 orderTableA와 orderTableB로 새 그룹을 구성해야 하는지 질문했다. 작성자는 기존 그룹에 설정한 실수를 인정하고 수정했다고 보고했으나, 실제 시나리오는 이미 지정된 A와 미지정 C를 함께 새 그룹으로 지정하는 것으로 구성했다고 설명했다. 수정 후 테스트 결과는 확인되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
table.setEmpty(true);
given(tables.find(id)).willReturn(Optional.of(table));
```

**적용 설명:** 대역 반환을 설정하기 전에 의도한 상태를 준비한다. 이후 가변 객체 변경이 테스트를 혼란스럽게 하지 않도록 한다.
