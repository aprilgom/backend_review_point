# FC0249 · 공개 오류와 내부 진단의 분리

[소속 분야: 예외·실패 계약](../13-errors.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0251](FC0251.md) · [다음 FC: FC0252 →](FC0252.md)

## 검토 질문

- [ ] 상세 원인은 통제된 로그에 남기고 사용자에게는 안전한 메시지와 추적 수단을 제공하는가?

**직접 작성한 예시**

```java
String incidentId = newIncidentId();
logFailure(incidentId, failure);
return error(500, "INTERNAL_ERROR", incidentId);
```

**적용 설명:** 상세 원인은 통제된 로그에 남기고 응답에는 추적 ID와 일반 코드를 준다.

## 구체적인 검토 사례

- [ ] 예상하지 못한 예외의 원래 메시지를 응답으로 그대로 전달하기보다, 상세 내용은 로그로 확인하고 클라이언트에는 일반적인 오류 메시지를 제공하도록 제안했다. (개선 제안)
  - 조건: 리뷰어는 실제 시스템에서는 로그로 상세 오류를 확인할 수 있다는 전제로 제안했다. 작성자는 클라이언트에 전달할 예외 메시지의 보안 측면을 놓쳤다고 답하고 반영했다고 보고했으나, 변경 결과는 이 대화에서 확인되지 않는다.

- [ ] IllegalArgumentException 이외의 예외에도 클라이언트가 처리할 수 있는 오류 메시지를 제공하자는 제안이다. (개선 제안)
  - 조건: 작성자는 예외들을 커스텀 예외로 바꾸었다고 보고했지만, 다른 예외에 대한 응답 처리 범위가 실제로 확대되었는지는 확인되지 않는다.

- [ ] 예외 메시지를 그대로 응답에 넣기보다 사람이 이해하기 쉬운 오류 메시지를 제공할 것을 제안했다. (개선 제안)
  - 조건: 응답 메시지의 이해 가능성에 관한 의견이다. 작성자의 후속 답변에는 이 메시지 개선을 실제로 반영했는지 명시되어 있지 않다.
