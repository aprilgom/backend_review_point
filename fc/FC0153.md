# FC0153 · 외부에서 의존성을 주입받는 구조가 되었으므로 일부 클래스를 제외하면 mvc로 옮겨도 mvc가 app을 의존하지 않을 것으로 보인다고 확인했다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0151](FC0151.md) · [다음 FC: FC0150 →](FC0150.md)

- [ ] 외부에서 의존성을 주입받는 구조가 되었으므로 일부 클래스를 제외하면 mvc로 옮겨도 mvc가 app을 의존하지 않을 것으로 보인다고 확인했다. (관찰)
  - 조건: 리뷰 참여자는 DispatcherServletInitializer와 이름에 Manual이 붙은 클래스들을 이동 가능 범위에서 제외했다. 작성자는 이에 동의하면서 빠뜨린 작업이 있다고 답했다. 이는 이동 가능성과 의존 방향에 대한 관찰이며, 실제 패키지 이동이나 의존성 검증이 완료되었다는 증거는 아니다.

- [ ] 콘솔 UI에도 Spring Boot가 필요한지, 향후 웹 UI와 웹 의존성을 제거해도 콘솔 UI가 동작하는지 검토하도록 질문했다. (토론)
  - 조건: 웹 기능을 제거하는 가정을 둔 질문이다. 작성자는 자동 주입의 편의 때문에 Spring을 사용했지만 콘솔 부분을 Spring과 분리하겠다고 답했다. 리뷰어는 불필요한 의존이 유지보수를 어렵게 할 수 있다고 덧붙였다. 웹 의존성 제거가 곧 Spring 전체 제거를 필수로 뜻한다는 기술적 결론은 확인되지 않았다.

- [ ] RequestMapping이 Controller 인터페이스만 알아도 될 것으로 보이는데 AbstractController 추상 클래스에 의존하도록 선택한 이유를 묻는다. (설계 질문)
  - 조건: 리뷰 참여자는 자신의 구현에서는 Controller에 의존하도록 했다고 비교했다. 작성자는 놓친 부분이라고 인정하고 인터페이스에 의존하는 편이 적절하다고 답했으나, 실제 변경 완료 여부는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
package framework;
public interface HandlerRegistry { Object find(String path); }
// app이 구현체를 공급하고 framework는 app 패키지를 import하지 않는다.
```

**적용 설명:** 재사용 모듈이 애플리케이션 구체 타입을 참조하지 않는 방향이다.
