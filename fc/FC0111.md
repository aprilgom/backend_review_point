# FC0111 · 동시 식별자 생성의 보장 범위

[소속 분야: 비동기·동시성](../05-concurrency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0110](FC0110.md) · [다음 FC: FC0105 →](FC0105.md)

## 검토 질문

- [ ] 원자적 증가 값이 보장하는 프로세스 범위와 재시작·다중 인스턴스·오버플로의 한계를 구분하는가?

**직접 작성한 예시**

```java
AtomicLong nextId = new AtomicLong();
long id = nextId.incrementAndGet();
```

**적용 설명:** 단일 프로세스 안에서 경쟁을 제어하는 예다. 재시작·다중 인스턴스·오버플로까지 해결하는 전역 ID 생성기는 아니다.

## 구체적인 검토 사례

- [ ] Long과 AtomicLong의 차이와 예약 ID 생성에 AtomicLong을 사용하는 이유를 설명하도록 질문했다. (설계 질문)
  - 조건: 작성자는 동시 접근 시 같은 값을 읽고 쓰는 문제를 방지하고 예약 ID의 중복을 막기 위해 사용했다고 설명했다. 질문 자체는 현재 구현의 결함을 확정한 것이 아니다.

- [ ] Long 대신 AtomicLong을 사용한 이유와 같은 고려를 Reservations에도 적용할 수 있는지 질문했다. (설계 질문)
  - 조건: 작성자는 여러 클라이언트가 접근하는 멀티스레드 상황에서 ID 중복을 방지하려는 목적이라고 설명했다. 또한 최초 코드의 AtomicLong 사용으로 Reservations에도 적용된다고 생각한다고 답했지만, 이에 대한 리뷰어의 확인이나 구체적인 적용 범위 설명은 없다.

- [ ] 일반 Long 대신 AtomicLong을 사용한 이유를 설명하고 관련 동작을 학습해 보도록 요청했다. (설계 질문)
  - 조건: 리뷰어는 작성자가 직접 선택한 코드가 아니더라도 알아보면 좋겠다고 덧붙였다. 작성자는 동시성 문제 대응을 선택 이유로 들고 CAS 루프 동작을 설명했으며, 리뷰어는 분석을 긍정했다. 해당 긍정을 설명 전체의 기술적 검증으로 간주하지 않는다.
