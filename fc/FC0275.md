# FC0275 · 리다이렉트 응답을 만드는 과정에서 /404.html 파일을 미리 읽어올 필요가 있는지 질문했다.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0296](FC0296.md) · [다음 FC: FC0283 →](FC0283.md)

- [ ] 리다이렉트 응답을 만드는 과정에서 /404.html 파일을 미리 읽어올 필요가 있는지 질문했다. (설계 질문)
  - 조건: 작성자는 리다이렉트 응답에 HTML 파일을 주어야 한다고 이해하여 읽는다고 답했으며, 코드와 최초 질문의 /404.html 대신 /401.html을 언급했다. 후속 참여자는 다른 스레드의 답변 링크만 제공했으므로, 그 설명이나 최종 합의는 확인할 수 없다.

- [ ] 2번 해결 방법을 적용해 writer로 트래픽이 몰리고 부하가 생길 경우 사용할 차선책이나 대안을 질문했다. (설계 질문)
  - 조건: writer 부하가 발생하는 상황을 전제로 한 질문이며 현재 부하가 있다는 결함 보고는 아니다. 2번 방법의 구체적인 내용과 이에 대한 답변은 이 단위에 없다. 이후 승인·머지 안내만으로 대안이 마련되었다고 판단하지 않는다.

- [ ] 응답 JSON에 Pretty Printer를 적용할 필요가 있는지, 메시지 본문 용량이 달라질 수 있다는 관점에서 질문했다. (설계 질문)
  - 조건: 용량 차이를 측정하거나 성능 결함으로 확정한 것은 아니다. 작성자는 응답을 확인할 때 들여쓰기가 더 읽기 좋다는 이유를 제시했고, 테스트는 응답을 객체로 다시 매핑해 검사하도록 바꿨다고 보고했다. Pretty Printer 제거에 합의한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
return HttpReply.redirect(302, "/not-found");
```

**적용 설명:** 리다이렉트에는 대상 파일 내용을 미리 읽을 필요가 없다. 원 요청 자체에 404를 내려야 하는 계약이라면 직접 404를 반환한다.
