# FC0032 · queryForObject와 query의 공통 구현을 추출하고, 반복되는 try-with-resources 구문까지 메서드로 묶어 중복을 줄이자고 제안했다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0031](FC0031.md) · [다음 FC: FC0033 →](FC0033.md)

- [ ] queryForObject와 query의 공통 구현을 추출하고, 반복되는 try-with-resources 구문까지 메서드로 묶어 중복을 줄이자고 제안했다. (개선 제안)
  - 조건: try-with-resources 추출은 추가로 고려할 수 있는 확장 제안이었다. 작성자는 공통 부분을 메서드로 추출해 중복을 제거했다고 보고했지만, 구체적인 추출 범위는 답변에 나타나지 않는다.

- [ ] queryForObject와 query에 겹치는 부분을 메서드로 추출해 중복을 줄이는 방안을 고려해보라고 제안했다. (개선 제안)
  - 조건: 메서드 추출을 고려하라는 제안이며, 구체적인 추출 범위나 실제 반영 결과는 제시되지 않았다.

- [ ] query와 queryForObject 사이의 중복을 줄이기 위해 공통 조회 메서드를 추출하거나 queryForObject에서 query를 호출하는 방식을 제안했다. (개선 제안)
  - 조건: 변경 범위가 크므로 반영은 자율이라고 명시했고, 함수형 인터페이스를 추가하는 첫 번째 방안은 과할 수 있다고 스스로 유보했다. 작성자는 첫 번째 방안에 불필요한 호출이 생긴다고 보고 두 번째 방안으로 리팩터링했다고 답했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
List<User> rows = query(sql, binder, this::mapUser);
if (rows.size() != 1) throw new UnexpectedRowCount(rows.size());
return rows.get(0);
```

**적용 설명:** 단건 조회를 공통 query에 위임하되 0건·복수 건 계약을 명시한다. query가 JDBC 자원을 안전하게 닫는다는 전제다.
