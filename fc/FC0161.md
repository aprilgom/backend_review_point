# FC0161 · HandlerAdaptors가 JsonView의 내부 약속인 "model" 키를 알고 값을 넣어야 하는 결합을 우려했다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0159](FC0159.md) · [다음 FC: FC0188 →](FC0188.md)

- [ ] HandlerAdaptors가 JsonView의 내부 약속인 "model" 키를 알고 값을 넣어야 하는 결합을 우려했다. (토론)
  - 조건: 초기에는 Map 항목을 직접 담아 키 조회를 없애는 방식을 제안했지만, 마지막에는 임의 반환값을 Map 안에 보관하는 방식의 유연성을 인정하면서도 특정 키를 어댑터가 알아야 한다는 점을 남은 관심사로 설명했다. 모든 키를 순회하는 JspView와 비교한 우려이며, 별도의 해결책이나 변경 결과는 확인되지 않는다.

- [ ] ModelAndView의 View를 JspView로 캐스팅하는 대신 View 인터페이스의 render를 그대로 사용하는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 캐스팅 이유를 질문하며 대안을 제시했다. 작성자는 기존 구현을 최대한 유지하려던 선택이었다고 설명하고 View의 render를 사용해도 되겠다고 답했지만, 실제 변경 여부는 확인되지 않는다.

- [ ] AdminViewController의 adminHome에 추가된 Model 의존성이 어떤 목적인지 확인한다. (설계 질문)
  - 조건: 코드에는 ch.qos.logback.core.model.Model을 가져와 매개변수로 추가한 내용이 보인다. 작성자는 실수라고 인정하고 수정하겠다고 답했지만, 실제 수정 내용이나 결과는 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record JsonPayload(Object value) {}
return new JsonPayload(reply);
```

**적용 설명:** 문자열 model 키를 호출자가 알아야 하는 숨은 계약 대신 명시적인 타입을 쓴다.
