# FC0161 · 문자열 기반 내부 계약의 결합

## 검토 질문

- [ ] 호출자가 다른 객체의 내부 키와 데이터 구조를 알아야 한다면 명시적인 타입·API로 바꿀 수 있는가?

**직접 작성한 예시**

```java
record JsonPayload(Object value) {}
return new JsonPayload(reply);
```

**적용 설명:** 문자열 model 키를 호출자가 알아야 하는 숨은 계약 대신 명시적인 타입을 쓴다.

## 구체적인 검토 사례

- [ ] **상황:** 다른 객체가 쓰는 내부 키를 호출자가 안다.
  - **판단 기준:** 타입이 있는 결과나 생성 API로 계약을 드러낸다.

- [ ] **상황:** 키를 바꾸면 먼 호출부까지 깨진다.
  - **판단 기준:** 변경 이유가 같은 코드가 한 경계에 있는지 본다.
