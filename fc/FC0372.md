# FC0372 · Adapter에서 ModelAndView를 얻은 뒤 렌더링은 별도로 수행하는 구조를 확인했다.

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0386](FC0386.md) · [다음 FC: FC0368 →](FC0368.md)

- [ ] Adapter에서 ModelAndView를 얻은 뒤 렌더링은 별도로 수행하는 구조를 확인했다. (관찰)
  - 조건: 구조에 대한 관찰이며, 변경 요구나 결함 보고 또는 이 구조가 보편적으로 더 낫다는 주장은 아니다.

- [ ] 뷰 렌더링은 View의 책임인데 ViewResolver도 이를 수행하여 역할이 중복된다고 지적했다. (문제 보고)
  - 조건: 리뷰 참여자가 설명한 책임 중복이며, 제안된 리팩터링의 적용 여부는 대화에서 확인되지 않는다.

- [ ] 현재 render()에서 View를 처리하는 방식과 스프링의 ViewResolver를 이용하는 방식의 차이를 질문했다. (설계 질문)
  - 조건: 학습을 위한 질문이며 ViewResolver 구현을 요구한 것은 아니다. 작성자는 스프링의 View 이름 해석 과정과 현재 ModelAndView에서 View를 꺼내 바로 render를 호출하는 방식을 대비해 설명했다. 설명의 기술적 정확성은 별도로 검증되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
ViewResult result = adapter.invoke(handler, request);
renderer.render(result, response);
```

**적용 설명:** 핸들러 실행과 뷰 출력은 다른 단계다. JSON 등 다른 결과를 지원할 때 경계가 유지되는지 확인한다.
