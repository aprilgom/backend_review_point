# FC0178 · 여러 HTTP 클라이언트 중 RestClient를 선택한 이유를 질문했다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0177](FC0177.md) · [다음 FC: FC0158 →](FC0158.md)

**혼합·경계:** RestClient 사례가 중심이지만 HTTP 클라이언트 선택 기준 자체는 일반 주제.

- [ ] 여러 HTTP 클라이언트 중 RestClient를 선택한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 RestTemplate을 레거시이자 사용성이 개선되기 전의 선택지로 보았고, WebClient는 단순 API 요청에 비해 가져올 코드가 많으며 비동기·논블로킹 중심이라 동기 결제를 구현하려는 목적에 RestClient가 적합하다고 설명했다. 이러한 비교는 작성자가 제시한 선택 근거이며 기술적 타당성이 별도로 확인된 것은 아니다.

- [ ] HTTP 클라이언트로 RestClient를 선택한 이유와 검토한 대안을 질문했다. (설계 질문)
  - 조건: 작성자는 처음에는 RestTemplate이 deprecated되었다고 오해해 RestClient를 선택했다고 설명하고, 이후 두 클라이언트의 특성과 다른 대안들을 조사했다고 답했다. 현재는 RestClient를 유지하고 Spring 제공 클라이언트 이해에 집중하겠다는 입장이다. 버전별 지원 상태와 기술적 비교는 작성자의 설명이며, 리뷰어가 특정 대안으로 교체하도록 요구한 것은 아니다.

- [ ] 여러 HTTP 클라이언트 선택지 중 RestClient를 선택한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 학습 테스트에서 사용한 RestTemplate과 RestClient를 비교했으며, 공식 문서의 마이그레이션 안내와 최신 라이브러리라는 판단을 선택 근거로 설명했다. 스프링의 선호나 다른 클라이언트 대비 기능 개선에 관한 설명은 작성자의 해석이며, 리뷰어가 확인한 결론은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
interface RemoteCatalog { Item fetch(ItemId id); }
RemoteCatalog catalog = new JdkCatalogClient(httpClient);
```

**적용 설명:** HTTP 클라이언트 선택을 어댑터 경계로 표현했다. 동기·비동기, 풀, 타임아웃, 테스트 지원 요구를 비교한다.
