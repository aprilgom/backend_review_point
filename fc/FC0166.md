# FC0166 · 저장 도우미의 생성 책임

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0164](FC0164.md) · [다음 FC: FC0162 →](FC0162.md)

## 검토 질문

- [ ] DAO가 내부 도우미를 직접 만들지 주입받을지 결정할 때 필수 의존성과 구성 책임이 명확한가?

**직접 작성한 예시**

```java
UserDao(SqlRunner runner) { this.runner = runner; }
// 생성 책임은 조립 코드로 이동
UserDao dao = new UserDao(new SqlRunner(dataSource));
```

**적용 설명:** SqlRunner는 자체 JDBC 도우미다. DAO의 의존성과 생성 책임을 분리하는 원리를 보여준다.

## 구체적인 검토 사례

- [ ] **상황:** DAO가 연결 설정을 받아 실행 도구를 직접 만든다.
  - **판단 기준:** 생성 책임을 조립 코드로 옮길 수 있다.

- [ ] **상황:** 동일 역할의 생성자가 여러 개 남는다.
  - **판단 기준:** 허용된 구성 경로와 차이를 명확히 한다.
