# FC0209 · 날짜 의미를 보존하는 타입

[소속 분야: 도메인 모델·값 표현](../11-domain-model.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0204](FC0204.md) · [다음 FC: FC0208 →](FC0208.md)

## 검토 질문

- [ ] 날짜를 임의 문자열 대신 검증·연산 가능한 타입으로 표현하고 시각·시간대와 구분하는가?

**직접 작성한 예시**

```java
LocalDate day = LocalDate.parse("2025-03-01");
LocalDate next = day.plusDays(1);
```

**적용 설명:** 날짜 의미와 연산을 타입으로 표현한다. 날짜에 임의의 시간대나 시각을 덧붙이지 않는다.

## 구체적인 검토 사례

- [ ] 날짜 정보를 문자열로 취급하는 대신 LocalDate로 표현하는 방식을 제안했다. (개선 제안)
  - 조건: 작성자는 도메인 로직에서 다루기 더 적절하다고 판단해 LocalDate로 수정했다고 보고했다. 실제 코드와 동작 결과는 대화에 제시되지 않았다.

- [ ] 예약 날짜와 시간을 LocalDate와 LocalTime으로 나눈 이유와 LocalDateTime으로 통합할 가능성을 논의했다. (토론)
  - 조건: 작성자는 요청 본문 구조에 맞춰 분리했다고 설명하고, 통합 시 요청과 도메인 간 매핑 및 의존성, DTO 도입 복잡도를 우려했다. 리뷰 참여자는 현재 복잡도에서 즉시 DTO를 도입하지 않아도 된다는 맥락이라면 기존 구조를 유지해도 된다고 답했다. 최초 질문을 잘못된 지적으로 철회한 것은 아니다.

- [ ] 날짜와 시간을 문자열 대신 LocalDate와 LocalTime으로 다루도록 개선해 보자는 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 실무에서도 날짜 타입을 자주 사용한다고 설명하며 개선을 권했다. 작성자는 스키마, 도메인 속성과 DAO 접근 코드를 변경했다고 보고했다. 스키마를 LocalDate·LocalTime으로 바꿨다는 표현은 작성자의 설명이며, 실제 DB 타입이나 구현 결과를 확인한 것은 아니다.
