# FC0220 · 선언형 검증의 실행 경로

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0217](FC0217.md) · [다음 FC: FC0221 →](FC0221.md)

## 검토 질문

- [ ] 검증 애너테이션뿐 아니라 실제 검증이 실행되는 경로·시점·오류 변환까지 확인했는가?

**직접 작성한 예시**

```java
record CreateLabel(@jakarta.validation.constraints.NotBlank String name) {}
var violations = validator.validate(new CreateLabel(""));
assertFalse(violations.isEmpty());
```

**적용 설명:** Spring 전용 API 대신 표준 Bean Validation 호출로 예시를 작성했다. 애너테이션만 붙이고 검증을 실행하지 않으면 동작하지 않는다.

## 구체적인 검토 사례

**혼합·경계:** @Validated 외에 표준 Bean Validation과 @Valid 사례가 섞임.

- [ ] 요청 유효성 검증 방법 중 하나인 @Validated를 추가로 학습해 보자고 제안했다. (개선 제안)
  - 조건: 기존 요청 검증은 잘되어 있다고 평가했으며, @Validated를 반드시 적용할 필요는 없다고 명시했다.

- [ ] 요청 본문 검증을 위해 @Valid를 알아보고 적용할 것을 제안한다. (개선 제안)
  - 조건: 예약 생성 컨트롤러의 @RequestBody 매개변수에 대한 제안이다. 작성자는 POST 요청들에 모두 @Valid를 적용했다고 보고했으며, 구체적인 검증 제약이나 동작 확인 결과는 제시되지 않았다.

- [ ] Java Bean Validation을 학습하여 요청 값 검증에 활용해 볼 것을 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 기능을 제대로 이해하지 못한 채 오용할 가능성을 우려했다. 작성자는 반환 동작을 정확히 학습한 뒤 다음 리팩터링에서 적용하겠다고 했고, 리뷰 참여자는 핵심 기능이 아닌 편의 기능이므로 우선순위를 미뤄도 된다고 명시했다. 제안 자체를 철회한 것은 아니다.
