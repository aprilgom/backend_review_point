# FC0315 · 프로토콜 이름의 상수 사용

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0308](FC0308.md) · [다음 FC: FC0309 →](FC0309.md)

## 검토 질문

- [ ] 헤더 이름 등 반복되는 프로토콜 식별자를 일관되게 표현하고 대소문자 등 실제 규약도 지키는가?

**직접 작성한 예시**

```java
private static final String AUTHORIZATION = "Authorization";
String header = request.header(AUTHORIZATION);
```

**적용 설명:** 일반 상수로 표현한 예다. HTTP 헤더 이름의 대소문자 비구분 조회는 request 구현에서 보장해야 한다.

## 구체적인 검토 사례

**혼합·경계:** HttpHeaders 활용 외에 문자열·상수 표현이라는 일반 가독성 주제.

- [ ] Authorization 헤더명을 문자열로 쓰는 대신 HttpHeaders.AUTHORIZATION 상수를 활용하자고 제안했다. (개선 제안)
  - 조건: 작성자는 상수를 사용하도록 수정했다고 보고했다. 함께 언급한 기본 상태 핸들러 추가는 작성자의 별도 변경 보고이며 이 제안의 범위에 포함하지 않는다.

- [ ] HTTP 헤더 이름을 문자열로 직접 쓰는 대신 HttpHeaders에 이미 정의된 상수를 사용하도록 제안한다. (개선 제안)
  - 조건: 제안 대상은 Authorization과 Content-Type 헤더 이름이다. 작성자는 기존 상수의 존재를 확인하며 감사했지만, 답변만으로 실제 반영 여부를 확정할 수는 없다.

- [ ] Authorization 헤더 이름을 문자열 리터럴로 쓰는 대신 HttpHeaders.AUTHORIZATION 상수를 활용하도록 제안했다. (개선 제안)
  - 조건: 헤더 이름 표현에 대한 제안이며 인증 처리의 보안 결함을 지적한 것은 아니다. 반영 여부는 제공되지 않았다.
