## 검토 질문

- [ ] 중복 생성 요청이 기존 데이터를 의도치 않게 덮어쓰지 않도록 생성과 갱신 계약을 구분했는가?

**직접 작성한 예시**

```sql
INSERT INTO account(login_name, password_hash)
VALUES (:login_name, :password_hash);
```

**적용 설명:** 가입은 기존 계정 갱신과 분리한다. login_name UNIQUE 위반을 처리하고 upsert로 기존 비밀번호를 덮어쓰지 않는다.

## 구체적인 검토 사례

- [ ] **상황:** 중복 생성이 기존 계정을 덮어쓴다.
  - **판단 기준:** 신규 삽입과 수정 API를 구분한다.

- [ ] **상황:** 편의상 모든 저장을 upsert로 처리한다.
  - **판단 기준:** 기존 정보 변경이 허용되는 작업인지 확인한다.
