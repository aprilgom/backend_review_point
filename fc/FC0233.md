# FC0233 · 신규 생성과 기존 데이터 갱신의 분리

## 검토 질문

- [ ] 중복 생성 요청이 기존 데이터를 의도치 않게 덮어쓰지 않도록 생성과 갱신 계약을 구분했는가?

**직접 작성한 예시**

```sql
INSERT INTO account(login_name, password_hash)
VALUES (:login_name, :password_hash);
```

**적용 설명:** 가입은 기존 계정 갱신과 분리한다. login_name UNIQUE 위반을 처리하고 upsert로 기존 비밀번호를 덮어쓰지 않는다.

## 구체적인 검토 사례

- [ ] 이미 존재하는 account로 재가입하면 기존 회원 정보가 덮어써지는 문제를 지적했다. (문제 보고)
  - 조건: 작성자는 예외 처리를 추가했다고 보고했다. 중복 검증의 구체적인 구현과 동작 결과는 이 대화만으로 확인되지 않는다.

- [ ] 회원가입에서 중복된 account로도 가입할 수 있다는 문제를 보고했다. (문제 보고)
  - 조건: 작성자 외 참여자의 문제 보고이며, 작성자 답변이나 수정 결과는 없다. 추출 과정에서 중복 가입 동작을 재현한 것은 아니다.

- [ ] 이미 존재하는 account로도 회원가입이 가능하며 기존 회원 정보가 덮어써질 수 있다고 지적했다. (문제 보고)
  - 조건: 중복 가입은 리뷰 참여자가 보고한 동작이고, 기존 정보 덮어쓰기는 가능성으로 제시했다. 이번 미션에서 중요하지 않아 넘어가도 된다고 했으며 지적 자체를 철회하지는 않았다. 작성자는 놓친 부분이라고 답했지만 수정 여부는 확인되지 않는다.
