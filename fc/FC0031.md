# FC0031 · 표준 enum 변환 기능의 활용

## 검토 질문

- [ ] 직접 작성한 문자열 변환을 표준 기능으로 단순화할 수 있으며 대소문자·잘못된 값의 처리가 명확한가?

**직접 작성한 예시**

```java
Method method;
try { method = Method.valueOf(raw.toUpperCase(Locale.ROOT)); }
catch (IllegalArgumentException invalid) { throw new BadMethod(raw); }
```

**적용 설명:** 자체 enum 변환 예시다. 대소문자 정규화 허용 여부와 지원하지 않는 메서드의 응답 정책을 정한다.

## 구체적인 검토 사례

- [ ] 문자열을 RequestMethod로 변환하는 별도 구현 대신 enum의 valueOf 메서드를 활용할 수 있는지 제안했다. (개선 제안)
  - 조건: 질문형 개선 제안이며, 기존 변환 메서드와 valueOf의 동작 및 예외 계약이 동일한지는 대화에서 확인되지 않았다.

- [ ] Method enum의 별도 문자열 value 대신 기본 제공되는 name()을 활용할 수 있다고 제안했다. (개선 제안)
  - 조건: 작성자는 피드백을 반영했다고 포괄적으로 보고했으나, 이 제안의 구체적인 적용 결과는 대화만으로 확인되지 않는다.

- [ ] 문자열로 RequestMethod를 찾는 기능을 직접 구현하기보다 enum에 기본 제공되는 valueOf()를 활용해보자고 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 valueOf()도 존재하지 않는 이름에 IllegalArgumentException을 던진다고 설명했다. 제시된 기존 구현은 equalsIgnoreCase를 사용하며, 대소문자 처리 차이는 대화에서 논의되지 않았다. 작성자는 제안을 반영했다고 보고했다.
