# FC0224 · 입력이 없어 readLine()이 null을 반환하는 경우를 고려해 요청 줄에 대한 null 방어를 추가하자고 제안했다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0228](FC0228.md) · [다음 FC: FC0232 →](FC0232.md)

- [ ] 입력이 없어 readLine()이 null을 반환하는 경우를 고려해 요청 줄에 대한 null 방어를 추가하자고 제안했다. (개선 제안)
  - 조건: requestLine.isBlank()를 호출하는 부분에 대한 제안이다. 작성자는 null 처리를 빠뜨렸다고 인정하고 수정했다고 보고했다.

- [ ] 가능하면 객체 생성 시점에 null을 검증해 유효하지 않은 값이 들어오지 않도록 하자. (개선 제안)
  - 조건: 봇 제안과 별개로 사람 참여자가 null 검증과 생성 시점 검증이라는 구체적인 관심사를 직접 설명했다. 작성자는 수정했다고 보고했다. 봇이 제시한 특정 검증 API나 모든 매개변수에 대한 적용 요구를 사람 참여자의 요구로 확대하지 않는다.

- [ ] 응답에 필수인 HttpStatus가 null일 수 있는 상태 자체를 없애는 것이 좋겠다고 제안했다. (개선 제안)
  - 조건: HttpResponse 초기화 시 상태 코드가 지정되지 않는 코드에 대한 제안이다. 구체적인 초기화 방식이나 실제 null로 인한 실패 사례는 제시하지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
String line = reader.readLine();
if (line == null) return; // 입력 종료: 요청을 만들지 않는다.
RequestLine request = parseRequestLine(line);
```

**적용 설명:** EOF와 빈 요청 줄은 다른 입력이다. 루프와 연결 종료 정책도 정의한다.
