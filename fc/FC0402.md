## 검토 질문

- [ ] JSON 전체 문자열 형식보다 검증 대상 필드와 값의 의미를 확인하는가?

**직접 작성한 예시**

```java
JsonNode body = mapper.readTree(response.body());
assertEquals("ready", body.path("state").asText());
```

**적용 설명:** JSON 공백·키 순서 대신 의미 있는 필드를 검증한다. 필드 부재와 기본값이 섞이지 않게 존재 검사도 고려한다.

## 구체적인 검토 사례

- [ ] JSON 응답 전체 문자열을 비교하기보다 jsonPath 등을 이용해 테스트 대상인 부분만 검증하자고 제안했다. (개선 제안)
  - 조건: 전체 문자열 비교는 응답 필드 추가나 순서 변경처럼 테스트 의도와 무관한 변경에도 실패할 수 있다는 우려다. 작성자는 제안에 감사했지만 실제 변경 여부는 이 답변만으로 확인되지 않는다.

- [ ] 메뉴 그룹 생성 테스트에서 assertDoesNotThrow만 사용하기보다 반환값을 비교하면 검증이 더 정확해질 것 같다. (개선 제안)
  - 조건: 예외 미발생 확인 대신 생성 결과를 비교하자는 제안이며, 구체적인 비교 항목이나 반영 결과는 제시되지 않았다.

- [ ] System.out.print나 로깅으로 결과를 확인하는 대신 assertThat으로 출력 결과를 검증하는 테스트 방식을 제안했다. (개선 제안)
  - 조건: 콘솔로 확인하는 방식이 찝찝하다면 다음 기회에 시도해 보라는 선택적 팁이다. 구체적인 설정은 외부 링크로 제시되었으며, 작성자는 다음 단계에서 도입하겠다고 답했을 뿐 실제 적용은 확인되지 않는다.
