# FC0172 · ReservationDateService가 ReservationRepository에 의존하는 방향이 자연스러운지 물었다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0160](FC0160.md) · [다음 FC: FC0177 →](FC0177.md)

- [ ] ReservationDateService가 ReservationRepository에 의존하는 방향이 자연스러운지 물었다. (설계 질문)
  - 조건: 의존 방향의 적절성을 검토하도록 한 질문이다. 대안이나 작성자의 설명이 없어 잘못된 의존이라고 확정할 수 없다.

- [ ] ReservationService가 ReservationTimeService에 의존하는 경우와 ReservationTimeRepository에 직접 의존하는 경우의 차이를 물었다. (설계 질문)
  - 조건: 작성자는 Repository 변경의 영향 범위를 줄이고 관련 로직을 ReservationTimeService 내부로 추상화하기 위해 서비스 의존을 선택했다고 설명했다. 직접 Repository에 의존하면 SRP를 위반한다는 설명은 작성자의 견해이며, 리뷰 참여자가 확정한 결론은 아니다.

- [ ] ReservationService가 ReservationTimeService에 의존하는 것이 꼭 필요한지 질문했다. (설계 질문)
  - 조건: 작성자는 하나의 서비스에 책임을 모으면 해당 의존성을 없앨 수 있지만, 책임 분리와 응집도를 높이는 편이 더 중요하므로 필요한 의존성이라고 답했다. 서비스 간 의존이 결함으로 확정되지는 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
interface SlotAvailability { boolean available(LocalDate day); }
CalendarService calendar = new CalendarService(slotAvailability);
```

**적용 설명:** 날짜 기능에 필요한 최소 조회 역할을 의존한다. 이름보다 실제 책임 방향을 기준으로 판단한다.
