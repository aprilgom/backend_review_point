# FC0310 · 긴 유스케이스의 의미 단위 분해

## 검토 질문

- [ ] 긴 메서드를 준비·검증·변경·저장 등 단계로 나누면서 실패와 트랜잭션 경계를 숨기지 않는가?

**직접 작성한 예시**

```java
Order order = prepareOrder(input);
reserveInventory(order);
return persistOrder(order);
```

**적용 설명:** 긴 유스케이스를 의미 있는 단계로 나눈다. 트랜잭션 경계와 단계 실패의 보상 처리를 숨기지 않는다.

## 구체적인 검토 사례

- [ ] **상황:** 긴 업무 메서드에서 흐름을 찾기 어렵다.
  - **판단 기준:** 단계를 의미 단위로 추출한다.

- [ ] **상황:** 추출된 메서드가 트랜잭션 경계를 감춘다.
  - **판단 기준:** 원자성과 실패 영향을 호출 흐름에 드러낸다.
