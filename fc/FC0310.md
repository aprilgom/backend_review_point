# FC0310 · registerOrder 메서드가 길어 보이므로 분리할 방법을 검토하자고 제안했다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0297](FC0297.md) · [다음 FC: FC0303 →](FC0303.md)

- [ ] registerOrder 메서드가 길어 보이므로 분리할 방법을 검토하자고 제안했다. (개선 제안)
  - 조건: 작성자는 대부분의 코드가 객체 생성이라 기능별 분리가 어렵다고 답하며 구체적인 분리 지점을 물었다. 리뷰 참여자는 후속으로 모델링과 검증 책임 이동을 대안으로 설명했으며, 기존 코드가 잘못되었다는 의미는 아니라고 완화했다.

- [ ] 코드 전반에서 메서드를 분리할 부분을 검토해 달라고 요청했다. (개선 제안)
  - 조건: 총평에서는 구체적인 메서드나 분리 기준을 지정하지 않았다. 작성자는 대부분 반영했다고 보고했으며, 후속 승인만으로 개별 메서드의 변경 결과를 확정할 수는 없다.

- [ ] 코드를 위에서 아래로 자연스럽게 읽을 수 있도록 메서드 배치를 조정하도록 제안했다. (개선 제안)
  - 조건: 가독성을 위한 배치 제안이며, 구체적인 메서드 순서는 제시하지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Order order = prepareOrder(input);
reserveInventory(order);
return persistOrder(order);
```

**적용 설명:** 긴 유스케이스를 의미 있는 단계로 나눈다. 트랜잭션 경계와 단계 실패의 보상 처리를 숨기지 않는다.
