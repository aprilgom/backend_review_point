# FC0299 · 기존 코드에 남아 있는 var 사용도 작성자가 정한 타입 표기 컨벤션에 맞춰 일관되게 정리하자는 제안이다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0313](FC0313.md) · [다음 FC: FC0308 →](FC0308.md)

- [ ] 기존 코드에 남아 있는 var 사용도 작성자가 정한 타입 표기 컨벤션에 맞춰 일관되게 정리하자는 제안이다. (개선 제안)
  - 조건: 명시적 타입만 사용하라는 요구는 아니다. 작성자는 생성자 호출처럼 타입을 직관적으로 추론할 수 있는 곳에는 var를 사용하는 기준을 정해 수정했다고 답했다. 리뷰 참여자도 해당 조건에서 var의 가독성 장점과 기준의 명확성을 긍정했다.

- [ ] 전체 코드에서 덜어낼 수 있는 부분을 찾아 코드를 줄일 방법을 함께 고민하자고 제안했다. (개선 제안)
  - 조건: 구체적으로 제거할 코드나 축약 방법은 이 대화에 명시되지 않았다. 이후 요구사항 충족을 이유로 머지한다는 안내가 있지만, 이 제안의 반영 여부를 확인해 주지는 않는다.

- [ ] 가로로 길어진 코드는 IDE의 hard wrap 기준을 정해 그 기준에 맞게 줄바꿈하도록 제안한다. (개선 제안)
  - 조건: 작성자는 중요한 비즈니스 로직이 화면 밖으로 벗어난 것이 아니어서 가독성 저하가 크지 않다고 판단했었다고 설명한 뒤, IntelliJ 설정을 했다고 보고했다. 특정 줄 길이 수치는 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
List<Station> stations = stationStore.findAll();
List<Line> lines = lineStore.findAll();
```

**적용 설명:** 명시적 타입을 택한 프로젝트의 일관된 예다. var 사용 여부 자체를 보편적 정답으로 취급하지 않는다.
