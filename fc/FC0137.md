# FC0137 · 명시적 매핑과 기본 규약의 선택

[소속 분야: 데이터 관계·영속성](../08-persistence.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0138](FC0138.md) · [다음 FC: FC0139 →](FC0139.md)

## 검토 질문

- [ ] 기본 매핑 규약과 실제 스키마가 일치하며 생략한 설정이 숨은 의존이나 혼란을 만들지 않는가?

**직접 작성한 예시**

```java
@Entity
class Tag {
    @Id Long id;
    String name;
}
```

**적용 설명:** Jakarta Persistence 기본 매핑을 사용하는 조각이다. 실제 테이블·컬럼 이름과 명명 전략이 일치할 때만 명시 설정을 생략한다.

## 구체적인 검토 사례

- [ ] 엔티티 매핑의 `@Table`과 `@Column`을 생략할 수 있다는 의견을 제시한다. (개선 제안)
  - 조건: 해당 코드에 대한 생략 가능성 언급이며, 모든 매핑에서 두 애너테이션을 제거해야 한다는 보편 규칙으로 해석하지 않는다. 구체적인 생략 조건은 설명하지 않았다.

- [ ] Answer 엔티티 매핑에 제시된 answer 테이블 DDL이 반영되었는지 확인하는 질문이다. (설계 질문)
  - 조건: DDL에는 식별자 생성 방식, contents의 clob 타입, 시간·삭제 여부 컬럼의 null 제약과 관계 식별자 컬럼 등이 포함되어 있다. 어느 항목이 누락되었다고 확정한 발언은 아니며, 작성자의 답변도 없다.

- [ ] `@Table`을 사용해 엔티티가 매핑되는 테이블 이름을 명시하도록 요청했다. (개선 제안)
  - 조건: 작성자는 기존 DB의 테이블 이름과 자동 생성 이름이 다를 수 있다는 점, 네이밍 전략 의존성을 줄이고 가독성을 높일 수 있다는 점을 이유로 수용했다. 이 이유들은 작성자의 설명이며 실제 적용 여부는 확인되지 않는다.
