# FC0137 · 명시적 매핑과 기본 규약의 선택

[소속 분야: 데이터 관계·영속성](../08-persistence.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0138](FC0138.md) · [다음 FC: FC0139 →](FC0139.md)

## 검토 질문

- [ ] 기본 매핑 규약과 실제 스키마가 일치하며 생략한 설정이 숨은 의존이나 혼란을 만들지 않는가?

**직접 작성한 예시**

```java
@Entity
class Tag {
    @Id Long id;
    String name;
}
```

**적용 설명:** Jakarta Persistence 기본 매핑을 사용하는 조각이다. 실제 테이블·컬럼 이름과 명명 전략이 일치할 때만 명시 설정을 생략한다.

## 구체적인 검토 사례

- [ ] **상황:** 기본값과 같은 매핑 설정을 모두 명시한다.
  - **판단 기준:** 설정이 실제 의미를 더하는지 본다.

- [ ] **상황:** 생략 후 명명 전략이 스키마와 다르다.
  - **판단 기준:** 실제 생성·검증 결과를 확인한다.
