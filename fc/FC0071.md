# FC0071 · 객체 생성 경로의 통제

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0065](FC0065.md) · [다음 FC: FC0072 →](FC0072.md)

## 검토 질문

- [ ] 팩토리나 파서에서 보장하는 규칙을 우회하는 불필요한 공개 생성자가 없는가?

**직접 작성한 예시**

```java
final class ResourcePath {
    private ResourcePath(String value) { this.value = value; }
    static ResourcePath parse(String raw) { return new ResourcePath(validate(raw)); }
}
```

**적용 설명:** 생성 경로가 parse 하나라면 private 생성자로 규칙 우회를 막는다. value 필드와 검증 구현은 생략했다.

## 구체적인 검토 사례

- [ ] 정적 팩토리 메서드가 있고 생성자를 별도로 사용하지 않는다면 RequestUri 생성자를 private으로 제한하는 방안을 제안했다. (개선 제안)
  - 조건: 정적 팩토리를 통해서만 생성한다는 사용 상황을 전제로 한 접근 범위 축소 제안이며, 이 단위에는 작성자의 답변이나 반영 결과가 없다.

- [ ] 정적 팩토리 메서드를 제공한다면 생성자를 통한 직접 생성을 제한하는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰어는 제한 대상을 '기본 생성자'라고 표현했으나 제공된 코드에는 매개변수가 있는 공개 생성자들이 보인다. 정확히 어떤 생성자를 지칭하는지는 추가 확인이 필요하다.

- [ ] 정적 팩토리 메서드로 객체를 생성하도록 의도했다면, 주 생성자를 private로 두어 생성 의도를 모르는 동료가 생성자를 직접 사용하지 않도록 하자는 제안이다. (개선 제안)
  - 조건: 사람 참여자가 생성자 공개로 인한 사용 경로 혼동을 직접 설명한 내용을 근거로 삼았다. 작성자는 동의하고 수정하겠다고 답했으나 실제 변경 여부는 확인되지 않는다.
