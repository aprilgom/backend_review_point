# FC0453 · 조회 실패 후 대체 경로의 트랜잭션

[소속 분야: 트랜잭션·자원 수명](../23-transaction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0450](FC0450.md) · [다음 FC: FC0451 →](FC0451.md)

## 검토 질문

- [ ] 실패한 조회의 트랜잭션 상태와 대체 조회 경계를 구분하고 부재·장애를 같은 방식으로 처리하지 않는가?

**직접 작성한 예시**

```java
try { return readerTransactions.read(() -> replica.find(id)); }
catch (ReplicaUnavailable failure) {
    return writerTransactions.read(() -> primary.find(id));
}
```

**적용 설명:** 가상 트랜잭션 경계를 분리한 개념 코드다. 실패한 트랜잭션 안에서 그대로 재조회해도 되는지, 단순 부재와 장애를 구분하는지 확인한다.

## 구체적인 검토 사례

- [ ] **상황:** 조회 실패 뒤 같은 트랜잭션에서 대체 조회한다.
  - **판단 기준:** 이미 실패한 상태인지 확인하고 경계를 분리한다.

- [ ] **상황:** 외부 호출과 여러 DB 쓰기의 순서를 바꾼다.
  - **판단 기준:** 원자성·중복·보상 처리를 비교하며 성공 확률을 추측하지 않는다.
