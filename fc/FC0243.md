# FC0243 · 요청 처리 중 잡힌 모든 예외를 Bad Request 응답으로 처리하는지 질문했다.

[소속 분야: 예외·실패 계약](../13-errors.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0242](FC0242.md) · [다음 FC: FC0246 →](FC0246.md)

- [ ] 요청 처리 중 잡힌 모든 예외를 Bad Request 응답으로 처리하는지 질문했다. (설계 질문)
  - 조건: 작성자는 그렇다고 답하며, 학습 범위가 GET·POST와 제한된 URL에 한정되어 주어진 요청 이외에는 잘못된 요청으로 간주했다고 설명했다. 이는 작성자의 범위 설정 근거이며, 리뷰 참여자가 오류 응답 정책의 결함을 확정하거나 변경을 요구한 것은 아니다.

- [ ] 개발자가 예상하지 못한 예외가 발생했을 때 어떻게 처리하고 응답하는지 질문했다. (설계 질문)
  - 조건: 작성자는 처음에는 날짜 파싱 예외 처리 범위에 관한 질문으로 이해해 전용 핸들러 삭제를 보고했다. 이후 상위 예외 발생 시 서버 오류로 응답하도록 수정했다고 보고했고, 리뷰 참여자는 후자의 해석이 질문 의도였다고 확인했다. 리뷰 참여자는 더 상위의 예외를 잡아 처리하는 방법을 언급했으나, 실제 구현 결과는 확인되지 않는다.

- [ ] MethodArgumentNotValidException 외의 예외도 처리할 필요가 없는지 질문했다. (설계 질문)
  - 조건: 처리해야 할 다른 예외의 종류나 응답 계약은 지정하지 않았다. 작성자는 몇 가지 처리를 추가했다고 답했지만, 이 답변만으로 처리 범위의 충분성이나 해결 결과가 확인되지는 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Reply reply = failure instanceof InvalidInput
    ? error(400, "INVALID_INPUT")
    : error(500, "INTERNAL_ERROR");
```

**적용 설명:** 모든 예외를 400으로 바꾸면 서버 결함을 클라이언트 탓으로 숨긴다. 실제 분류 기준은 도메인별로 확장한다.
