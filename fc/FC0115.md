# FC0115 · 기본 키 생성 전략의 선택

[소속 분야: 엔티티 동등성·식별](../06-identity.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0112](FC0112.md)

## 검토 질문

- [ ] ID 생성 시점·DB 의존성·배치 처리·분산 환경을 고려해 기본 키 생성 전략을 선택했는가?

**직접 작성한 예시**

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

**적용 설명:** Jakarta Persistence 매핑 조각이다. DB 삽입 시점의 ID 획득과 배치 처리 제약을 다른 생성 전략과 비교한다.

## 구체적인 검토 사례

- [ ] `GenerationType.IDENTITY`의 ID 부여 방식과 다른 기본 키 생성 전략 대신 이를 선택한 이유를 물었다. (설계 질문)
  - 조건: 작성자는 여러 전략의 동작을 설명하고, 전략을 명시해 동작을 드러내려 했으며 현재 애플리케이션에서는 IDENTITY의 대량 삽입 오버헤드 가능성이 낮다고 판단했다고 답했다. 답변에 포함된 각 전략의 기술적 설명이 검증된 것은 아니다.

- [ ] 사용 중인 IDENTITY 외에 어떤 기본 키 생성 전략이 있는지 확인하도록 질문했다. (설계 질문)
  - 조건: 작성자는 여러 생성 전략을 정리하고 현재는 단순성과 체감한 성능 문제의 부재를 이유로 IDENTITY가 적절하다고 판단했다. 리뷰 참여자는 정리를 칭찬했으며, 특정 전략으로 변경하라고 요구하거나 작성자의 각 기술적 주장을 별도로 검증하지는 않았다.

- [ ] @GeneratedValue의 역할과 기본 키 생성 전략으로 IDENTITY를 선택한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 기본 키 자동 생성과 DB에 ID 할당을 위임하는 방식을 설명하고, INSERT 이후 ID를 얻으므로 쓰기 지연 등 일부 최적화가 제한될 수 있다고 답했다. 다만 현재 미션에서는 그 단점이 실제 문제가 될 가능성이 낮고 설정이 간단하다고 판단해 선택했다고 밝혔다. 이러한 영향은 작성자의 설명이며 측정이나 재현 결과는 제시되지 않았다.
