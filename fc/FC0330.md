# FC0330 · SQL 문자열 변수 선언에서 var와 String을 혼용하는 기준이 있는지 물었다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0317](FC0317.md) · [다음 FC: FC0339 →](FC0339.md)

- [ ] SQL 문자열 변수 선언에서 var와 String을 혼용하는 기준이 있는지 물었다. (설계 질문)
  - 조건: 작성자는 기존 코드의 var 사용을 따라가다 의도치 않게 혼용했다고 설명했다. 테스트에서는 변경 유연성과 코드 길이 때문에 var를 종종 쓰지만 프로덕션 코드에서는 타입 명시를 선호한다고 답했으며, 실제 수정 여부는 이 대화에서 확인되지 않는다.

- [ ] SQL 문자열에 명시적으로 넣은 개행 문자 `\n`은 생략해도 된다고 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 로그 출력 시에는 개행이 장점이 될 수 있다고 덧붙였다. 작성자는 디버깅 로그를 위해 넣었으나 가독성을 고려해 삼중 따옴표 형식으로 바꾸었다고 보고했다.

- [ ] 헤더 문자열을 만들 때 keySet 순회와 개별 값 조회 대신 entrySet으로 키와 값을 함께 다루는 방식을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 반영하지 않아도 되는 선택적 제안임을 명시했으며, 형식 문자열을 사용하는 예시도 제시했다. 실제 반영 여부는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
String sql = "SELECT id FROM tag WHERE name = ?";
```

**적용 설명:** SQL 변수 타입 표기를 하나의 팀 규칙으로 맞춘 예다.
