# FC0024 · ContentType과 ContentTypeValue를 하나로 병합하는 방안을 제안했다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0028](FC0028.md) · [다음 FC: FC0022 →](FC0022.md)

- [ ] ContentType과 ContentTypeValue를 하나로 병합하는 방안을 제안했다. (개선 제안)
  - 조건: 병합해도 될 것 같다는 제안이며, 구체적인 병합 방식이나 반영 결과는 제시되지 않았다.

- [ ] 템플릿 처리 결과인 view를 문자열 대신 객체로 사용하는 방안을 제안한다. (개선 제안)
  - 조건: 객체의 구체적인 역할이나 인터페이스까지 명시한 제안은 아니다.

- [ ] Content-Type 중 text/plain만 별도로 관리하는 이유를 확인하고, 관리가 수월하도록 정리할 것을 제안한다. (개선 제안)
  - 조건: HttpResponse의 기본 Content-Type 문자열에 대한 질문과 관리 방식 개선 제안이다. 구체적인 통합 위치나 자료구조는 지정하지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record MediaType(String value) {
    static final MediaType JSON = new MediaType("application/json");
}
```

**적용 설명:** 두 래퍼가 같은 값만 표현한다면 하나로 줄일 수 있다. 파싱 결과와 원문처럼 역할이 다르면 병합하지 않는다.
