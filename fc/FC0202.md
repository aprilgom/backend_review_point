# FC0202 · 검증 가능한 요구사항 표현

[소속 분야: 문서·개발·학습 과정](../10-workflow.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0199](FC0199.md) · [다음 FC: FC0198 →](FC0198.md)

## 검토 질문

- [ ] 입력·성공 결과·실패 조건을 테스트할 수 있을 만큼 구체적으로 정의했는가?

**직접 작성한 예시**

```text
입력: 제목은 앞뒤 공백 제거 후 1~80자
성공: 생성된 식별자 반환
실패: 빈 제목이면 저장하지 않고 입력 오류 반환
```

**적용 설명:** 입력·결과·실패를 검증 가능한 요구로 적는 예시다.

## 구체적인 검토 사례

- [ ] **상황:** 요구사항이 기능 이름만 나열한다.
  - **판단 기준:** 입력·결과·실패 조건을 구체화한다.

- [ ] **상황:** 구현 방식까지 요구로 고정한다.
  - **판단 기준:** 업무 제약과 선택 가능한 설계를 구분한다.
