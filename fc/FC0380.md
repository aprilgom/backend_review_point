# FC0380 · 서비스 등에 남아 있는 로직을 도메인 객체에 더 위임할 수 있는지 검토하자는 제안이다.

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0377](FC0377.md) · [다음 FC: FC0358 →](FC0358.md)

- [ ] 서비스 등에 남아 있는 로직을 도메인 객체에 더 위임할 수 있는지 검토하자는 제안이다. (개선 제안)
  - 조건: 처음에는 도메인으로 로직을 더 옮길 여지가 있어 변경을 요청했다. 후속 리뷰에서도 같은 관심사를 유지했지만, JPA 전환 과정에서 개선될 것으로 기대하여 남은 작업은 3단계로 미루고 2단계는 머지하겠다고 했다. 머지가 해당 개선의 완료를 의미하지는 않는다.

- [ ] 서비스 레이어에 있는 로직을 가능한 한 도메인으로 옮겨 도메인 중심으로 검증할 수 있도록 하자고 제안한다. (개선 제안)
  - 조건: 서비스 레이어 테스트에 여러 기술이 섞여 이해하기 어렵다는 맥락의 제안이다. 작성자는 리팩터링 의사를 밝혔으나 구체적인 이동 범위나 구현 결과는 제시되지 않았다.

- [ ] 도메인 객체가 충분히 역할을 수행하는지, 서비스에 절차지향적인 로직이 몰려 있지는 않은지 검토하도록 제안한다. (개선 제안)
  - 조건: 다른 참여자의 코멘트를 언급하지만, 이 발언 자체에서도 도메인과 서비스 사이의 책임 배분을 구체적으로 검토하도록 요청한다. 특정 로직의 이동이나 설계 결함이 확정된 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Money total = order.total();
```

**적용 설명:** 서비스가 주문 항목을 꺼내 계산하기보다 관련 데이터를 가진 객체에 계산을 위임한다. 외부 API 호출까지 도메인에 넣지는 않는다.
