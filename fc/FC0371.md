# FC0371 · 서비스 코드에 데이터 액세스 관련 코드가 남아 있으므로 컴포넌트의 위치와 책임을 고려해 분리하도록 제안했다.

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0381](FC0381.md)

- [ ] 서비스 코드에 데이터 액세스 관련 코드가 남아 있으므로 컴포넌트의 위치와 책임을 고려해 분리하도록 제안했다. (개선 제안)
  - 조건: 중복 템플릿 처리 자체는 긍정적으로 평가했다. 현재 단계에서 즉시 수정하라는 요구가 아니라 다음 4단계를 진행하며 개선할 내용으로 명시했다.

- [ ] ReservationCreateValidator의 역할과 책임을 살펴보고 더 전문적인 기능을 제공하는 컴포넌트로 분리할 수 있는지 검토한다. (설계 질문)
  - 조건: 리뷰 참여자는 기능별 컴포넌트가 많아질 때 서비스가 어떤 영향을 받는지도 함께 질문했다. 구체적인 분리안이나 현재 설계의 결함을 확정한 발언은 아니다.

- [ ] 강하게 연관된 menu와 menuGroup을 함께 묶는 대신 모듈을 작은 단위로 나눈 기준을 질문했다. (설계 질문)
  - 조건: 참여자는 자신의 경우 두 도메인을 menu 모듈로 묶었다고 비교했다. 작성자는 애그리거트 단위로 나눴으며 MenuGroup이 메뉴 없이 생성되고 두 영역의 요구사항 변화도 다를 수 있어 분리했다고 설명했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
List<Task> tasks = taskStore.findDueBefore(deadline);
```

**적용 설명:** 서비스에서 ResultSet·SQL 조립을 직접 하지 않고 저장 계약에 맡긴다.
