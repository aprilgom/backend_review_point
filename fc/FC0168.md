# FC0168 · 표현 계층의 저장 구현 의존

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0187](FC0187.md) · [다음 FC: FC0159 →](FC0159.md)

## 검토 질문

- [ ] 컨트롤러가 특정 DB 구현에 직접 결합하지 않도록 필요한 계약과 조립 위치를 분리했는가?

**직접 작성한 예시**

```java
CartController(Carts carts) { this.carts = carts; }
CartController controller = new CartController(new SqlCarts(dataSource));
```

**적용 설명:** 컨트롤러가 특정 DB 제품 구현을 직접 지정하지 않도록 조립 위치로 옮긴다.

## 구체적인 검토 사례

- [ ] CartController에 H2CartDao 구현체가 직접 주입되고 있음을 지적한다. (관찰)
  - 조건: 리뷰어는 구현체 주입 사실을 짚었으며, 이 댓글에서는 구체적인 변경 방식이나 그 영향을 설명하지 않았다.

- [ ] OrderService에서 CartItemService를 거치지 않고 CartItemRepository를 직접 주입한 이유와 장점을 질문하고, 서비스 재사용을 통한 중복·공통 처리 가능성과 비교했다. (토론)
  - 조건: 작성자는 서비스가 하위 Repository들을 조합하고 컨트롤러가 서비스들을 조합한다는 팀 구조의 일관성을 근거로 들었으며, Service와 Repository를 함께 의존하는 구조에 대한 어색함과 변경 취약성에 대한 고민도 밝혔다. 리뷰어는 단일 정답을 강제하지 않고 합의한 팀 컨벤션과 일관성의 중요성을 인정했다.

- [ ] CartService에서도 H2CartDao 구현체 직접 주입이 반복되고 있음을 지적한다. (관찰)
  - 조건: 리뷰어는 구현체 주입의 반복을 짚었다. 이 단위에는 구체적인 수정 요청이나 작성자의 답변이 없다.
