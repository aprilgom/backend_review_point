# FC0375 · 도메인 변경과 영속화의 분담

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0361](FC0361.md) · [다음 FC: FC0378 →](FC0378.md)

## 검토 질문

- [ ] 도메인은 규칙과 상태 전이를 담당하고 서비스가 저장을 조율하는 구조가 적절한가?

**직접 작성한 예시**

```java
order.cancel(cancellationPolicy);
orders.save(order);
```

**적용 설명:** 도메인은 상태 전이, 서비스는 저장 흐름을 담당한다. 저장 실패 시 원자성은 트랜잭션 경계로 보장한다.

## 구체적인 검토 사례

- [ ] 도메인 객체가 DAO에 직접 접근해야 하는 이유를 검토하고, 도메인은 판단 결과를 반환하며 서비스가 DAO를 통해 저장하는 역할 분담을 고려하자. (토론)
  - 조건: 작성자가 Sections에서 종점 등록·중간 삽입을 판단한 뒤 DB 작업까지 수행하는 설계의 존재 여부를 물었다. 리뷰 참여자는 자신이 아는 범위에서는 그런 설계가 없다고 한정하고, 도메인의 판단과 서비스의 저장 실행을 나누는 대안을 제시했다. 도메인의 DAO 접근이 보편적으로 불가능하다고 확정한 발언으로 해석하지 않는다.

- [ ] 단순 DAO 호출만 하는 서비스 계층은 생략하고 컨트롤러에서 DAO를 호출해도 된다는 의견을 제시했다. (조건부 제안)
  - 조건: 간단한 CRUD로 서비스에 별도 로직이 없는 경우에 대한 의견이다. 같은 도메인의 서비스가 이미 존재하고 다른 로직도 담당한다면 기존 서비스를 통해 DAO를 호출하면 된다는 조건을 덧붙였다.

- [ ] DAO가 반드시 하나의 테이블만 다룰 필요는 없고 내부적으로 조인 쿼리를 사용할 수도 있다고 설명한다. (토론)
  - 조건: 리뷰 참여자는 반환값의 통일성이 유지되면 DAO 내부에서 조인을 사용할 수 있다고 설명했다. 특정 조인 구현으로 변경하라는 요구나 성능 검증 결과는 제시되지 않았다.
