# FC0200 · 작은 구현과 피드백의 반복

[소속 분야: 문서·개발·학습 과정](../10-workflow.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0201](FC0201.md) · [다음 FC: FC0199 →](FC0199.md)

## 검토 질문

- [ ] 하나의 정답을 미리 찾기보다 검증 가능한 작은 구현으로 가정을 확인하며 개선하는가?

**직접 작성한 예시**

```java
PricePolicy first = new FlatPricePolicy();
assertEquals(new Money(100), first.price(sample));
```

**적용 설명:** 작은 작동 구현을 검증하며 다음 요구로 확장한다. 추상적 정답을 찾느라 검증 가능한 피드백을 미루지 않는다.

## 구체적인 검토 사례

- [ ] 테스트와 운영 코드 작성에 하나의 정답을 찾기보다 다음 단계에서 우선 구현해 보며 자신의 방식을 찾아가도록 권했다. (개선 제안)
  - 조건: 작성자는 현재 미션에서 테스트 방식에 대한 고민보다 스프링 기능 사용에 먼저 집중했다고 답했다. 이는 학습 진행 방식에 관한 권유이지 테스트를 생략하라는 요구는 아니다.

- [ ] 테스트에 사용한 생소한 API나 객체를 어디서 학습하는지, 학습 방법이나 팁을 공유해 달라고 요청한다. (설계 질문)
  - 조건: 코드 결함이나 테스트 수정 요구가 아니라 API 및 객체 활용을 익히는 학습 과정에 대한 질문이다. 작성자의 답변은 없다.

- [ ] HTTP 요청·응답 구조를 파악하고 객체 설계에 참고하도록 HTTP 명세의 4·5·6절을 읽어볼 것을 권했다. (개선 제안)
  - 조건: 명세 학습을 권한 것이며, 링크의 세부 내용이나 구체적인 코드 결함을 이 대화에서 확인한 것은 아니다.
