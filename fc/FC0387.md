# FC0387 · 응답 정보의 최소 공개

[소속 분야: 인증·보안·비밀값](../20-security.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [다음 FC: FC0388 →](FC0388.md)

## 검토 질문

- [ ] 응답에 필요한 공개 필드만 포함하고 토큰·자격증명·내부 정보가 직렬화되지 않는가?

**직접 작성한 예시**

```java
record PublicUser(long id, String displayName) {}
return new PublicUser(user.id(), user.displayName());
```

**적용 설명:** 해시·토큰·내부 설정을 응답 타입에 포함하지 않는다. 전체 엔티티 자동 직렬화보다 공개 필드를 명시한다.

## 구체적인 검토 사례

- [ ] 응답에서 노출되면 안 되는 정보가 노출되며 실제 서비스에서는 심각한 보안 문제가 될 수 있다고 지적했다. (문제 보고)
  - 조건: 어떤 정보가 어떤 응답에서 노출되는지는 첨부 이미지에만 있어 확인할 수 없다. 작성자는 마지막 사진을 제외한 나머지를 수정했다고 포괄적으로 보고했으나, 보안 문제의 구체적인 수정 내용과 결과는 확인되지 않는다.

- [ ] 예외 메시지를 클라이언트에 그대로 전달하면 노출되어서는 안 되는 내부 정보가 드러날 수 있다고 지적한다. (위험 지적)
  - 조건: 리뷰어는 기타 예외의 원문 메시지가 전달되는 경우를 조건으로 설명했고, 클라이언트에게 불필요한 내용도 전달될 수 있다고 덧붙였다. 일반적인 오류 메시지로 바꾼 방향을 긍정적으로 평가했으며, 실제 정보 유출이 발생했다는 보고는 아니다.

- [ ] 인증할 수 없는 구체적인 이유를 응답으로 자세히 노출해도 보안상 괜찮은지 검토하도록 제안했다. (설계 질문)
  - 조건: 보안 취약점이 확정됐다는 지적은 아니다. 작성자는 메시지를 추상화하는 방향에 동의하고 관련 수정 커밋을 제시했으나, 링크의 변경 내용은 이 대화에서 확인되지 않는다.
