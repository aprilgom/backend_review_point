# FC0276 · 즐겨찾기 조회 과정에서 쿼리가 여러 번 발생하는 비효율을 줄여 최소한의 쿼리로 처리하도록 제안했다.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0266](FC0266.md) · [다음 FC: FC0267 →](FC0267.md)

- [ ] 즐겨찾기 조회 과정에서 쿼리가 여러 번 발생하는 비효율을 줄여 최소한의 쿼리로 처리하도록 제안했다. (개선 제안)
  - 조건: 참여자는 데이터베이스 조회 비용을 근거로 개선을 요청했다. 작성자는 수정했다고만 답했으며, 구체적인 변경 방식이나 쿼리 수·성능 측정 결과는 없다.

- [ ] 메뉴별 존재 여부를 반복 검증할 때 발생하는 쿼리 횟수를 줄일 수 있는지 검토를 제안했다. (개선 제안)
  - 조건: menus.forEach(this::validateMenuExist)에 대한 개선 제안이다. 실제 쿼리 횟수나 성능 측정값, 구체적인 대체 구현은 제시되지 않았다.

- [ ] 데이터 존재 여부를 확인하는 count 쿼리를 exists로 바꾸는 방안을 학습하고, 두 쿼리의 성능 차이를 비교해보자고 제안했다. (개선 제안)
  - 조건: 작성자는 exists가 하나의 행을 찾으면 연산을 종료할 수 있다고 설명하고 변경했다고 보고했다. 실제 성능 측정 결과는 제시되지 않았으므로 성능 차이의 크기는 확인되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```sql
SELECT f.id, p.name FROM favorite f
JOIN product p ON p.id = f.product_id WHERE f.account_id = :account;
```

**적용 설명:** 연관 데이터를 한 번에 조회하는 예다. 결과 중복·페이지 처리·인덱스 비용을 함께 확인한다.
