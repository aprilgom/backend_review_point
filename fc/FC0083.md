# FC0083 · 초기 데이터와 스키마 관리의 분리

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0078](FC0078.md) · [다음 FC: FC0075 →](FC0075.md)

## 검토 질문

- [ ] 개발용 데이터와 스키마 변경을 구분하고 실행 환경·순서·중복 적용 정책을 명시했는가?

**직접 작성한 예시**

```sql
-- 개발용 초기 데이터 파일의 내용 예
INSERT INTO category(id, name) VALUES (1, 'sample');
```

**적용 설명:** 개발 데이터와 스키마 변경을 분리한다. 이 파일을 실행할 초기화 절차를 명시하고 운영에서 자동 적용되지 않게 한다.

## 구체적인 검토 사례

**혼합·경계:** 초기 데이터·스키마 관리 원리와 Spring SQL 자동 초기화가 섞임.

- [ ] 개발용 초기 데이터를 애플리케이션 코드로 관리하는 대신 data.sql로 초기화하자고 제안한다. (개선 제안)
  - 조건: 작성자는 프론트 화면 테스트에 실제 로직을 거쳐 검증된 데이터를 쓰려는 의도였다고 설명했다. 성능 저하와 불필요한 코드 생성을 단점으로 든 것은 작성자의 판단이며, 원하는 시나리오의 data.sql로도 가능하다고 보고 초기화 방식을 변경하겠다고 답했다. 실제 변경 완료는 확인되지 않는다.

- [ ] 스키마 관리를 위한 SQL 파일을 별도로 만들지 않을 때의 단점을 검토하도록 요청했다. (설계 질문)
  - 조건: 작성자는 개발·운영 환경의 스키마 불일치와 버전 관리의 어려움을 답했다. 이는 작성자가 정리한 내용이며, 별도 SQL 파일을 실제로 추가했다는 보고는 없다.

- [ ] 스프링의 schema.sql 이후 자동 실행을 활용하도록 초기 데이터 파일을 data.sql로 바꾸는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 data.sql이 테스트에서도 기본 데이터를 매번 저장하기 때문에, 필요한 환경에서만 선택적으로 실행하려고 다른 이름을 사용했다고 설명했다. 자동 실행 순서는 리뷰어가 알고 있는 동작으로 제시했으며 변경 여부는 확인되지 않는다.
