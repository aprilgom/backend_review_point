# FC0139 · 관계 탐색의 필요성과 비용

## 검토 질문

- [ ] 연관 객체를 직접 보유함으로써 필요한 협력이 생기는지, 불필요한 로딩과 결합만 늘어나는지 확인했는가?

**직접 작성한 예시**

```java
class DiningTable {
    private TableGroup group;
    boolean isGrouped() { return group != null; }
}
```

**적용 설명:** 그룹 동작과 협력할 필요가 있는지 확인한다. 소속 식별만 필요하면 ID 참조도 대안이다.

## 구체적인 검토 사례

- [ ] OrderTable이 TableGroup을 객체 연관관계로 보유하도록 선택한 이유를 질문했다. (설계 질문)
  - 조건: 참여자는 다른 리뷰에서도 물었다고 언급했지만, 이 단위에서는 해당 선택에 대한 직접적인 답변이 없다.

- [ ] OrderTable이 tableGroupId로 간접 참조하더라도 TableGroup이 OrderTable을 보유하면 결국 양방향 참조가 되는 것 아닌지 질문했다. (설계 질문)
  - 조건: 작성자는 놓친 부분이라고 인정하고 다시 검토하겠다고 답했다. 실제 참조 구조의 변경 여부는 확인되지 않는다.

- [ ] 다른 참조는 간접 참조로 변경하면서 TableGroup의 OrderTable 직접 참조를 유지한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 처음에는 두 객체가 같은 생명주기로 함께 존재해야 한다고 생각했으나 그 생각을 정정하고 참조 구조를 변경했다고 답했다. 변경 구조의 상세 내용은 이미지에 있으므로 본문만으로 직접·간접 참조의 최종 배치를 확정하지 않는다.
