# FC0358 · 조회 모델과 변환 책임의 배치

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0380](FC0380.md) · [다음 FC: FC0373 →](FC0373.md)

## 검토 질문

- [ ] 필요한 값만 가져올지 모델 전체를 거칠지 결정하고 변환 책임·로딩 비용을 적절히 배치했는가?

**직접 작성한 예시**

```java
MemberRow row = members.load(id);
Member member = memberMapper.toDomain(row);
return member.cart();
```

**적용 설명:** 부분 문자열만 반환하는 대신 모델을 거치는 대안이다. 필요한 데이터보다 과도하게 로딩하는 비용도 비교한다.

## 구체적인 검토 사례

- [ ] **상황:** 필요한 값만 직접 읽어 모델을 우회한다.
  - **판단 기준:** 업무 규칙을 함께 적용해야 하는지 본다.

- [ ] **상황:** 값 하나를 얻으려고 큰 모델을 로딩한다.
  - **판단 기준:** 변환 이점과 조회 비용을 비교한다.
