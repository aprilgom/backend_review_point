# FC0225 · 누락값과 기본값의 구분

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0236](FC0236.md)

## 검토 질문

- [ ] 필수 입력의 누락이 0 같은 기본값으로 바뀌어 유효한 값처럼 처리되지 않는가?

**직접 작성한 예시**

```java
Integer age = input.age();
if (age == null) throw new MissingAge();
if (age < 0) throw new InvalidAge();
```

**적용 설명:** 누락과 실제 0을 구분한다. 0세 허용 여부는 업무 규칙으로 정한다.

## 구체적인 검토 사례

- [ ] 나이를 입력하지 않았을 때 0으로 처리되는 구조라면 버그가 발생할 가능성을 제기했다. (위험 지적)
  - 조건: 리뷰 참여자는 현재 바인딩 오류가 발생한다고 단정하지 않고, 미입력이 0이 되는 경우를 조건으로 제시했다. 작성자는 컨트롤러의 래퍼 타입과 @Valid로 입력을 검증하는 방식을 설명했으나, 해당 1차 검증은 아직 미적용 상태라고 명시했다.

- [ ] 체스방 생성 폼에서 아무 값도 입력하지 않아도 정상 제출되는 문제를 지적한다. (문제 보고)
  - 조건: 이름과 비밀번호 입력이 있는 폼에 대한 리뷰 참여자의 동작 보고다. 서버에서 실제로 방이 생성되는지나 어느 계층에서 검증해야 하는지는 설명되지 않았다.

- [ ] 클라이언트의 잘못된 입력에 대비해 입력값 검증을 꼼꼼히 하는 습관이 필요하다고 강조했다. (개선 제안)
  - 조건: 리뷰 참여자는 패킷 탈취·변조 같은 공격을 지금 깊게 공부하기에는 이르다고 범위를 제한하면서도 기본 입력 검증은 필요하다고 설명했다. 작성자는 이후 @Valid 적용과 잘못된 요청에 대한 테스트 추가를 보고했지만, 실제 검증 범위나 구현 결과는 확인되지 않는다.
