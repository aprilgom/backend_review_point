# FC0357 · 입력 추출과 저장 실행의 분리

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0366](FC0366.md) · [다음 FC: FC0382 →](FC0382.md)

## 검토 질문

- [ ] 요청을 해석하는 과정이 저장 등 부작용까지 일으키지 않도록 역할을 나누었는가?

**직접 작성한 예시**

```java
CreateUserCommand command = requestParser.parse(request);
User user = userService.create(command);
```

**적용 설명:** 입력 해석과 저장 실행을 분리한다. 파서는 DB 변경을 일으키지 않는다는 계약이다.

## 구체적인 검토 사례

- [ ] 요청에서 User를 추출하는 행위와 User를 저장하는 행위를 분리하자고 제안했다. (개선 제안)
  - 조건: CreateUserController의 saveUser 메서드에 대한 의견이며, 구체적인 분리 방식은 제시하지 않았다.

- [ ] 예약 삭제와 대기 예약 승격을 분리해 동작시키는 설계 대안을 검토해 보도록 제안했다. (개선 제안)
  - 조건: 승격 알림 발송 요구사항이 추가되는 상황을 예로 들어, 두 동작이 강결합되면 트랜잭션 범위와 승격 실패 시 삭제도 실패시킬지에 대한 판단이 필요하다고 설명했다. 현재 구현의 실패를 확정한 지적이나 특정 분리 방식의 강제는 아니다.

- [ ] 리다이렉트 처리를 JspView에서 분리하여 별도의 View로 보는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 리다이렉트가 담긴 모델이나 RequestDispatcher를 사용하지 않아 JSP와 직접적인 관련이 적다는 이유를 들었다. 별도 View로의 분리는 제안이며, 구현 결과는 제시되지 않았다.
