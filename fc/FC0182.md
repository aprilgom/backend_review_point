# FC0182 · 핸들러와 결과 모델의 결합

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0191](FC0191.md)

## 검토 질문

- [ ] 핸들러가 특정 뷰 결과를 알아야 하는지 지원할 출력 종류와 재사용 범위로 판단했는가?

**직접 작성한 예시**

```java
interface PageHandler { PageResult execute(Request request); }
```

**적용 설명:** 페이지 전용 핸들러라면 페이지 결과 의존이 자연스러울 수 있다. JSON 등 다른 반환 방식까지 강제하는지는 별도 검토한다.

## 구체적인 검토 사례

- [ ] ManualHandler가 ModelAndView를 알고 있어도 괜찮은 의존 관계인지 질문했다. (설계 질문)
  - 조건: 리뷰 참여자는 자신도 정답을 모르는 질문이라고 명시했다. 작성자는 기존 AnnotationHandler와 HandlerExecution의 관계를 따라 사용했다고 설명하고, 학습 후 관심사 분리 측면에서 좋지 않을 수 있다고 생각해 더 고민하겠다고 답했다. 의존 관계의 부적절성이나 해결 여부가 확정된 것은 아니다.
