# FC0361 · 컨트롤러와 유스케이스의 책임

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0374](FC0374.md) · [다음 FC: FC0375 →](FC0375.md)

## 검토 질문

- [ ] 컨트롤러의 입출력 처리와 업무 규칙·흐름 조율을 분리해 변경 이유가 섞이지 않게 했는가?

**직접 작성한 예시**

```java
CreateLineCommand command = toCommand(request);
LineReply reply = lineService.create(command);
return created(reply);
```

**적용 설명:** 컨트롤러는 입출력 변환을 담당하고 업무 흐름은 서비스로 위임한다. 단순 전달 계층만 늘리는지 확인한다.

## 구체적인 검토 사례

- [ ] LineStationController가 너무 많은 로직을 책임지고 있으므로 비즈니스 로직을 서비스에서 처리하도록 제안했다. (개선 제안)
  - 조건: PR 작성자는 다른 코멘트를 반영하면서 컨트롤러의 비즈니스 로직이 자연스럽게 줄었다고 설명했다. 이는 작성자의 보고이며, 해당 답변만으로 서비스로의 책임 이전이 완료되었다고 단정하지 않는다.

- [ ] 결제 승인 등 비즈니스 로직을 Controller에서 수행하는 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 처음에는 RestClient를 단순 HTTP 통신 도구로 보았으나 결제 승인을 비즈니스 로직으로 판단하여 서비스 계층으로 옮겼다고 보고했다. 실제 변경의 완결성이나 적절성이 이 답변만으로 확인된 것은 아니다.

- [ ] 결제와 예약을 진행하는 핵심 비즈니스 로직이 컨트롤러 안에 있는 것이 어색하다는 의견을 제시했다. (의견)
  - 조건: 제공된 코드의 결제 호출 및 예약 생성 흐름에 관한 계층 책임 지적이다. 앞선 언급을 참조하지만 이 댓글 자체에도 관심사가 명시되어 있으며, 구체적인 이동 대상이나 후속 변경 결과는 제시되지 않았다.
