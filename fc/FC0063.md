# FC0063 · 다중 요청 메서드 매핑

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0061](FC0061.md) · [다음 FC: FC0055 →](FC0055.md)

## 검토 질문

- [ ] 한 경로가 여러 요청 메서드를 지원할 때 등록·충돌·기본값 규칙을 명확히 처리하는가?

**직접 작성한 예시**

```java
for (Method method : mapping.methods()) {
    RouteKey key = new RouteKey(mapping.path(), method);
    if (routes.putIfAbsent(key, handler) != null) throw new DuplicateRoute(key);
}
```

**적용 설명:** 자체 라우터가 여러 메서드를 등록하는 예시다. 빈 메서드 목록의 의미와 충돌 처리를 명시한다.

## 구체적인 검토 사례

**혼합·경계:** 직접 구현하는 MVC 요청 매핑과 Spring 사용 사례를 구별해야 함.

- [ ] RequestMapping의 method가 배열인 만큼 여러 RequestMethod를 입력했을 때의 매핑 동작을 명확히 정해보자고 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 전체 매핑, 첫 항목만 매핑한다는 주석·Javadoc 명시, 예외 처리 등을 대안으로 제시했으며 전체 매핑만을 요구하지는 않았다. 작성자는 모든 입력을 매핑하도록 수정했다고 보고했고, 추가된 반복문은 가독성을 고려해 별도 메서드로 분리하지 않았다고 설명했다.

- [ ] `@RequestMapping`에 지정된 여러 HTTP 메서드를 모두 매핑할 수 있어야 한다고 제안했다. (개선 제안)
  - 조건: 제시된 코드에서는 method 배열의 첫 원소만 HandlerKey 생성에 사용하고 있었다. 리뷰 참여자는 다른 참여자의 의견을 언급하면서도 다중 메서드 매핑 필요성을 직접 제시했다. 작성자는 다중 지원이 가능하도록 수정했다고 보고했으나 구현 결과는 대화에서 검증되지 않았다.

- [ ] RequestMapping의 첫 번째 RequestMethod만 매핑하면 여러 HTTP 메서드를 지정한 경우 문제가 생길 수 있다고 지적했다. (위험 지적)
  - 조건: 리뷰 참여자는 현재 RequestMethod를 두 개 지정한 사례는 없으므로 의견으로 남긴다고 한정했다. 작성자는 모든 HTTP 메서드에 대해 HandlerExecution을 만들도록 변경했다고 보고했다.
