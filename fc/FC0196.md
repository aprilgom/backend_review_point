# FC0196 · 다음 리뷰 요청 때 변경 반영뿐 아니라 설계나 구현을 선택한 이유도 PR 설명에 적어 달라고 요청했다.

[소속 분야: 문서·개발·학습 과정](../10-workflow.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0195](FC0195.md) · [다음 FC: FC0197 →](FC0197.md)

- [ ] 다음 리뷰 요청 때 변경 반영뿐 아니라 설계나 구현을 선택한 이유도 PR 설명에 적어 달라고 요청했다. (개선 제안)
  - 조건: 이후 승인과 머지 안내는 선택 이유가 실제로 문서화되었는지를 확인하는 근거로 삼지 않았다.

- [ ] 기존 리뷰 코멘트를 확인하고 반영하거나 의견이 다르면 답변을 남겨 이해 여부와 판단을 공유해 달라고 요청했다. (개선 제안)
  - 조건: 참여자는 이전 단계 코멘트에 답변이 적어 확인 여부와 의도 전달 여부를 알기 어렵다고 설명했다. 모든 의견을 무조건 반영하라는 요구가 아니라 이견을 포함한 소통 요청이다.

- [ ] PR 변경 내용을 살펴보며 정확히 설명하기 어렵거나 대안을 확신하지 못하는 개념을 하나 이상 찾아 학습하고 정리하도록 과제를 제시했다. (학습 제약)
  - 조건: 작성자는 synchronized 대신 AtomicLong을 선택한 이유를 학습 주제로 삼아 정리했다. 답변에 포함된 동시성 설명은 작성자의 학습 결과이며, 리뷰어가 해당 기술 설명을 구체적으로 검증하거나 정정한 근거는 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```text
문제: 외부 전송 실패가 주문 저장까지 되돌리고 있었다.
선택: 저장 후 발송 작업을 별도 큐에 기록한다.
검증: 재시도 중 중복 발송 여부를 확인한다.
```

**적용 설명:** 변경·선택 이유·검증을 함께 쓰는 설명 템플릿이다. 실제 구현하지 않은 내용을 완료로 쓰지 않는다.
