# FC0341 · 실행과 예외 검증을 함께 하는 테스트 구간의 주석을 `when, then`으로 표시하자고 제안했다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0329](FC0329.md) · [다음 FC: FC0343 →](FC0343.md)

- [ ] 실행과 예외 검증을 함께 하는 테스트 구간의 주석을 `when, then`으로 표시하자고 제안했다. (개선 제안)
  - 조건: 테스트 동작의 결함이 아니라 해당 구간이 검증 단계이기도 하다는 점을 주석에 반영하자는 제안이다.

- [ ] 테스트의 given·when·then 구분에 주석과 개행을 함께 쓰기보다 한 가지 방식만 사용하도록 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 주석과 개행 중 특정 방식을 강제하지 않았다. 작성자는 개행으로 통일했다고 보고했다.

- [ ] 테스트의 given-when-then 단계를 주석으로 명시하는 편이 가독성이 좋다는 의견을 제시했다. (의견)
  - 조건: 작성자가 단계 주석을 명시하는 것이 나은지 먼저 질문했고, 리뷰어가 가독성 측면에서 긍정했다. 작성자는 주석을 남겨두겠다고 답했으며, 필수적인 테스트 작성 규칙으로 요구한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
// when, then
assertThrows(InvalidPrice.class, () -> new Price(-1));
```

**적용 설명:** 예외 단언은 실행과 검증을 함께 수행한다. 불필요한 구간 주석을 강제할 필요는 없다.
