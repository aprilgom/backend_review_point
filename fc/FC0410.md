# FC0410 · 예약 대기를 예약으로 전환할 때 잘못된 객체의 정보를 사용하는 문제가 맞다면 이를 검증하는 테스트를 추가하자고 제안했다.

[소속 분야: 테스트 대상·검증](../21-test-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0407](FC0407.md) · [다음 FC: FC0406 →](FC0406.md)

- [ ] 예약 대기를 예약으로 전환할 때 잘못된 객체의 정보를 사용하는 문제가 맞다면 이를 검증하는 테스트를 추가하자고 제안했다. (조건부 제안)
  - 조건: 리뷰어의 테스트 제안은 정보 사용 오류가 실제로 존재한다는 조건이었다. 작성자는 정보 사용 오류를 인정하고 로직 수정을 보고했지만, 해당 테스트를 추가했다고 명시하지는 않았다.

- [ ] 예약 취소뿐 아니라 예약 정보 변경 시에도 대기가 예약으로 승격되는지 검증하는 테스트를 추가하도록 제안한다. (개선 제안)
  - 조건: 작성자는 예약 변경으로 기존 일정이 비면 첫 대기자가 승격되고 남은 대기 순번이 1번으로 재정렬되는 테스트를 추가했다고 보고했다. 이는 작성자의 변경 보고이며 실제 테스트 결과를 확인한 근거는 없다.

- [ ] 예약을 생성한 뒤 다시 조회하여 저장된 예약이 포함되는지 확인하는 정상 흐름 테스트를 추가하도록 요청했다. (개선 제안)
  - 조건: ReservationServiceTest에 대한 요청이며, 테스트 추가 결과는 제공되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Booking promoted = waiting.promote(waitingId);
assertEquals(waitingCustomerId, promoted.customerId());
assertEquals(waitingSlotId, promoted.slotId());
```

**적용 설명:** 승격 대상과 다른 객체의 필드가 섞이지 않는지 검증한다. 서로 다른 값의 두 후보를 준비하면 오류를 드러내기 좋다.
