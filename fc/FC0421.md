# FC0421 · 해당 테스트 설정을 인수 테스트에서만 사용하는 이유를 질문했다.

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0424](FC0424.md) · [다음 FC: FC0423 →](FC0423.md)

- [ ] 해당 테스트 설정을 인수 테스트에서만 사용하는 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 서비스 테스트, 인수 테스트, 레포지토리 테스트 순으로 실행할 때 인수 테스트 이후 새 컨텍스트가 생성되지 않아 예외가 발생했다고 설명했다. 이는 작성자가 보고한 설정 배경이며, 예외 원인이나 해결 방법이 검증된 것은 아니다.

- [ ] 서비스 테스트마다 관련 테스트 설정을 따로 구성한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 서비스별 구현체를 독립적으로 구성하고 MySQL·H2·Fake 저장소를 교체해 테스트하는 구조를 시도하려 했으며, 해당 테스트에만 적용되는 설정이라 내부 클래스로 두었다고 설명했다. 공통 TestConfig를 분리해 @Import하는 방식도 기능적으로 같을 것이라는 의견은 작성자가 제시한 것이며, 리뷰어의 공통화 요구나 실제 변경으로 볼 수 없다.

- [ ] 테스트를 위해서만 사용하고 운영 코드에서는 사용하지 않는 빌더를 추가하는 것이 적절한지 질문했다. (설계 질문)
  - 조건: 테스트 전용 빌더 추가에 대한 설계 판단을 묻는 질문이지 보편적인 금지 규칙은 아니다. 작성자는 다른 코드를 참고하다 생긴 실수라며 제거했다고 답했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record TestConfig(int httpPort, DataSource dataSource) {}
TestConfig acceptance = new TestConfig(0, isolatedTestDataSource);
```

**적용 설명:** HTTP 포트와 DB가 필요한 테스트에만 해당 설정을 제공한다. 순수 단위 테스트는 서버 설정을 요구하지 않게 한다.
