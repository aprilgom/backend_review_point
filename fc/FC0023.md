# FC0023 · 조건 기반 규칙에 맞는 자료구조

## 검토 질문

- [ ] 조건을 순서대로 평가하는 처리에 키 조회용 자료구조를 쓰고 있지 않으며, 우선순위와 선택 규칙이 드러나는가?

**직접 작성한 예시**

```java
record ViewRule(Predicate<Result> matches, Function<Result, View> build) {}
View view = rules.stream().filter(r -> r.matches().test(result))
    .findFirst().orElseThrow().build().apply(result);
```

**적용 설명:** 조건을 순회한다면 Map보다 순서 있는 규칙 목록이 의도를 잘 드러낼 수 있다. 첫 일치 규칙 우선이라는 계약이다.

## 구체적인 검토 사례

- [ ] Predicate를 키로 둔 Map이 Map의 탐색 특성을 활용하는지 의문을 제기하고, 조건 판정과 View 생성을 함께 담은 클래스의 리스트를 대안으로 제안했다. (개선 제안)
  - 조건: 리뷰어는 Predicate 키 사용을 부정적으로 평가하면서 실제로 Map 특유의 탐색을 하고 있거나 할 수 있는지 물었다. 작성자는 분기문을 피하려던 의도였고 자신도 확신이 없었다고 설명했다. 대안의 구현 여부는 명시되지 않았다.

- [ ] JspView의 리다이렉트 처리를 RedirectView로 분리하는 대안을 소개하면서, 현시점에는 주석으로 의도를 드러내는 방식을 제안한다. (토론)
  - 조건: 참여자는 자신의 구현에서는 View 인터페이스에 맞춰 RedirectView를 분리했고 역할을 더 명확히 보여줄 수 있다고 설명했다. 다만 추상화는 결과론적인 선택이라며 현재 코드에는 우선 주석을 사용하는 편을 제안하고 의견을 물었다. 분리를 필수 변경으로 요구하거나 제안을 철회한 것은 아니다.

- [ ] ModelAndView 생성의 중복을 줄이고, 조건문에서는 뷰 경로만 결정하도록 구성할 것을 제안했다. (개선 제안)
  - 조건: LoginController의 반복되는 객체 생성에 대한 제안이며, 실제 변경 여부는 대화에서 확인되지 않는다.
