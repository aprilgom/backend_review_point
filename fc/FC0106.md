# FC0106 · 스레드 풀 크기의 측정 근거

[소속 분야: 비동기·동시성](../05-concurrency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0101](FC0101.md) · [다음 FC: FC0099 →](FC0099.md)

## 검토 질문

- [ ] CPU·I/O·DB 풀·지연 목표를 함께 고려해 실행 수와 대기열 크기를 측정으로 조정하는가?

**직접 작성한 예시**

```java
int workers = config.workerCount();
int queueCapacity = config.queueCapacity();
metrics.recordQueueDepth(executor.getQueue().size());
```

**적용 설명:** 동시 작업 수는 CPU·I/O 대기·DB 풀·지연 목표와 함께 조정한다. 정답 숫자를 외우는 대신 대기열·거절률을 관측한다.

## 구체적인 검토 사례

- [ ] 스레드 풀의 최대 스레드 수를 보통 어느 정도로 설정하는지 학습해 보도록 제안했다. (개선 제안)
  - 조건: 작성자는 Tomcat 공식 문서의 기본 maxThreads가 200이라고 알게 되었다고 보고하고, 스레드 수가 너무 적거나 많을 때의 영향을 정리하며 서버 자원과 트래픽 특성에 맞춰야 한다고 설명했다. 이 설명은 작성자의 학습 답변이며 외부 링크와 이미지는 추가 검증하지 않았다. 리뷰어가 현재 값 250을 결함으로 판단하거나 200으로 변경하라고 요구한 것은 아니다.

- [ ] 스레드 풀의 최소 스레드 수와 최대 스레드 수를 동일하게 설정한 이유를 질문한다. (설계 질문)
  - 조건: 작성자는 실제 서비스라면 이용자가 가장 적은 시간대에도 유지해야 할 스레드 수를 기준으로 삼겠지만, 이 프로젝트에서는 명확한 기준을 떠올리지 못했다고 답했다. 최소 수를 최대 수보다 작게 두는 것이 좋았겠다는 의견도 밝혔으나 실제 설정 변경은 확인되지 않는다.

- [ ] 스레드 풀 생성자 사용에 별도 이유가 있다면 coreThreads, maximumThreads, keepAlive, workQueueSize의 설정 기준을 설명해 달라고 요청했다. (설계 질문)
  - 조건: 작성자는 모든 스레드가 동작 중일 때 대기하는 OS 큐 크기를 지정하려다가 workQueueSize를 혼동했으며, 의도한 설정은 createServerSocket() 수행 시 이루어진다고 설명하고 수정했다고 보고했다. 나머지 인자의 설정 기준과 실제 수정 결과는 대화에서 확인되지 않는다.
