## 검토 질문

- [ ] 테스트 라이브러리·실행 엔진·빌드 설정이 일치하고 서로 다른 세대의 병행 이유가 명확한가?

**직접 작성한 예시**

```kotlin
tasks.test { useJUnitPlatform() }
dependencies { testImplementation(libs.junit.jupiter) }
```

**적용 설명:** JUnit 5를 사용하는 프로젝트의 구성 예시다. JUnit 4를 병행한다면 레거시 테스트 실행 엔진과 이행 이유를 명시한다.

## 구체적인 검토 사례

- [ ] JUnit 4.13.1 테스트 의존성을 추가한 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 @Test를 import하는 과정에서 버튼을 잘못 눌러 추가한 의존성이며 제거했다고 보고했다. 실제 제거 여부는 이 대화만으로 검증되지 않는다.

- [ ] 테스트용 MySQL 이미지 버전을 변경한 이유와 버전 간 차이를 질문했다. (설계 질문)
  - 조건: 리뷰어는 변경 버전을 8.4.20으로 적었지만 코드와 작성자 답변에는 8.4.2로 표시되어 있다. 작성자는 로컬에 이미 설치된 이미지를 사용해 추가 다운로드를 피하려는 목적이었다고 설명하고, 지원 중단 기능 삭제와 특정 명령 최적화 등의 차이가 있다고 답했다. 해당 차이는 작성자의 설명으로만 확인된다.

- [ ] Java 버전을 11로 변경한 이유를 물었다. (설계 질문)
  - 조건: 작성자는 특별한 이유보다는 Java 11에 익숙해서 선택했으며, 실제 현업 상황이었다면 기존 버전을 유지했을 것이라고 답했다. 버전 변경이 결함이라는 지적은 아니다.
