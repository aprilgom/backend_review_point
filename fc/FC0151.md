# FC0151 · 저장 어댑터의 추가 책임

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0155](FC0155.md) · [다음 FC: FC0153 →](FC0153.md)

## 검토 질문

- [ ] 저장 라이브러리를 감싼 구현이 모델 변환·정책·기술 격리 등 분명한 책임을 가지는가?

**직접 작성한 예시**

```java
final class PersistentCustomers implements Customers {
    private final EntityStore entities;
    Customer get(long id) { return toDomain(entities.get(id)); }
}
```

**적용 설명:** 저장 모델 변환을 담당하는 어댑터라면 감싸기의 의미가 있다. 단순 전달만 하는 계층은 비용과 이점을 비교한다.

## 구체적인 검토 사례

- [ ] **상황:** 저장 래퍼가 모든 호출을 그대로 전달한다.
  - **판단 기준:** 기술 격리 외에 필요한 책임을 확인한다.

- [ ] **상황:** 저장 행을 도메인으로 변환해야 한다.
  - **판단 기준:** 변환 경계라면 별도 어댑터가 유효하다.
