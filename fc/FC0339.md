# FC0339 · 뷰 이름과 리졸버 규약

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0330](FC0330.md) · [다음 FC: FC0333 →](FC0333.md)

## 검토 질문

- [ ] 템플릿 접미사·경로를 코드와 리졸버가 중복 적용하지 않으며 실제 탐색 규칙과 일치하는가?

**직접 작성한 예시**

```java
return new TemplateView("tasks/list"); // resolver가 .html 접미사를 붙이는 계약
```

**적용 설명:** 리졸버가 실제로 접미사를 붙일 때만 확장자를 생략한다. 설정과 템플릿 탐색 테스트를 맞춘다.

## 구체적인 검토 사례

- [ ] 템플릿 이름의 html 확장자 표기에 대해, 템플릿 리졸버가 접미사를 붙이므로 명시하지 않아도 된다는 의견을 제시했다. (토론)
  - 조건: 질문은 작성자가 먼저 제기했다. 답변자는 타임리프 사용 경험이 적어 모범 관행은 잘 모르겠다는 전제를 밝혔으며, 확장자 생략을 필수 규칙으로 요구하지 않았다. 작성자는 이후 View Resolver의 접미사 처리를 이유로 확장자를 생략했다고 보고했다.

- [ ] 확장자 타입은 HTTP에 종속적인 개념이 아니라는 관점에서 HttpExtensionType 이름의 Http 접두사를 제거하는 것을 제안한다. (개선 제안)
  - 조건: HTTP 종속성이 없다고 본 참여자의 명명 제안이며, 실제 변경 여부는 제시되지 않았다.

- [ ] DB 명명 규칙은 팀과 합의하되 불필요한 접두사·접미사와 해석이 모호한 약어를 피하는 방향을 논의한다. (토론)
  - 조건: 리뷰 참여자는 개인적으로 접두사·접미사·약어를 거의 쓰지 않지만 인덱스의 idx 등은 예외로 사용한다고 설명했다. 개인 취향보다 팀·페어의 컨벤션 합의를 우선하며 특정 규칙을 강제하지 않았다.
