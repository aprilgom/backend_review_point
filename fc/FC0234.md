# FC0234 · reservation 테이블의 time_id와 theme_id에도 NOT NULL 제약이 필요한지 질문했다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0227](FC0227.md) · [다음 FC: FC0233 →](FC0233.md)

- [ ] reservation 테이블의 time_id와 theme_id에도 NOT NULL 제약이 필요한지 질문했다. (설계 질문)
  - 조건: 해당 두 컬럼에 NOT NULL이 없는 스키마를 대상으로 한 질문이다. null 허용이 실제 요구사항에 어긋나는지에 대한 답변이나 변경 결과는 없다.

- [ ] reservation 테이블의 theme_id와 time_id에도 NOT NULL 제약이 필요한지 물었다. (설계 질문)
  - 조건: 작성자는 현재 구조에서 테마·매장·시간·날짜 조합이 의미 있는 슬롯을 이루므로 필수 데이터로 두는 것이 적절하다고 판단했고, 수정했다고 보고했다. 리뷰 참여자의 질문을 곧바로 확정된 결함으로 해석하지 않았다.

- [ ] 예약 테이블의 time_id와 theme_id에 NOT NULL 제약이 필요한 것 아닌지 확인하는 질문이다. (설계 질문)
  - 조건: 리뷰어가 가리킨 코드는 reservation의 두 컬럼이다. 작성자는 예약과 예약 대기 모두 해당 값이 없으면 등록이 성립하지 않는다고 판단해 두 테이블에 제약을 추가했다고 보고했다. 예약 대기 테이블까지의 변경 범위는 작성자의 설명이다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```sql
CREATE TABLE booking (
  id BIGINT PRIMARY KEY,
  slot_id BIGINT NOT NULL REFERENCES slot(id),
  theme_id BIGINT NOT NULL REFERENCES theme(id)
);
```

**적용 설명:** 항상 필요한 연관관계를 NOT NULL과 외래 키로 표현한다.
