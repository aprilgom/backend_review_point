# FC0230 · 장바구니 수량 변경 요청의 quantity에 음수도 입력될 수 있다는 지적이다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0235](FC0235.md) · [다음 FC: FC0231 →](FC0231.md)

- [ ] 장바구니 수량 변경 요청의 quantity에 음수도 입력될 수 있다는 지적이다. (문제 보고)
  - 조건: 리뷰 대상 코드에는 quantity의 NotNull 검증이 제시되어 있다. 리뷰 참여자는 음수 허용을 지적했으며, 구체적인 허용 범위나 후속 수정은 대화에 제시되지 않았다.

- [ ] 장바구니 수량 변경 요청의 수량이 음수일 때 어떻게 처리되는지 질문했다. (설계 질문)
  - 조건: 작성자는 요청 DTO에 양수만 받도록 검증을 추가했다고 답했다. 실제 검증 코드나 기존 수량 0 처리와의 관계는 이 대화에서 확인되지 않으며, 양수만 허용하라는 요구를 리뷰 참여자가 직접 제시한 것은 아니다.

- [ ] 이미 장바구니에 들어 있는 상품을 다시 추가할 수 없는 정책인지 확인한다. (설계 질문)
  - 조건: 중복 추가 금지를 결함으로 확정한 발언은 아니다. 작성자는 팀 논의로 재추가 시 예외를 발생시키고 수량은 update로 변경하도록 정했다고 설명했다. 중복 행의 개수 조회와 삭제 대상 선택의 모호함은 작성자가 제시한 설계 이유이며, 리뷰 참여자의 요구나 검증된 필연적 결과로 보지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
if (input.quantity() <= 0) throw new InvalidQuantity();
cart.changeQuantity(productId, input.quantity());
```

**적용 설명:** 이 예시는 0도 거절한다. 0을 삭제로 취급하는 계약이라면 삭제 경로를 명시한다.
