# FC0320 · 주문 조회 테스트의 주문 번호에 매직 넘버를 피하면 의미가 더 명시적으로 드러날 것이라고 제안했다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0337](FC0337.md) · [다음 FC: FC0328 →](FC0328.md)

- [ ] 주문 조회 테스트의 주문 번호에 매직 넘버를 피하면 의미가 더 명시적으로 드러날 것이라고 제안했다. (개선 제안)
  - 조건: 원문 맥락 확인

- [ ] 요청 라인을 분리한 결과의 길이와 비교하는 숫자 3이 무엇을 의미하는지 질문했다. (설계 질문)
  - 조건: 작성자는 전체 코드를 다시 검사하여 상수화했다고 보고했다. 참여자의 질문에 숫자의 의미를 직접 설명한 답변은 없으며, 비교 조건 자체가 잘못되었다는 지적은 아니다.

- [ ] 거리 검증 조건의 숫자 0을 매직 넘버로 볼 수 있지 않은지 질문했다. (설계 질문)
  - 조건: 작성자는 0의 의미를 유추하기 어렵지는 않다고 반론하면서 조건식을 이름 있는 메서드로 분리하는 데에는 동의했다. 이후 Distance 값 객체로 분리했으며, 일반적으로 0을 금지하되 하행 종점에서는 emptyDistance()를 통해 예외적으로 허용하도록 했다고 보고했다. 이는 작성자의 설계 설명이며 리뷰 참여자의 추가 검증이나 동의는 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
long savedOrderId = orders.save(sampleOrder()).id();
assertEquals(savedOrderId, orders.get(savedOrderId).id());
```

**적용 설명:** 하드코딩 숫자 대신 준비 단계에서 생성된 식별자를 사용한다.
