# FC0088 · 향후 배포를 고려해 CSS 주소를 localhost가 포함된 절대경로 대신 상대경로로 바꾸는 것을 제안한다.

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0087](FC0087.md) · [다음 FC: FC0091 →](FC0091.md)

- [ ] 향후 배포를 고려해 CSS 주소를 localhost가 포함된 절대경로 대신 상대경로로 바꾸는 것을 제안한다. (개선 제안)
  - 조건: 작성자는 수정했다고 답했으나 실제 변경 내용과 배포 환경에서의 동작은 확인되지 않는다.

- [ ] localhost와 포트를 하드코딩한 요청 주소 대신 현재 서버 주소나 경로만 사용하는 방안을 검토하고, cart.html의 주소 표기도 선택한 방식으로 통일하도록 제안한다. (토론)
  - 조건: 참여자는 포트 변경에도 동작하도록 현재 페이지에서 서버 주소를 구하는 방법과 경로만 지정하는 방법을 대안으로 제시하고, URL과 경로 지정의 차이를 질문했다. 작성자는 경로는 baseURL의 호스트를 기준으로 하고 URL은 명시한 주소를 기준으로 동작한다고 설명했다. 후속 발언에서는 URL 직접 지정의 장점이 더 크면 유지해도 되지만 별도 장점이 없다면 경로가 더 간결하다고 조건을 달았다. 작성자는 반영 의사를 밝혔으나 최종 선택과 변경 결과는 확인되지 않는다.

- [ ] 운영체제별 경로 인코딩 문제를 피하기 위해 resource.getFile() 대신 Paths.get(resource.toURI())를 사용하는 방안을 제안한다. (개선 제안)
  - 조건: 리뷰 참여자가 제기한 위험은 운영체제에 따른 파일 경로 처리의 이식성 문제이며, 실제 오류 재현 결과는 없다. 작성자는 추가 조사 후 수정하겠다고 답했다. 전용 파일 경로 처리 범주가 없어 환경 호환성에 가까운 BUILD_CONFIG로 분류했으며, 대안의 기술적 타당성과 반영 결과는 확인되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```html
<link rel="stylesheet" href="/assets/app.css">
```

**적용 설명:** 개발 머신 주소를 제거한 루트 상대경로다. 하위 경로에 배포하는 앱이라면 배포 base path도 반영한다.
