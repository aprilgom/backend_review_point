# FC0415 · RequestMethod를 지정하지 않았을 때 모든 HTTP 메서드를 지원하는지 검증하는 테스트를 추가하자는 제안이다.

[소속 분야: 테스트 대상·검증](../21-test-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0412](FC0412.md) · [다음 FC: FC0416 →](FC0416.md)

- [ ] RequestMethod를 지정하지 않았을 때 모든 HTTP 메서드를 지원하는지 검증하는 테스트를 추가하자는 제안이다. (개선 제안)
  - 조건: 메서드 미지정이라는 조건의 동작을 검증하자는 요청이며, 실제 구현의 지원 여부나 테스트 추가 결과는 확인되지 않는다.

- [ ] RequestMapping에 method를 설정하지 않으면 모든 HTTP 메서드를 지원하는지 검증하는 테스트를 AnnotationHandlerMappingTest에 추가하자는 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 나중에 추가하면 좋겠다는 선택적 제안으로 표현했고, 2~3단계 리팩터링 중 해당 기능의 동작을 확인하기 위한 회귀 테스트의 가치를 설명했다. 현재 기능이 잘못 동작한다고 보고한 것은 아니다.

- [ ] @RequestMapping의 method 설정이 없으면 모든 HTTP 메서드를 지원한다는 요구사항을 검증하는 테스트를 추가하자는 제안이다. (개선 제안)
  - 조건: method를 설정하지 않은 경우에 관한 테스트 제안이다. 작성자는 해당 요구사항을 놓쳤다고 답한 뒤 반영했다고 보고했으며, 구현과 테스트의 실제 결과는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
for (Method method : supportedMethods) {
    assertTrue(router.find("/any", method).isPresent());
}
```

**적용 설명:** 자체 라우터에서 메서드 생략은 모든 지원 메서드라는 계약일 때의 테스트다. 기본 계약이 다르면 기대값도 달라진다.
