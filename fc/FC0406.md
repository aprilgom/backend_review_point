# FC0406 · 서비스 테스트의 대역 범위

[소속 분야: 테스트 대상·검증](../21-test-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0410](FC0410.md) · [다음 FC: FC0398 →](FC0398.md)

## 검토 질문

- [ ] 검증할 서비스의 책임을 먼저 정한 뒤 외부 의존을 실제 객체·fake·mock 중 무엇으로 둘지 선택했는가?

**직접 작성한 예시**

```java
RecordingSender sender = new RecordingSender();
NotificationService service = new NotificationService(sender);
service.notify(sampleEvent);
assertEquals(1, sender.sentCount());
```

**적용 설명:** 외부 전송을 대역으로 둔 서비스 단위 테스트다. RecordingSender는 서비스의 Sender 계약을 구현하고 보낸 횟수를 관측하는 가상 타입이다.

## 구체적인 검토 사례

- [ ] 서비스 테스트에서 검증하려는 범위를 먼저 명확히 하고, 다른 서비스를 실제로 사용할지 Mock으로 대체할지 결정하자고 제안한다. (개선 제안)
  - 조건: 작성자는 같은 계층의 여러 서비스를 가져오는 것이 불가피한지 물었다. 리뷰 참여자는 여러 도메인이 얽힌 기능에서는 다른 서비스의 도움이 필요할 수 있고 같은 계층 사용도 상황에 따라 괜찮다고 답했다. 테스트의 핵심이 아닌 서비스는 Mock으로 대체할 수 있다는 선택지를 제시했으며, 하위 계층만 사용하라는 규칙은 제시하지 않았다.

- [ ] Mock을 사용하는 FavoriteServiceTest가 의미 있는 검증인지 검토하고 Mock 없이 테스트해보자는 제안이다. (개선 제안)
  - 조건: PR 작성자 외 참여자는 테스트의 의미를 질문한 뒤 대안을 제안했다. 해당 테스트가 무의미하다는 확정 판정이나 구체적인 대체 방식은 제시하지 않았다.

- [ ] 서비스를 mock 처리한 컨트롤러 테스트가 무엇을 검증하려는지 명확히 하고, 단위 테스트와 통합 테스트의 목적에 맞게 검증 범위를 정하도록 질문했다. (토론)
  - 조건: 참여자는 컨트롤러 호출·DTO 형태를 확인하려는지, 실제 서비스 비즈니스 로직을 거친 응답까지 확인하려는지 구분해 물었다. 작성자는 서비스 로직은 별도의 ServiceTest에서 검증하고 컨트롤러는 결과 변환과 반환을 담당하므로 mock을 사용할 수 있다고 주장했다. 참여자는 후속 답변에서 각 테스트의 용도와 목적에 맞게 작성하면 단위·통합 테스트의 구분이 명확해진다고 호응했다. 실제 빈 사용을 필수로 요구한 것으로 해석하지 않는다.
