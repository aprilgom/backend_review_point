# FC0370 · 서비스 계층의 도입 이유

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0378](FC0378.md) · [다음 FC: FC0366 →](FC0366.md)

## 검토 질문

- [ ] 서비스가 실제 유스케이스 조율 책임을 가지는지 단순 전달 계층만 미리 늘리는지 검토했는가?

**직접 작성한 예시**

```java
Receipt placeOrder(CreateOrder command) {
    Order order = Order.create(command.lines());
    orders.save(order);
    return Receipt.from(order);
}
```

**적용 설명:** 유스케이스 조율 책임이 있을 때 서비스 계층의 의미가 생긴다. 도메인 규칙은 Order에 둔다.

## 구체적인 검토 사례

- [ ] **상황:** 역할 없이 서비스 계층을 미리 추가한다.
  - **판단 기준:** 조율할 유스케이스가 있는지 확인한다.

- [ ] **상황:** 컨트롤러에 반복 업무 흐름이 늘어난다.
  - **판단 기준:** 경계를 만들 이점이 생겼는지 다시 검토한다.
