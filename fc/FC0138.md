# FC0138 · 연관 컬럼의 기본 명명 규칙

[소속 분야: 데이터 관계·영속성](../08-persistence.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0136](FC0136.md) · [다음 FC: FC0137 →](FC0137.md)

## 검토 질문

- [ ] 연관 컬럼 이름을 생략했을 때 생성되는 매핑을 알고 실제 스키마와 일치시키는가?

**직접 작성한 예시**

```java
@ManyToOne
@JoinColumn(name = "owner_id")
private Owner owner;
```

**적용 설명:** 외래 키 이름을 명시한 예다. 생략 시 생성되는 이름을 실제 매핑 메타데이터·DDL로 비교한다.

## 구체적인 검토 사례

- [ ] @JoinColumn의 name을 생략했을 때 어떻게 동작하는지 확인하도록 제안했다. (개선 제안)
  - 조건: 작성자는 name을 지정했을 때와 동일하게 동작하는 것으로 보인다며 확인을 요청했다. 그 판단에 대한 리뷰어의 후속 확인은 없다.

- [ ] 연관관계 매핑에서 @JoinColumn을 생략할 수도 있는데 명시적으로 사용한 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 기본 이름 매핑도 가능하지만 필드명 변경이 DB 컬럼 매핑에 영향을 주어 실수를 유발할 수 있으므로 명시했다고 설명했다. 리뷰어의 질문을 어노테이션 제거 요구나 매핑 결함 확정으로 해석하지 않으며, 이 설명에 대한 후속 판단은 없다.

- [ ] 연관관계 필드에 별도 설정 없는 @JoinColumn을 명시한 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 해당 어노테이션의 기능을 사용하지 않는다고 판단하여 삭제했다고 보고했다. 삭제의 실제 반영 여부나 매핑 결과는 확인되지 않는다.
