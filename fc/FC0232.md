# FC0232 · 노선 이름 수정 시 다른 노선의 기존 이름으로 변경하여 중복이 생기는 경우를 검증해야 한다고 지적했다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0224](FC0224.md) · [다음 FC: FC0227 →](FC0227.md)

- [ ] 노선 이름 수정 시 다른 노선의 기존 이름으로 변경하여 중복이 생기는 경우를 검증해야 한다고 지적했다. (문제 보고)
  - 조건: a, b, c 노선 중 c의 이름을 a로 바꾸는 구체적인 사례를 제시하며 검증 추가를 제안했다. 작성자는 이를 놓쳤다고 인정하고 수정하겠다고 답했지만, 실제 반영 결과는 이 대화에 없다.

- [ ] 같은 역을 한 노선의 서로 다른 방향에 중복 등록할 수 있는 것이 의도인지 묻고, 의도에 따라 등록 검증 또는 조회 결과를 수정하도록 제안했다. (조건부 제안)
  - 조건: 리뷰어는 동일한 jamie 역을 같은 기준 역의 DOWN과 UP 방향에 각각 추가하는 요청을 제시했다. 중복 등록을 허용한다면 조회에서 한 역만 나오는 점을 수정하고, 허용하지 않는다면 중복 등록을 막아야 한다는 조건부 지적이다. 작성자는 모든 예외 처리를 했다고 답했지만 선택한 정책과 실제 결과는 구체적으로 설명하지 않았다.

- [ ] 기존 구간 사이에 길이 조건을 만족하지 않는 구간을 추가할 때 생성이 허용되는 경우가 있는지 확인하도록 요청했다. (위험 지적)
  - 조건: 리뷰 참여자는 여러 번 테스트했을 때 생성이 되기도 하고 안 되기도 하는 것 같다고 표현했다. 구체적인 입력별 결과와 원인은 제시되지 않아 일관된 재현이나 결함 원인은 확정할 수 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
if (lines.existsByNameExceptId(newName, lineId)) throw new DuplicateLineName();
```

**적용 설명:** 자기 자신의 기존 이름은 제외하고 다른 엔티티와 충돌하는지 확인한다. DB 유일성 제약도 유지한다.
