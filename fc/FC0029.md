# FC0029 · Reservation의 부생성자에서 필드 초기화를 반복하기보다 다른 생성자에 위임해 객체를 생성하자는 제안이다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0030](FC0030.md) · [다음 FC: FC0031 →](FC0031.md)

- [ ] Reservation의 부생성자에서 필드 초기화를 반복하기보다 다른 생성자에 위임해 객체를 생성하자는 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 기본 생성자를 활용하라는 표현과 함께 this(null, ...) 형태를 예시로 제시했다. 예시의 실제 적용 가능성이나 구현 결과는 확인되지 않는다.

- [ ] Reservation의 중복된 필드 초기화를 생성자 체이닝으로 처리해보자고 제안했다. (개선 제안)
  - 조건: id를 받지 않는 생성자에서 this(null, name, date, time, theme)으로 다른 생성자를 호출하는 구체적인 예시를 제공했다. 적용 결과는 제시되지 않았다.

- [ ] Reservation의 각 생성자에서 필드 설정을 반복하지 말고 다른 생성자를 내부 호출해 공통화하는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 ID를 받는 생성자에서는 ID의 null 검증이 필요해 분리했다고 설명하고, 관련 논의의 판단에 따라 추후 리팩터링하기를 요청했다. 리뷰 참여자는 이를 수용했으며 제안을 철회한 것은 아니다. 참조된 다른 스레드의 판단과 실제 리팩터링 결과는 이 대화에서 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Reservation(LocalDate day) { this(day, LocalTime.NOON); }
Reservation(LocalDate day, LocalTime time) {
    this.day = Objects.requireNonNull(day);
    this.time = Objects.requireNonNull(time);
}
```

**적용 설명:** 기본 시간을 제공하는 생성자도 같은 초기화 경로를 사용한다. 기본값 자체가 요구사항에 맞는지 확인한다.
