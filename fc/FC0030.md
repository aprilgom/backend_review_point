# FC0030 · UserHistoryDao에도 작성한 JdbcTemplate을 적용해 보자고 제안했다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0011](FC0011.md) · [다음 FC: FC0029 →](FC0029.md)

**혼합·경계:** 직접 구현한 JdbcTemplate의 중복 제거도 포함하므로 제품 API 사용과 구별.

- [ ] UserHistoryDao에도 작성한 JdbcTemplate을 적용해 보자고 제안했다. (개선 제안)
  - 조건: 이 대화에는 해당 DAO의 구체적인 변경 내역이 없으며, 작성자의 포괄적인 반영 보고나 최종 승인만으로 적용 결과를 확정하지 않는다.

- [ ] JdbcTemplate의 Connection 연결과 try-catch 처리에 반복되는 코드를 공통 부분으로 추출해 중복을 줄이는 방안을 제안했다. (개선 제안)
  - 조건: 참여자는 반드시 반영할 필요는 없는 선택적 제안임을 명시했다. 작성자는 클래스 내부에서 함수형 인터페이스를 사용해 공통 부분을 추출했다고 보고했으며, 추후 적절하다고 판단하면 별도 클래스로 분리하겠다고 답했다. 실제 변경 결과는 이 답변만으로 확정하지 않는다.

- [ ] JdbcTemplate 전반에 반복되는 try-with-resources 구문의 중복을 제거해보자고 제안했다. (개선 제안)
  - 조건: 작성자는 해당 리뷰를 놓쳤다고 설명하고 3단계에서 고민하여 반영하겠다고 답했다. 실제 반영 여부는 이 대화에서 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
// 직접 작성한 SQL 실행 도우미의 사용 예
sqlRunner.update("INSERT INTO activity(kind) VALUES (?)",
    statement -> statement.setString(1, "LOGIN"));
```

**적용 설명:** sqlRunner는 가상 자체 도우미다. 연결 생성·해제·예외 변환을 공통화하되 트랜잭션 참여 계약을 먼저 정한다.
