# FC0342 · 호출부에 맞는 조건 이름

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0338](FC0338.md) · [다음 FC: FC0316 →](FC0316.md)

## 검토 질문

- [ ] 긍정·부정 판정 이름을 호출부에서 자연스럽게 읽히도록 선택하고 이중 부정을 피하는가?

**직접 작성한 예시**

```java
if (!first.hasSameColorAs(second)) allowConnection();
```

**적용 설명:** 긍정형에 부정을 붙인 형태도 읽기 쉬울 수 있다. 호출부가 대부분 부정 조건이라면 hasDifferentColorFrom 같은 이름을 비교한다.

## 구체적인 검토 사례

- [ ] 호출부가 서로 다른 색상인지 확인하려는 용도이므로 isSameColor를 isNotSameColor 형태로 바꾸자고 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 GamePiece와 Pawn의 두 호출부 모두 부정 결과를 원한다고 설명하며, isNotEmpty처럼 부정형으로 의미를 드러내는 방식을 제안했다. 단순 이름 변경만으로 동작이 유지된다고 단정하지 않는다.

- [ ] 상품 id 컬럼의 기본 키 선언을 컬럼 정의와 같은 줄에 작성할 수 있는지 제안했다. (개선 제안)
  - 조건: SQL 선언을 한 줄로 정리하자는 취지다. 제안 코드에는 PRIMART KEY라는 철자가 포함되어 있어 이를 유효한 SQL 예제로 확정하지 않는다. 작성자는 수정했다고 답했지만 구체적인 수정 내용은 제시하지 않았다.

- [ ] 개별 import가 wildcard import로 바뀐 것이 코드 스타일 설정 변경 때문인지 확인한다. (설계 질문)
  - 조건: 작성자는 최근 노트북을 바꾸면서 코드 스타일 설정을 하지 않았다고 설명했다. 설정을 복구하거나 import를 수정했다는 보고는 없다.
