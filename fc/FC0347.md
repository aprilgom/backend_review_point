# FC0347 · 브라우저의 추가 리소스 요청

[소속 분야: 렌더링·데이터 로딩](../18-rendering.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0344](FC0344.md) · [다음 FC: FC0348 →](FC0348.md)

## 검토 질문

- [ ] HTML 이후 CSS·JS 등 추가 요청이 발생하는 흐름과 서버의 경로·캐시·제공 설정을 확인했는가?

**직접 작성한 예시**

```html
<link rel="stylesheet" href="/assets/site.css">
<script src="/assets/site.js" defer></script>
```

**적용 설명:** 브라우저는 HTML을 해석하며 참조 리소스를 추가 요청한다. 서버 라우팅·캐시·리소스 경로를 함께 검증한다.

## 구체적인 검토 사례

- [ ] 브라우저가 index.html을 처음 받은 뒤 HTML에 연결된 CSS와 JS를 어떤 과정으로 추가 요청하는지 묻는다. (설계 질문)
  - 조건: 내부 동작 이해를 위한 선택적 질문으로 제시되었으며 결함 지적은 아니다. 작성자는 Content-Type에 따른 HTML 해석, 리소스 태그 발견, 개별 HTTP 요청, 렌더링 순으로 설명했다. 이 답변을 검증된 기술적 정답으로 확정하지 않는다.

- [ ] 요청 처리 과정에서 HTML 페이지 응답과 JSON 데이터 응답이 어떻게 결정되고 반환되는지 학습해 공유하도록 요청했다. (학습 제약)
  - 조건: 작성자는 DispatcherServlet, 핸들러 반환값, 뷰 리졸버를 중심으로 자신의 이해를 정리하고 정확성 확인을 요청했다. 이 설명에 대한 기술적 검증이나 정정은 해당 대화에 없다. 첨부 이미지와 외부 링크의 내용은 근거로 보충하지 않았다.

- [ ] 별도 PageController를 두는 대신 resources 하위의 적절한 HTML 배치로 처리할 수 있는지 검토하고, 자동 처리가 되지 않는다면 요청 경로와 파일명의 불일치를 확인하도록 제안했다. (개선 제안)
  - 조건: 리뷰어는 Spring이 자동으로 렌더링할 것이라는 예상과 함께 `admin/reservation`과 `reservations`의 차이를 원인 후보로 들었다. 실제 파일 배치나 렌더링 결과는 제시되지 않아 동작 불량이나 원인이 확정된 것은 아니다.
