# FC0432 · 삭제 테스트에서 `/times/1`처럼 ID를 직접 지정하지 말고 삽입된 데이터의 ID를 받아 사용하도록 제안했다.

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0434](FC0434.md) · [다음 FC: FC0427 →](FC0427.md)

- [ ] 삭제 테스트에서 `/times/1`처럼 ID를 직접 지정하지 말고 삽입된 데이터의 ID를 받아 사용하도록 제안했다. (개선 제안)
  - 조건: 작성자는 적용하겠다고 답했으며, 실제 변경 여부는 대화에서 확인되지 않는다.

- [ ] 테스트에서 상품 ID를 1L처럼 하드코딩하지 않고 실제 생성된 ID를 사용하는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 상품 생성 응답의 Location 헤더에서 생성된 ID를 구해 활용했다고 보고했다. 변경 결과를 별도로 검증한 근거는 없다.

- [ ] 테스트에서 ID를 항상 1로 고정하지 말고 전달받은 ID 값을 사용하자고 제안한다. (개선 제안)
  - 조건: 작성자는 앞에서 데이터 수가 1임을 확인한 뒤 SELECT id FROM reservation_time으로 ID를 조회하도록 리팩터링했다고 보고하고 더 나은 방법을 질문했다. 그 방법에 대한 후속 평가나 답변은 제공되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
long id = slots.save(sampleSlot()).id();
assertEquals(204, client.delete("/slots/" + id).status());
```

**적용 설명:** DB 생성 ID를 사용해 시퀀스 상태에 덜 의존하게 한다.
