# FC0237 · 형식 검증과 실제 유효성

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0231](FC0231.md) · [다음 FC: FC0238 →](FC0238.md)

## 검토 질문

- [ ] 문자열 형식 검증이 보장하는 범위와 실제 존재·소유권 검증을 구분했는가?

**직접 작성한 예시**

```java
record Contact(
    @jakarta.validation.constraints.NotBlank
    @jakarta.validation.constraints.Email String email) {}
```

**적용 설명:** 간단한 형식 검증일 뿐 주소 소유권·실제 수신 가능성을 보장하지 않는다.

## 구체적인 검토 사례

- [ ] Email 값에 정규표현식 등을 활용한 간단한 이메일 형식 검증을 추가하도록 제안했다. (개선 제안)
  - 조건: 작성자는 Email 도메인에서 정규표현식으로 검증하도록 리팩터링했다고 보고했다. 구체적인 정규표현식이나 허용 형식의 적절성은 대화에 제시되지 않았다.

- [ ] 이메일 형식이 아닌 값으로도 가입할 수 있으므로 회원가입 요청에서 이메일 형식을 검증하도록 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 이메일 형식이 아니어도 가입되는 상황을 지적했다. 작성자는 회원가입 요청 DTO에 이메일 형식 검증을 추가했다고 보고했으며, 실제 변경 결과는 이 대화만으로 검증되지 않는다.

- [ ] 회원가입 요청 폼에 account나 email 등의 필드가 없는 경우를 검증하도록 제안했다. (개선 제안)
  - 조건: 작성자는 반영 완료라고 답했으나, 구체적인 검증 방식과 실제 변경 결과는 이 대화에서 확인되지 않는다.
