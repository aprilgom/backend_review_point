# FC0057 · 사용자 상태에 따른 화면 이동

[소속 분야: API·공개 인터페이스 계약](../03-api-contract.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0054](FC0054.md) · [다음 FC: FC0058 →](FC0058.md)

## 검토 질문

- [ ] 사용자의 인증·업무 상태에 따라 기대한 화면으로 이동하며 응답 상태와 이동 경로도 맞는가?

**직접 작성한 예시**

```java
if (session.isAuthenticated() && request.path().equals("/login")) {
    return HttpReply.redirect(303, "/home");
}
```

**적용 설명:** 로그인 사용자의 화면 이동 계약 예시다. 실제 응답의 Location 헤더와 로그인하지 않은 경우도 테스트한다.

## 구체적인 검토 사례

- [ ] 로그인 상태에서 GET /login 요청 시 index.html로 리다이렉트하는 요구사항이 동작하지 않는 것으로 보여 확인을 요청했다. (문제 보고)
  - 조건: 참여자 eunseongu가 제기한 의심성 문제 보고다. 작성자는 자신의 테스트 환경에서는 정상 동작했다고 반박하고, 브라우저에 남은 유효하지 않은 JSESSIONID 때문에 로그인 페이지가 표시된 상황일 가능성을 추측했다. 유효한 세션을 발급받은 뒤 재확인을 요청했으며, 해당 추측은 확인된 원인이 아니다. 이후 참여자는 변경을 확인했다고 승인했지만 구체적인 변경 내용이나 재현 결과를 설명하지 않았으므로 해결 또는 지적 철회를 확정하지 않는다.

- [ ] 로그인한 상태에서 GET /login 요청을 보내면 /index.html로 리다이렉트해야 하는 요구사항이 구현되지 않았다고 지적했다. (문제 보고)
  - 조건: 작성자는 해당 기능을 구현했으나 정상 동작하지 않았다고 설명하고, JSESSIONID 키에 공백이 추가되는 문제를 확인하여 우선 trim으로 처리했다고 보고했다. 추가 확인이 필요하다고도 밝혔으며, 이후 승인·머지만으로 동작 해결이 검증되었다고 볼 수는 없다.

- [ ] 로그인 요청에 쿼리 파라미터를 포함해도 로그인 처리가 동작하지 않는다고 보고했다. (문제 보고)
  - 조건: 참여자는 디버깅 중 '?'가 포함되지 않아 해당 분기로 들어가지 않는다고 설명했다. 후속 요구사항 확인과 승인만으로 원인이나 수정 결과를 확정하지 않는다.
