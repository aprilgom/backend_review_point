# FC0287 · 반복 처리 밖으로 조회 이동

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0286](FC0286.md) · [다음 FC: FC0277 →](FC0277.md)

## 검토 질문

- [ ] 반복문 안의 DB 접근을 사전 일괄 조회로 바꿀 수 있으며 데이터량과 묶음 크기를 제한하는가?

**직접 작성한 예시**

```java
Map<Long, Row> rows = store.findAll(ids);
for (long id : ids) consume(requireRow(rows, id));
```

**적용 설명:** 반복문 밖에서 필요한 데이터를 모은다. 한 번에 너무 많은 ID를 보내면 묶음 크기를 제한한다.

## 구체적인 검토 사례

- [ ] 반복 처리 중 DB를 조회한다면 데이터를 한 쿼리로 가져온 뒤 처리하여 반복 조회를 줄이도록 제안한다. (개선 제안)
  - 조건: 반복문 내부에 DB 쿼리 같은 작업이 있다는 조건에서 제기한 개선안이다. 실제 쿼리 횟수나 성능 측정 결과는 제시되지 않았다.

- [ ] 상품별로 DB를 여러 번 조회하는 대신 한 번에 조회하여 DB 부하를 줄이는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 현재 큰 문제가 있는 것은 아니라고 전제했다. 실제 부하 측정이나 변경 결과는 제시되지 않았다.

- [ ] 이미 조회한 전체 구간 데이터를 활용하여 경로 계산 중 반복되는 DB 조회와 네트워크 요청을 줄이도록 제안한다. (개선 제안)
  - 조건: 리뷰어는 repository 호출마다 쿼리가 발생하고 요청 증가가 DB와 네트워크 대역폭에 영향을 줄 수 있다고 설명했다. PathService에서 allLineStations를 이미 조회한 점을 근거로 들었으며, LineService.wholeLines에도 같은 검토를 요청했다. 실제 부하 측정 결과는 없다.
