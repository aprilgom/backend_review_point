# FC0132 · 현재 요구에 맞는 DB 제약

[소속 분야: 데이터 관계·영속성](../08-persistence.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0133](FC0133.md) · [다음 FC: FC0134 →](FC0134.md)

## 검토 질문

- [ ] 미래 변경 가능성만으로 제약을 생략하지 않고 현재의 유일성·필수값·범위 규칙을 보장하는가?

**직접 작성한 예시**

```sql
ALTER TABLE account ADD CONSTRAINT email_unique UNIQUE (email);
ALTER TABLE cart_line ADD CONSTRAINT positive_quantity CHECK (quantity > 0);
```

**적용 설명:** 현재 불변식을 DB에서도 보장한다. 기존 데이터 정리와 마이그레이션 순서를 먼저 확인한다.

## 구체적인 검토 사례

- [ ] **상황:** 미래 확장을 이유로 모든 컬럼을 nullable로 둔다.
  - **판단 기준:** 현재의 필수값 규칙을 우선 보장한다.

- [ ] **상황:** 유일성 규칙을 서비스 검사에만 맡긴다.
  - **판단 기준:** 우회 경로와 동시 쓰기에 대한 최종 제약을 둔다.
