# FC0005 · 저장소를 한 번 더 추상화하는 근거

## 검토 질문

- [ ] 이미 추상화된 저장소를 추가 인터페이스로 감쌀 때 의존성 격리·모델 변환·교체 가능성 중 어떤 이점이 생기는가?

**직접 작성한 예시**

```java
interface CustomerStore { Optional<Customer> find(CustomerId id); }
final class SqlCustomerStore implements CustomerStore {
    // DB 의존 코드는 이 어댑터에 둔다.
}
```

**적용 설명:** 저장 기술 교체·도메인 분리를 위한 경계가 실제로 필요할 때의 모양이다. 기존 인터페이스를 그대로 복제할 뿐이면 추가 추상화 이점이 작다.

## 구체적인 검토 사례

- [ ] **상황:** 저장 API를 그대로 복제한 인터페이스를 추가한다.
  - **판단 기준:** 추가 경계가 막는 변경을 구체적으로 확인한다.

- [ ] **상황:** 저장 형식이 도메인으로 새어 나온다.
  - **판단 기준:** 모델 변환을 맡는 어댑터라면 별도 추상화가 유효하다.
