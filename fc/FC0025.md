## 검토 질문

- [ ] 생성·수정의 입력과 검증이 실제로 같을 때 계약을 공유하고, 의미가 달라지는 시점에 분리하는가?

**직접 작성한 예시**

```java
record LabelInput(String name, String color) {}
Label create(LabelInput input) { return labels.create(input); }
void update(long id, LabelInput input) { labels.update(id, input); }
```

**적용 설명:** 생성·수정의 필수값과 검증이 동일할 때의 공유 예시다. 부분 수정 등 계약이 달라지면 분리한다.

## 구체적인 검토 사례

- [ ] **상황:** 생성과 수정의 필드·검증이 같다.
  - **판단 기준:** 공유 입력 계약으로 중복을 줄일 수 있다.

- [ ] **상황:** 수정에서 필드 생략을 허용한다.
  - **판단 기준:** 생성 필수값과 부분 수정의 의미가 다르면 분리한다.
