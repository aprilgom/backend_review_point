# FC0390 · 토큰에 담긴 생성 시점의 정보만으로 인증하지 말고 인증 시점에도 올바른 접근인지 확인하는 방식을 제안했다.

[소속 분야: 인증·보안·비밀값](../20-security.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0391](FC0391.md) · [다음 FC: FC0392 →](FC0392.md)

- [ ] 토큰에 담긴 생성 시점의 정보만으로 인증하지 말고 인증 시점에도 올바른 접근인지 확인하는 방식을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 토큰 위변조 가능성을 근거로 관련 인증 로직 전반에 제안했다. 이는 참여자가 제시한 보안 전제이며, 이 대화만으로 실제 위변조 가능성이 검증된 것은 아니다. 작성자는 인증 시 실제 Member 정보를 조회하도록 리팩터링했다고 보고했다.

- [ ] 토큰 쿠키에 적용한 HttpOnly와 Path 설정이 각각 어떤 의미인지 설명을 요청한다. (설계 질문)
  - 조건: 작성자는 HttpOnly가 클라이언트 스크립트의 쿠키 접근을 막고, Path는 쿠키를 포함할 요청 경로를 정한다고 설명했다. 설정의 결함이나 변경 필요성을 확정한 질문은 아니다.

- [ ] 토큰에 저장한 role만으로 관리자 권한을 판단하면 권한을 회수한 뒤에도 기존 토큰으로 접근할 수 있으므로, 가능하면 ID를 받아 판단하는 방식을 권했다. (위험 지적)
  - 조건: 작성자는 ID로 회원을 조회하던 방식에서 토큰의 role을 확인하는 방식으로 변경했다고 밝혔다. 리뷰 참여자의 우려는 발급 후 권한이 회수되는 경우에 해당하며, 실제 접근 가능 여부를 검증한 결과나 후속 변경은 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
VerifiedToken token = tokenVerifier.verify(rawToken);
Account account = accounts.requireActive(token.subject());
authorization.requireAllowed(account, resource);
```

**적용 설명:** 토큰 검증과 현재 계정 상태·자원 권한 확인을 구분한다. 폐기·만료·키 회전 정책도 필요하다.
