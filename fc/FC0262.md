# FC0262 · 예외를 식별할 수 있는 로그

[소속 분야: 로그·관측](../15-observability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [다음 FC: FC0264 →](FC0264.md)

## 검토 질문

- [ ] 로그만으로 실패의 종류·원인·관련 작업을 추적할 수 있으며 비밀값은 제외했는가?

**직접 작성한 예시**

```java
logger.error("operation failed: operationId={}", operationId, failure);
```

**적용 설명:** SLF4J 형태다. 스택과 상관 ID를 남기되 예외 메시지·컨텍스트에 비밀값이 들어가지 않도록 한다.

## 구체적인 검토 사례

- [ ] 현재 로그만으로는 어떤 예외가 발생했는지 확인할 수 없으므로 발생한 오류를 식별할 수 있는 정보를 남기도록 제안했다. (개선 제안)
  - 조건: 작성자는 정의되지 않은 예외를 개발자가 인지하도록 로깅했다고 설명했다. 리뷰 참여자는 적용 방향을 긍정하면서도 예외 식별 정보가 부족하다고 지적했다. 작성자는 어떤 Exception인지 알 수 있도록 수정했다고 보고했으나 실제 로그 내용은 제시되지 않았다.

- [ ] 개발자가 예측 불가능한 오류 상황을 파악할 수 있도록 예외를 로그로 남기는 방안을 제안했다. (개선 제안)
  - 조건: 예측하지 못한 예외를 처리하는 상황에 대한 제안이며, 예시로 예외 객체를 포함한 logger.error 호출을 제시했다.

- [ ] 요청 실패를 로그로 조사하기 쉽도록 예외 메시지를 더 자세히 작성하자고 제안했다. (개선 제안)
  - 조건: 수십만 명이 사용하는 서비스에서 실패 요청을 로그로 확인할 가능성이 높다는 상황을 가정한 제안이다.
