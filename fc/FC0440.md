# FC0440 · 날짜 의존 테스트의 시간 기준

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0441](FC0441.md) · [다음 FC: FC0447 →](FC0447.md)

## 검토 질문

- [ ] 고정 데이터와 현재 날짜가 어긋나지 않도록 앱·DB의 시간 기준과 입력 날짜를 제어하는가?

**직접 작성한 예시**

```java
Clock clock = Clock.fixed(Instant.parse("2025-03-08T00:00:00Z"), ZoneOffset.UTC);
LocalDate from = LocalDate.now(clock).minusDays(6);
```

**적용 설명:** 애플리케이션 기준 오늘을 고정한 예다. SQL이 CURRENT_DATE를 직접 쓰면 이 Clock만으로 고정되지 않으므로 날짜를 바인딩하거나 DB 시계 전략도 맞춘다.

## 구체적인 검토 사례

- [ ] CURRENT_DATE 기준으로 최근 7일을 조회하는 테스트에 고정된 예약 날짜를 사용하면 시간이 지나 실패하므로, 시간 기준과 테스트 데이터 설정 방식을 검토하도록 요청했다. (문제 보고)
  - 조건: 리뷰어는 2026년 5월 1~2일로 고정된 데이터 때문에 5월 9일 이후 테스트가 실패한다고 지적했고, 작성자도 당시 실패 중이라고 보고했다. 작성자는 기준 날짜 주입과 동적 데이터 생성의 장단점을 비교하겠다고 한 뒤, LocalDate.now에 Clock을 주입하는 방식을 선택했다고 보고했다. 동적 데이터 설정의 복잡성과 고정 날짜 테스트의 윤년 등 특수 상황 검증 한계는 작성자가 제기한 고민이며, 리뷰어가 확정한 결함이나 추가 요구가 아니다. 변경 후 테스트 결과는 제시되지 않았다.

- [ ] 테스트에 오늘 날짜를 하드코딩하면 이후에는 과거 예약이 되므로, 향후 과거 예약 금지 검증이 추가될 경우 테스트가 깨질 수 있어 개선을 요청했다. (조건부 제안)
  - 조건: 현재 테스트 실패를 보고한 것이 아니라 날짜 경과와 향후 검증 추가를 조건으로 한 우려다. 작성자는 LocalDate.now()로 당일 날짜를 사용하는 방안을 제시했으며, 리뷰어의 후속 평가나 구현 결과는 없다.

- [ ] 고정된 예약 날짜를 사용하는 테스트가 시간이 지나도 계속 성공할 수 있는지, Clock을 도입한 목적과 함께 점검하도록 질문했다. (설계 질문)
  - 조건: 작성자는 고정 Clock을 전제로 했다고 설명하며, 날짜 리터럴만으로는 그 의도가 드러나지 않을 수 있어 LocalDate.now(clock).plusDays(...)로 데이터를 만들겠다고 답했다. 실제 시스템 시간 의존이나 향후 실패가 확인된 결함으로 단정할 수는 없다.
