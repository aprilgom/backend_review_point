# FC0235 · 요청 필드의 빈값과 null 등에 대한 기본 검증을 추가하는 것이 좋지 않은지 질문했다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0229](FC0229.md) · [다음 FC: FC0230 →](FC0230.md)

- [ ] 요청 필드의 빈값과 null 등에 대한 기본 검증을 추가하는 것이 좋지 않은지 질문했다. (개선 제안)
  - 조건: LineController의 생성 요청 처리에 대한 제안이다. 구체적인 검증 구현 방식이나 각 필드의 허용 조건까지 정하지는 않았다.

- [ ] 회원가입 입력을 null 여부만 검사하면 빈 문자열도 저장될 수 있으므로 검증을 보완해야 한다고 지적했다. (문제 보고)
  - 조건: 작성자는 계정·비밀번호·이메일이 누락되거나 공백이면 저장하지 않도록 수정했다고 보고했다.

- [ ] null과 빈 문자열 검증을 request에서만 수행해도 되는지, command와 domain에서도 검증이 필요한지 질문했다. (설계 질문)
  - 조건: 작성자는 request에서 빠르게 오류를 발생시키려 했으며 여러 위치의 검증을 중복으로 여겼지만 계층마다 다른 책임일 수 있다고 재고했다. 이후 도메인이 엔티티 역할도 겸해 ID의 null을 허용해야 하므로 현재는 컨트롤러·서비스 DTO에서 검증하고, 엔티티 역할을 분리한다면 도메인에서도 null 검증을 할 것이라는 입장을 밝혔다. 모든 계층에서 검증해야 한다는 결론이나 리뷰 참여자의 후속 동의는 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record Signup(@jakarta.validation.constraints.NotBlank String nickname) {}
```

**적용 설명:** 기본 입력 검증의 예시다. 길이·허용 문자·정규화·중복 같은 업무 규칙은 추가로 정한다.
