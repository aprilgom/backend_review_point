# FC0191 · 사용하지 않는 코드 의존의 정리

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0188](FC0188.md) · [다음 FC: FC0182 →](FC0182.md)

## 검토 질문

- [ ] 미사용 import·의존성을 제거하되 동적 로딩이나 런타임 사용 여부도 확인했는가?

**직접 작성한 예시**

```java
import java.util.List;
// 사용하지 않는 java.util.Objects import는 남기지 않는다.
```

**적용 설명:** 미사용 import 정리 예시다. 의존성은 리플렉션·런타임 사용 여부까지 확인한 뒤 제거한다.

## 구체적인 검토 사례

- [ ] 사용하지 않는 의존성과 import 정리를 요청했고, 후속 리뷰에서는 HandlerMappers의 java.util.Objects import가 남아 있다고 지적했다. (개선 제안)
  - 조건: 후속 리뷰에서 폴더 단위로 IntelliJ 코드 최적화를 적용할 수 있다고 안내했다. 다음 단계 진행을 승인했지만 남은 import의 제거까지 확인된 것은 아니다.

- [ ] 레거시 LoginController에 추가한 Controller import가 사용되지 않는 것으로 보인다고 지적했다. (개선 제안)
  - 조건: 지적 대상은 context.org.springframework.stereotype.Controller import이며, 실제 제거 여부는 대화에서 확인되지 않는다.

- [ ] RegisterController에 추가된 javax.swing.Popup import가 무엇을 위한 것인지 묻는다. (설계 질문)
  - 조건: 질문의 대상은 인라인 위치와 diff에 나타난 import로 파악되며, 리뷰어가 미사용 여부나 빌드 문제를 확정한 것은 아니다. 작성자는 '사용하지 않는 주석'을 제거했다고 답했으나, 지목된 코드는 import이므로 답변의 표현과 대상이 일치하지 않는다. 해당 import가 실제로 제거되었는지는 확인할 수 없다.
