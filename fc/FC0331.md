# FC0331 · 전송 메서드와 업무 메서드명의 구분

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0324](FC0324.md) · [다음 FC: FC0302 →](FC0302.md)

## 검토 질문

- [ ] HTTP 메서드만으로 이름을 정하지 않고 조회 대상·조건·역할을 드러내는가?

**직접 작성한 예시**

```java
List<InvoiceReply> findUnpaidInvoices(CustomerId customerId) {
    return invoices.findUnpaid(customerId);
}
```

**적용 설명:** HTTP GET이라는 이유만으로 모든 메서드를 read로 부르지 않는다.

## 구체적인 검토 사례

- [ ] **상황:** 모든 GET 처리 메서드를 같은 동사로 부른다.
  - **판단 기준:** 조회 대상과 조건을 드러낸다.

- [ ] **상황:** HTTP 메서드와 업무 동작을 혼동한다.
  - **판단 기준:** 전송 규약과 내부 역할은 따로 명명한다.
