# FC0480 · 예약 완료 알림과 화면 표시 외에도 사용자가 자신의 예약을 다시 조회하거나 취소할 수 있는 사용자 친화적 흐름을 고민하도록 제안했다.

[소속 분야: UI 동작·사용성](../25-ui-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0468](FC0468.md) · [다음 FC: FC0476 →](FC0476.md)

- [ ] 예약 완료 알림과 화면 표시 외에도 사용자가 자신의 예약을 다시 조회하거나 취소할 수 있는 사용자 친화적 흐름을 고민하도록 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 LMS 요구사항에 없는 확장 논의임을 명시했다. 작성자는 현재 인증·인가 수단이 없다는 제약을 설명하고 향후 인증 도입 시 본인 예약 관리도 함께 고려하겠다고 답했다. 리뷰 참여자는 이름이나 고유 입력을 바탕으로 화면에 접근하는 아이디어를 잠정적으로 제시하면서, 다음 미션 단계로 미루는 것도 괜찮다고 했다. 즉시 구현을 강제한 요구가 아니다.

- [ ] 이미 예약한 테마와 시간에 재예약하면 예약이 없어 대기할 수 없다고 표시되는 동작이 요구사항에 맞는지 확인하고 수정할 것을 요청한다. (문제 보고)
  - 조건: 리뷰 참여자가 직접 보고한 재예약·대기 동작의 문제이며, 내부 원인은 제시되지 않았다. 작성자는 해당 버그를 수정해 반영했다고 보고했다. 이후 승인만으로 실제 동작이 해결되었다고 확정하지 않는다.

- [ ] 예약 시간 관리 화면에서 예약 시간을 추가해도 화면이 갱신되지 않는 문제를 확인하고 수정해 달라고 요청했다. (문제 보고)
  - 조건: 리뷰어가 보고한 화면 동작 문제이며, 구체적인 원인은 제시되지 않았다. 이후 피드백 반영에 대한 총평과 승인은 있지만 이 문제의 수정 내용이나 재확인 결과는 명시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```html
<p role="status">예약이 완료되었습니다.</p>
<a href="/my-bookings">내 예약 확인 및 취소</a>
```

**적용 설명:** 완료 메시지 뒤 후속 작업 경로를 제공한다. 서버 조회·취소 권한 확인은 별도로 필요하다.
