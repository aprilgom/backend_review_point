# FC0297 · 자료구조보다 의미를 드러내는 이름

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [다음 FC: FC0310 →](FC0310.md)

## 검토 질문

- [ ] 변수명이 Map·List 같은 구현보다 키와 값의 업무 의미를 설명하는가?

**직접 작성한 예시**

```java
Map<UserId, User> usersById = loadUsers();
```

**적용 설명:** 자료구조보다 키·값의 의미를 이름에 드러낸다.

## 구체적인 검토 사례

- [ ] idMap처럼 자료형을 포함하는 변수명 대신 의미를 더 명확하게 드러내는 이름을 고민하도록 요청했다. (개선 제안)
  - 조건: 자료형을 변수명에 넣는 것이 올바르지 않다는 것은 리뷰 참여자의 명명 기준이다. 작성자는 관련 메서드 로직을 리팩터링하고 해당 로직을 삭제했다고 보고했으며, 대체 변수명은 제시하지 않았다.

- [ ] createdAtMap처럼 자료형이 포함된 변수명 대신 의미를 더 잘 드러내는 이름을 고민할 것을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 자료형을 이름에 포함하는 것이 일반적으로 권장되지 않는다는 견해를 제시했다. 작성자는 createdAtById로 변경했다고 보고했다.

- [ ] anotherTime을 새로 예약하려는 시작 시간이라는 의미가 드러나는 이름으로 바꾸는 방안을 제안했다. (개선 제안)
  - 조건: 현재 이름만으로는 어떤 시간인지 파악하기 어렵다는 의견이다. 변경 결과는 제공되지 않았다.
