# FC0398 · 동작 계약과 내부 구현 테스트

## 검토 질문

- [ ] 테스트가 공개 계약을 검증하는지 불필요한 내부 구조에 결합되어 리팩터링을 방해하는지 확인했는가?

**직접 작성한 예시**

```java
assertEquals(new Money(500), calculator.price(input));
// 내부 보조 메서드의 호출 횟수보다 공개 결과를 검증한다.
```

**적용 설명:** 내부 구조 변경에 취약한 테스트인지 살핀다. 호출 자체가 계약인 외부 부작용은 상호작용 검증이 의미 있다.

## 구체적인 검토 사례

- [ ] 동작이 아니라 구현사항을 확인하는 것으로 보이는 테스트가 왜 필요한지 질문했다. (설계 질문)
  - 조건: 작성자는 미션 단계별로 제공된 테스트 중 하나였다고 설명하고, 구현사항을 만족한 뒤에는 제거해도 된다고 판단해 삭제했다고 보고했다. 해당 테스트의 구체적인 검증 코드는 제공되지 않았으므로 불필요한 테스트라고 확정하지 않는다.

- [ ] 해당 테스트가 무엇을 검증하기 위한 것인지 설명해 달라. (설계 질문)
  - 조건: 작성자는 9단계에서 제공된 테스트이며, 계층 분리 요구에 따라 컨트롤러에서 기존 레포지토리 컴포넌트가 사라졌는지 확인하는 테스트로 이해한다고 답했다. 이는 작성자의 설명이며, 리뷰 참여자가 테스트의 무용성이나 결함을 확정한 것은 아니다.

- [ ] 기능 구현에 대한 테스트가 없다며 꼼꼼한 테스트 작성을 요청했다. (문제 보고)
  - 조건: 작성자는 빈이 단일 인스턴스인지 확인하는 테스트와 Controller·Service·Repository 스캔 테스트를 추가했다고 보고했다. 실제 추가 내용과 검증 결과는 이 대화만으로 확인되지 않는다.
