# FC0312 · 연산 표현의 형식과 의미

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0332](FC0332.md) · [다음 FC: FC0317 →](FC0317.md)

## 검토 질문

- [ ] 연산자 공백 등 형식 규칙을 지키고 primitive와 객체의 비교 의미를 혼동하지 않는가?

**직접 작성한 예시**

```java
boolean sameId = firstId == secondId;
```

**적용 설명:** primitive long 비교의 공백 예다. Long 래퍼 객체의 값 비교에는 ==를 그대로 쓰지 않는다.

## 구체적인 검토 사례

- [ ] ID 비교식의 == 연산자 앞뒤 공백을 맞춰 코드 컨벤션을 지키도록 제안한다. (개선 제안)
  - 조건: 제안은 비교 방식 변경이 아니라 공백 형식 수정이다. 작성자는 컨벤션 확인을 놓쳤다며 수정하겠다고 답했다.

- [ ] 앞선 if 분기에서 반환하므로 else 문 없이도 동작을 유지할 수 있다는 조건문 단순화 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 else가 없어도 동작에 문제가 없어 보인다고 제안했고 작성자는 이에 동의했다. 작성자의 답변에 실제 수정 완료 보고는 없다.

- [ ] 구분자 개수에 따른 경우가 두 가지뿐이라면 두 번째 if문을 없애 분기를 단순화할 수 있다. (조건부 제안)
  - 조건: delimiterCount가 0 이하일 가능성이 없고 두 가지 경우만 존재한다는 가정 아래 제안한 구조다. 그 가정의 성립 여부는 확인되지 않았다.
