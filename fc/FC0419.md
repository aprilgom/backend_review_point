# FC0419 · 여러 검증이 나열된 테스트에서 assertAll 같은 방식을 활용하자고 제안했다.

[소속 분야: 테스트 대상·검증](../21-test-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0420](FC0420.md) · [다음 FC: FC0400 →](FC0400.md)

- [ ] 여러 검증이 나열된 테스트에서 assertAll 같은 방식을 활용하자고 제안했다. (개선 제안)
  - 조건: 구체적인 적용 범위나 변경 결과는 설명되지 않았다.

- [ ] 테스트의 여러 검증문을 assertAll()로 묶어보자고 제안했다. (개선 제안)
  - 조건: 검증 대상이나 기대값의 오류를 지적한 것은 아니며, 검증문 구성 방식에 대한 제안이다.

- [ ] 테스트의 여러 검증문을 assertAll이나 assertSoftly로 묶는 방안을 제안했다. (개선 제안)
  - 조건: 대상 코드는 실행 결과의 뷰 타입과 기대 객체와의 동등성을 각각 검증한다. 제안의 구체적인 이유나 작성자의 답변은 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
assertAll(
    () -> assertEquals("reader", user.name()),
    () -> assertTrue(user.isActive()));
```

**적용 설명:** 관련 속성을 함께 보고 싶을 때 JUnit assertAll을 사용한다. 독립적인 시나리오까지 하나의 거대한 테스트로 합치지 않는다.
