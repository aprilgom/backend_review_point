# FC0332 · 검증 불변식의 구체적 명명

## 검토 질문

- [ ] 검증 호출부에서 어떤 불변식을 확인하는지 이름만으로 파악할 수 있는가?

**직접 작성한 예시**

```java
validateDistinctEndpoints(startId, endId);
validatePositiveDistance(distance);
```

**적용 설명:** 검증할 불변식을 이름으로 나누어 호출부에서도 확인하게 한다.

## 구체적인 검토 사례

- [ ] validate라는 이름만으로는 검증 대상을 알기 어려우므로 무엇을 검증하는 메서드인지 드러내자고 제안했다. (개선 제안)
  - 조건: 원문 맥락 확인

- [ ] 테이블 검증에서 스트림 내부에서 예외를 던지는 대신, anyMatch로 위반 여부를 구한 뒤 별도 if문에서 예외를 던지는 형태를 제안했다. (개선 제안)
  - 조건: 제시한 코드는 비어 있지 않거나 이미 그룹화된 테이블이 있는지를 boolean 변수에 담아 검사한다. 첨부 이미지의 내용은 확인 근거로 사용하지 않았으며, 코드 제안 자체에서 관심사를 확인했다.

- [ ] validateResultSize라는 이름에 결과 개수가 정확히 1개인지 검증한다는 책임이 드러나도록 validateResultSizeSingle처럼 구체화할 것을 제안했다. (개선 제안)
  - 조건: 참여자는 기존 이름만으로 검증 기준을 알기 어려워 구현을 확인해야 했다고 설명했다. 작성자는 더 명확한 이름으로 바꾸었다고 보고했지만, 실제 변경된 이름은 이 대화에 제시되지 않았다.
