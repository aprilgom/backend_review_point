# FC0269 · rowsExpected로 ArrayList의 초기 용량을 설정한 목적이 최적화인지, 그렇다면 어떤 근거로 작성했는지 질문했다.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0279](FC0279.md) · [다음 FC: FC0273 →](FC0273.md)

- [ ] rowsExpected로 ArrayList의 초기 용량을 설정한 목적이 최적화인지, 그렇다면 어떤 근거로 작성했는지 질문했다. (설계 질문)
  - 조건: 리뷰어는 최적화 효과가 있는지 확신하지 못한다고 밝혔다. 최적화가 목적이라는 조건하에 이유를 요청했으며, 효과가 없다고 확정하지 않았다.

- [ ] 구간 병합 과정에서 values.indexOf(section)을 불필요하게 두 번 호출하고 있다는 지적이다. (문제 보고)
  - 조건: 작성자는 findNextSection이 Section 대신 이미 구한 index를 받도록 수정했다고 보고했다. 실제 변경 결과나 성능 효과는 별도로 확인되지 않았다.

- [ ] 문자열을 RequestMethod로 변환할 때 valueOf와 switch-case의 성능 차이를 참고해 볼 수 있다는 의견을 남겼다. (의견)
  - 조건: 리뷰 참여자는 스프링이 switch-case를 사용한다고 설명하며 요청 앞단의 성능을 높이려는 선택일 수 있다고 추측했다. 선택적으로 읽을 자료를 공유한 것이며 변경 요구나 측정에 근거한 성능 결함 보고는 아니다. 외부 링크의 내용과 실제 성능 차이는 이 입력에서 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
List<Row> rows = new ArrayList<>(expectedRows);
```

**적용 설명:** 초기 용량은 크기와 다르다. 과도한 예상치는 메모리를 낭비하므로 실제 분포를 근거로 사용한다.
