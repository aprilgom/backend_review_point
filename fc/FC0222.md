# FC0222 · @NotBlank의 검증 구현이 null도 검사하므로 함께 사용한 @NotNull은 생략할 수 있다는 의견을 제시한다.

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0221](FC0221.md) · [다음 FC: FC0218 →](FC0218.md)

- [ ] @NotBlank의 검증 구현이 null도 검사하므로 함께 사용한 @NotNull은 생략할 수 있다는 의견을 제시한다. (개선 제안)
  - 조건: 리뷰 참여자는 자신이 알고 있는 구현 동작을 근거로 제안하면서 참고만 해 달라고 명시했다. 필수 변경 요구가 아니며, 실제 어노테이션 제거 여부는 확인되지 않는다.

- [ ] @NotNull, @NotEmpty, @NotBlank의 검증 조건 차이를 설명하도록 질문한다. (설계 질문)
  - 조건: 작성자는 null, 빈 문자열, 공백 문자열의 허용 여부 차이를 설명하고, 프로그램에서 문자열의 빈값을 받지 않으려는 의도로 @NotBlank로 수정했다고 답했다. 특정 애너테이션 사용을 처음부터 요구한 지적으로 확대하지 않는다.

- [ ] 문자열 orderId의 검증에 @NotNull 외에 @NotEmpty나 @NotBlank도 사용해볼 수 있다고 제안했다. (개선 제안)
  - 조건: 문자열 입력이라는 조건에서 제시한 검증 선택지이며, 특정 애노테이션을 반드시 사용하라는 요구는 아니다. 작성자는 수정했다고 답했지만 어떤 애노테이션을 선택했는지는 답변에 명시하지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record Form(@jakarta.validation.constraints.NotBlank String title) {}
```

**적용 설명:** NotBlank는 null과 공백 문자열을 모두 거절한다. 검증 그룹·메시지를 별도로 쓰는 경우까지 동일한지는 확인한다.
