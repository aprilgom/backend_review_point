# FC0176 · 실행 환경의 실제 저장 구현

## 검토 질문

- [ ] 운영·개발·테스트에서 선택한 저장 구현이 영속성 요구와 일치하는가?

**직접 작성한 예시**

```java
Users users = config.production()
    ? new SqlUsers(dataSource)
    : new MemoryUsers();
```

**적용 설명:** 실제 실행 환경의 저장 구현을 확인한다. 재시작 후 데이터 보존 요구와 개발·테스트 구성을 구분한다.

## 구체적인 검토 사례

- [ ] 애플리케이션에서도 InMemoryUserRepository 대신 DB에 연결된 UserDao를 사용하도록 바꾸는 것을 제안한다. (개선 제안)
  - 조건: 작성자는 UserService가 UserDao를 가지고 있으므로 컨트롤러에 InMemoryUserRepository 대신 UserService를 주입하도록 수정했다고 보고했다. 이후 승인은 실제 의존성 교체나 동작 검증의 근거로 간주하지 않는다.

- [ ] 구현한 UserDao를 컨트롤러에서 InMemoryUserRepository 대신 사용하도록 바꾸자고 제안했다. (개선 제안)
  - 조건: 작성자는 기존 컨트롤러들을 변경했다고 보고했다. 단일 UserDao의 자동 주입은 미션 외 구현 부담 때문에 보류하고 각 컨트롤러에서 생성하도록 했다는 설명은 작성자의 선택이며, 리뷰어가 싱글턴이나 자동 주입을 요구한 것은 아니다.

- [ ] 기존 Controller에서 사용하는 InMemory 구현을 새로 만든 UserDao로 교체해 볼 것을 제안했다. (개선 제안)
  - 조건: 작성자는 피드백을 전부 반영했다고 포괄적으로 보고했으나, 이 교체의 구체적인 구현 결과를 별도로 설명하지는 않았다.
