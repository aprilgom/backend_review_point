# FC0274 · 장바구니 항목을 순회하며 상품을 개별 조회하는 쿼리를 한 번의 조회로 줄이는 방식을 제안했다.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0270](FC0270.md) · [다음 FC: FC0292 →](FC0292.md)

- [ ] 장바구니 항목을 순회하며 상품을 개별 조회하는 쿼리를 한 번의 조회로 줄이는 방식을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 반복 조회 횟수 감소를 제안했으며, 구체적인 쿼리 구현이나 성능 측정 결과는 제시하지 않았다.

- [ ] 상품 존재 여부를 조회한 뒤 수정하는 과정의 DB 접근을 한 번으로 줄일 수 있는지 검토를 요청했다. (설계 질문)
  - 조건: 리뷰 참여자는 조회와 수정에서 각각 DB 커넥션이 이루어진다고 설명했다. 작성자는 수정된 행 수로 성공 여부를 판단하고 예외를 던지도록 변경했다고 보고했으며, 실제 변경 결과는 이 대화만으로 확인되지 않는다.

- [ ] 상품 존재 확인을 위한 추가 조회의 성능 영향은 있을 수 있지만 대개 크게 작용하지는 않을 것이라는 의견이다. (의견)
  - 조건: 작성자가 사전 조회와 변경으로 두 번의 쿼리가 실행되며 규모가 커지면 성능에 영향을 줄 수 있다고 우려하자, 리뷰 참여자가 제시한 의견이다. 측정 근거는 없고 성능 영향이 없다고 단정하지도 않았으며, 최종 선택에는 상품 부재 응답에 대한 협업 요구를 고려하라고 했다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Map<ProductId, Product> productsById = products.findAllByIds(ids).stream()
    .collect(Collectors.toMap(Product::id, Function.identity()));
```

**적용 설명:** 여러 상품을 일괄 조회한다. 부재 ID·중복 요청·파라미터 개수 제한을 처리한다.
