# FC0141 · @ManyToOne의 fetch를 LAZY로 선택한 이유와 기본값이 EAGER인 이유를 질문했다.

[소속 분야: 데이터 관계·영속성](../08-persistence.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0140](FC0140.md) · [다음 FC: FC0142 →](FC0142.md)

- [ ] @ManyToOne의 fetch를 LAZY로 선택한 이유와 기본값이 EAGER인 이유를 질문했다. (설계 질문)
  - 조건: 선택한 로딩 전략과 기본 로딩 전략의 근거를 묻는 질문이며, 어느 전략이 이 코드에 적합한지에 대한 답변이나 결론은 없다.

- [ ] @ManyToOne의 fetch를 LAZY로 선택한 이유와 기본값이 EAGER인 이유를 설명하도록 묻는다. (설계 질문)
  - 조건: 연관관계 로딩 전략의 선택 근거와 기본 동작에 관한 질문이다. LAZY 설정이 잘못되었다는 지적이나 성능 문제의 확인은 없다.

- [ ] @ManyToOne 연관관계의 FetchType을 EAGER로 둔 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 FetchType을 고려하지 않아 따로 설정하지 않았고 기본값이 EAGER라는 사실도 몰랐다고 답했다. 이어 EAGER와 LAZY에 관해 학습한 내용을 설명했으나, 이를 리뷰 참여자가 LAZY를 의무화한 것으로 해석하거나 실제 설정 변경이 확인된 것으로 보지는 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@ManyToOne(fetch = FetchType.LAZY)
private Team team;
```

**적용 설명:** 지연 로딩의 필요성과 실제 제공자 동작을 확인한다. 접근 시 추가 쿼리와 영속성 컨텍스트 밖 접근 문제도 검증한다.
