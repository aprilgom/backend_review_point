# FC0187 · RedisSerializer 구현체 중 GenericJackson2JsonRedisSerializer를 선택한 이유를 묻고, JdkSerializationRedisSerializer와의 차이와 절충점을 검토한다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0190](FC0190.md) · [다음 FC: FC0168 →](FC0168.md)

- [ ] RedisSerializer 구현체 중 GenericJackson2JsonRedisSerializer를 선택한 이유를 묻고, JdkSerializationRedisSerializer와의 차이와 절충점을 검토한다. (토론)
  - 조건: 리뷰 참여자는 선택 이유가 따로 없다면 두 구현체의 차이를 학습해 보라고 제안했다. 작성자는 JDK 직렬화의 Serializable 요구와 버전 관련 제약, Generic Jackson의 클래스 정보 및 애플리케이션 간 호환성 문제, 타입 지정 Jackson 구현체의 제약을 학습 내용으로 설명했다. 후속으로 리뷰 참여자는 JDK 방식의 다른 언어와의 낮은 호환성 및 텍스트 기반 Jackson 방식의 데이터 크기 단점을 설명했고 작성자는 이를 새로 배웠다고 답했다. 이러한 비교는 참여자들의 설명으로 보존하며, 실제 데이터 크기 측정이나 구현체 변경 결과는 제시되지 않았다.

- [ ] API 문서화 기술로 Spring REST Docs 대신 springdoc을 선택한 근거를 질문했다. (설계 질문)
  - 조건: 작성자는 Swagger 사용 경험을 활용해 문서화를 빠르게 적용하고 결제 설계 리뷰에 시간을 투자하려 했다고 설명했다. 두 기술의 장단점을 충분히 비교하지 못했다고 인정하며 추후 학습 의사를 밝혔지만, 리뷰 참여자가 REST Docs 사용을 요구한 것은 아니다.

- [ ] 노선 탐색과 관련 없는 Sections가 그래프 라이브러리에 의존할 필요가 있는지 질문한다. (설계 질문)
  - 조건: 리뷰어는 Sections가 WeightedMultigraph를 받는 메서드를 가진 상황에서 의존성의 필요성을 물었다. 작성자의 설명이나 변경 결과는 제공되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
byte[] encoded = codec.encode(new CacheEntry(1, payload));
CacheEntry decoded = codec.decode(encoded);
```

**적용 설명:** 가상 코덱에 스키마 버전을 포함한 예다. JSON과 Java 직렬화를 호환성·크기·타입 정보·안전성으로 비교하고 신뢰하지 않는 역직렬화를 제한한다.
