# FC0187 · 캐시 직렬화 형식의 선택

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0190](FC0190.md) · [다음 FC: FC0168 →](FC0168.md)

## 검토 질문

- [ ] 직렬화 형식을 크기·호환성·타입 정보·안전성으로 비교하고 스키마 변경을 처리하는가?

**직접 작성한 예시**

```java
byte[] encoded = codec.encode(new CacheEntry(1, payload));
CacheEntry decoded = codec.decode(encoded);
```

**적용 설명:** 가상 코덱에 스키마 버전을 포함한 예다. JSON과 Java 직렬화를 호환성·크기·타입 정보·안전성으로 비교하고 신뢰하지 않는 역직렬화를 제한한다.

## 구체적인 검토 사례

- [ ] **상황:** 캐시에 타입 메타데이터를 그대로 저장한다.
  - **판단 기준:** 역직렬화 안전성과 버전 호환성을 검토한다.

- [ ] **상황:** 모델 변경 후 이전 캐시를 읽지 못한다.
  - **판단 기준:** 스키마 버전·무효화·이행 정책을 마련한다.
