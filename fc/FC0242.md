# FC0242 · 예외 변환과 원인 보존

## 검토 질문

- [ ] 기술 예외를 상위 계약으로 바꾸는 이유가 명확하고 원인·맥락을 잃지 않는가?

**직접 작성한 예시**

```java
catch (SQLException failure) {
    throw new StorageFailure("저장 작업 실패", failure);
}
```

**적용 설명:** 저장 기술 예외를 계약에 맞는 unchecked 예외로 바꾸되 원인은 보존한다. 재시도 가능 여부는 별도 판단한다.

## 구체적인 검토 사례

- [ ] **상황:** 기술 예외를 원인 없이 새 예외로 바꾼다.
  - **판단 기준:** 원인과 진단 맥락을 보존한다.

- [ ] **상황:** 모든 예외를 unchecked로 바꾸면 해결된다고 본다.
  - **판단 기준:** 호출자의 복구·전파 계약을 먼저 정한다.
