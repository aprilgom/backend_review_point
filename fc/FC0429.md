# FC0429 · 테스트 환경 설정의 분리

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0427](FC0427.md) · [다음 FC: FC0439 →](FC0439.md)

## 검토 질문

- [ ] 테스트용 리소스와 프로파일의 역할을 구분하고 실제 로딩 우선순위가 운영 설정과 격리되는가?

**직접 작성한 예시**

```properties
# 테스트 전용 설정 파일 예
db.name=isolated_test
mail.delivery=record-only
```

**적용 설명:** 테스트 리소스만으로 환경을 분리할 수 있는지 검토한다. 애플리케이션이 실제로 읽는 키와 우선순위를 맞춘다.

## 구체적인 검토 사례

**혼합·경계:** Spring 테스트 리소스 관례 외에 환경별 설정 관리가 포함됨.

- [ ] 테스트 설정을 위해 별도 프로필이 필요한지, 테스트 모듈의 properties만으로 해결할 수 없는지 검토한다. (설계 질문)
  - 조건: 리뷰어는 현재 테스트에서 프로필 개념이 당장 필요해 보이지 않는다고 질문했다. 작성자는 properties를 삭제하고 각 테스트 클래스에 설정을 직접 선언했다고 보고했으며, 이는 리뷰어가 제시한 테스트 모듈 properties 방식과는 구분된다.

- [ ] 테스트 설정은 test.resources 아래 application.properties로 두는 통상적인 방식도 있다고 안내했다. (개선 제안)
  - 조건: 현재 application-test.properties 방식도 허용한다고 명시했다. application-{profile}.properties는 보통 운영·테스트 서버 등 서비스 환경별 설정 구분에 사용한다는 설명이며, 현재 설정을 결함으로 지적한 것은 아니다.

- [ ] 마무리 전에 테스트를 확인하고, 환경변수를 추가할 때 테스트용 properties 파일에도 해당 설정을 함께 챙기도록 요청했다. (개선 제안)
  - 조건: 환경변수 추가 시 테스트 설정도 함께 관리하라는 조건부 요청이다. 같은 댓글의 승인과 단계 마무리 안내는 테스트 통과나 설정 반영 완료의 증거가 아니다. 별도 타임아웃 댓글을 확인하라는 안내만으로 그 스레드의 구체적인 내용을 추가 추출하지 않는다.
