# FC0422 · 테스트 데이터 때문에 단건 조회 결과가 여러 개 나오는 문제는 테스트 코드를 수정하는 방향으로 해결하도록 제안했다.

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0426](FC0426.md) · [다음 FC: FC0428 →](FC0428.md)

- [ ] 테스트 데이터 때문에 단건 조회 결과가 여러 개 나오는 문제는 테스트 코드를 수정하는 방향으로 해결하도록 제안했다. (개선 제안)
  - 조건: 댓글 0의 중복 데이터와 검사 조건 완화 사유는 리뷰어가 인용한 작성자 설명이다. 직접적인 리뷰 근거는 댓글 2의 테스트 수정 제안이며, 구체적인 데이터 격리 방법이나 수정 결과는 이 스레드에 제시되지 않았다.

- [ ] 테스트에서 반복해서 사용하는 동일한 요청 데이터를 공통으로 사용할 수 있도록 추상화하거나 분리할 것을 제안한다. (개선 제안)
  - 조건: 작성자는 테스트 데이터를 test/resource 폴더로 분리하고, 데이터를 읽어 HttpRequest를 만드는 부분을 추상 클래스로 구현했다고 답했다. 구체적인 분리 방식은 작성자가 보고한 선택이다.

- [ ] 테스트의 조건이 되는 준비 코드를 해당 테스트 안에 두어 조건과 검증이 분리되지 않도록 하는 것을 제안했다. (개선 제안)
  - 조건: 리뷰어는 응집되지 않은 테스트 조건이 간혹 False Negative를 유발한다고 설명했다. 작성자는 beanScopeTest가 공통 setup에서 만든 beanDefinitions를 검증하는 구조였다고 답하고, 스캔 범위는 다른 테스트에서 이미 검증하므로 해당 테스트를 삭제했다고 보고했다. 첨부 링크의 내용은 별도 근거로 사용하지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
String uniqueName = "case-" + UUID.randomUUID();
users.insert(new User(uniqueName));
assertTrue(users.findByName(uniqueName).isPresent());
```

**적용 설명:** 중복된 테스트 데이터로 단건 계약을 깨지 않는다. 무작위 이름만으로 완전한 격리가 되는 것은 아니므로 데이터 정리도 필요하다.
