# FC0073 · 스키마 검증과 자동 변경의 선택

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0095](FC0095.md) · [다음 FC: FC0080 →](FC0080.md)

## 검토 질문

- [ ] 실행 시 스키마를 검증할지 자동 변경할지 환경별 요구와 데이터 보존 관점에서 결정했는가?

**직접 작성한 예시**

```properties
hibernate.hbm2ddl.auto=validate
```

**적용 설명:** Hibernate가 스키마를 검증하도록 한 예다. 스키마 변경은 별도 마이그레이션으로 적용하며 update와의 운영상 차이를 설명할 수 있어야 한다.

## 구체적인 검토 사례

- [ ] ddl-auto를 update로 설정할 수도 있는데 validate를 선택한 이유가 무엇인지 묻는다. (설계 질문)
  - 조건: 작성자는 처음에 update와 validate의 동작 차이를 설명했다. 이후 설정 위치를 잘못 지정하여 실제로는 create-drop이 적용되고 있었다고 보고하고, 개발 환경에는 update가 맞다고 판단해 설정을 수정했다고 밝혔다. 실제 적용값과 수정 결과는 작성자의 보고이며, 리뷰 참여자가 update 사용을 강제한 것은 아니다.

- [ ] JPA의 자동 스키마 생성을 비활성화한 이유를 질문했다. (설계 질문)
  - 조건: 리뷰어는 ddl-auto를 false로 표현했으나 제시된 설정은 none이다. 작성자는 schema.sql로 스키마를 명시적으로 관리하고 JPA가 테이블을 생성하거나 수정하지 않도록 하기 위한 선택이라고 설명했다.

- [ ] 로컬에서 assert가 동작하지 않는다며 단언문을 동작시키는 방법을 질문했다. (설계 질문)
  - 조건: 참여자는 AssertionError 대신 url.getFile()에서 NullPointerException이 발생했다고 보고했다. 작성자는 동작하지 않는 이유를 모르겠다며 확인 방법을 되물었다. 활성화 방법에 대한 답은 이 대화에 없다.
