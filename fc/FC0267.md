# FC0267 · `Arrays.asList(mappings)`를 세 번 생성하지 말고 한 번 만든 변수를 재사용할 것을 제안했다.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0276](FC0276.md) · [다음 FC: FC0280 →](FC0280.md)

- [ ] `Arrays.asList(mappings)`를 세 번 생성하지 말고 한 번 만든 변수를 재사용할 것을 제안했다. (개선 제안)
  - 조건: 불필요한 반복 생성을 지적한 것으로, 성능 측정 결과는 제시되지 않았다.

- [ ] 반복문에서 자동차마다 개별 INSERT를 실행하는 대신 배치 삽입을 사용해 데이터베이스 호출 부담을 줄이는 방향을 제안했다. (개선 제안)
  - 조건: 리뷰어는 여러 INSERT와 DB 커넥션 부담을 근거로 JDBC의 batchUpdate를 예로 들었다. 작성자는 SimpleJdbcInsert의 executeBatch를 사용하도록 변경했다고 보고했으나, 실제 쿼리 수나 커넥션 사용량 및 성능 개선 효과를 측정한 근거는 없다.

- [ ] 삭제 후 두 구간을 추가하는 방식을 유지한다면 개별 insert 대신 bulk 삽입을 고려할 수 있지 않은지 묻는다. (조건부 제안)
  - 조건: 삭제 후 재삽입 방식을 사용하는 경우에 한정한 제안이다. 작성자의 수정 보고만으로 bulk 삽입을 적용했다고 판단할 수 없으며 성능 측정 결과도 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
List<Mapping> mappingList = Arrays.asList(mappings);
validate(mappingList);
register(mappingList);
```

**적용 설명:** 반복 생성 대신 한 번 만든 뷰를 재사용한다. Arrays.asList는 배열 변경과 연결되고 크기 변경이 제한된다.
