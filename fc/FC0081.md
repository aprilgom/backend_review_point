# FC0081 · 버전을 명시해 추가하는 라이브러리는 해당 버전이 최신인지 확인해 보면 좋겠다고 제안했다.

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0084](FC0084.md) · [다음 FC: FC0095 →](FC0095.md)

- [ ] 버전을 명시해 추가하는 라이브러리는 해당 버전이 최신인지 확인해 보면 좋겠다고 제안했다. (개선 제안)
  - 조건: 작성자는 jjwt에 더 최신 버전이 있음을 알지만 사용 빈도와 안정성을 이유로 0.9.1을 선택했다고 설명했다. jaxb-api 2.3.1도 안정성을 이유로 선택했으며, 취약점 대비와 업데이트에 따른 호환성 변경 사이에서 고민한다고 답했다. 리뷰어는 최신 버전 사용을 의무화하거나 선택한 버전에 결함이 있다고 단정하지 않았다.

- [ ] Spring Boot 의존성 선언에서 버전을 생략했을 때 어떤 버전이 선택되는지 확인하도록 제안했다. (개선 제안)
  - 조건: 작성자는 처음에 mavenCentral의 최신 버전이 적용된다고 설명했다. 리뷰어는 Spring Boot가 관리하는 의존성은 현재 Boot 버전에 맞는 버전으로 매핑된다고 정정했고, 작성자는 이를 이해했다고 답했다. 최신 버전 자동 적용이라는 초기 설명을 결론으로 채택하지 않는다.

- [ ] sourceCompatibility는 Java 1.8인데 subway 테스트에서 더 높은 버전의 기능을 사용하고 있다고 지적하며 전체 테스트 실행으로 이상 여부를 확인하도록 요청했다. (위험 지적)
  - 조건: 리뷰 참여자는 인자 없는 orElseThrow() 사용을 예로 들었다. 실제 빌드 또는 테스트 실패 결과는 제시되지 않았으며, 전체 테스트 실행 결과도 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```sh
./gradlew dependencyInsight --dependency jackson-core --configuration runtimeClasspath
```

**적용 설명:** 선언 버전과 실제 선택 버전·충돌 원인을 확인하는 예시다. 최신 여부만으로 변경하지 않고 호환성과 필요한 기능을 검토한다.
