## 검토 질문

- [ ] 타입 이름에서 요청·응답 방향과 생성·수정 등의 목적을 구분할 수 있는가?

**직접 작성한 예시**

```java
record CreateTaskRequest(String title, LocalDate dueDate) {}
```

**적용 설명:** 요청 방향과 사용 목적을 이름에 포함한다. 수정 요청과 계약이 같다면 과도한 타입 분리는 피한다.

## 구체적인 검토 사례

- [ ] **상황:** DTO 이름에서 방향과 용도를 알 수 없다.
  - **판단 기준:** 요청·응답과 작업 목적을 드러낸다.

- [ ] **상황:** 계약이 같은데 작업명마다 복제한다.
  - **판단 기준:** 명명과 타입 분리의 필요는 별도로 판단한다.
