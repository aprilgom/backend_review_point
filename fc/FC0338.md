# FC0338 · 미션에서 요구하는 Google Java Style Guide에 맞춰 wildcard import를 피하고 명시적인 import를 사용한다.

[소속 분야: 가독성·명명](../17-readability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0333](FC0333.md) · [다음 FC: FC0342 →](FC0342.md)

- [ ] 미션에서 요구하는 Google Java Style Guide에 맞춰 wildcard import를 피하고 명시적인 import를 사용한다. (학습 제약)
  - 조건: 리뷰 참여자는 해당 스타일을 지키는 협업자와 작업할 때 불필요한 변경이 반복될 수 있다는 이유를 덧붙였다. 작성자는 요구사항을 놓쳤다고 인정하고 전체 wildcard import를 정리하겠다고 답했으나, 완료 여부는 확인되지 않는다.

- [ ] 여러 결제 기능을 담당할 수 있는 서비스라면 이름을 PaymentApprovalService처럼 승인으로 한정하지 않아도 좋겠다고 제안했다. (개선 제안)
  - 조건: 작성자는 PG사별로 다른 승인 로직을 유즈케이스 수준에서 분리한 이름이라고 설명했다. 저장·조회는 공통 서비스로 두고, 향후 통합 결제 흐름을 담당하는 PaymentService가 승인 서비스를 내부 구성 요소로 사용하게 할 계획이라고 답했다. 이러한 책임 분리 계획은 작성자의 설명이며, 명칭 변경 결과는 제시되지 않았다.

- [ ] import에서 와일드카드 사용을 지양하는 것을 제안한다. (개선 제안)
  - 조건: 와일드카드 import를 피하자는 제안이며, 구체적인 오동작이나 변경 결과는 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
import java.util.ArrayList;
import java.util.List;
```

**적용 설명:** 명시적 import를 요구하는 스타일 규칙의 예다. 학습 제약을 모든 프로젝트의 필수 규칙으로 확대하지 않는다.
