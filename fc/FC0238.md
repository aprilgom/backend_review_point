# FC0238 · 공백 입력과 정규화

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0237](FC0237.md) · [다음 FC: FC0239 →](FC0239.md)

## 검토 질문

- [ ] 빈 문자열뿐 아니라 공백만 있는 입력을 처리하고 정규화 전후 검증 순서를 정했는가?

**직접 작성한 예시**

```java
if (raw == null || raw.isBlank()) throw new MissingTitle();
String title = raw.strip();
```

**적용 설명:** 빈 문자열과 공백만 있는 입력을 모두 다룬다. Unicode 공백의 허용 범위도 요구에 따라 검토한다.

## 구체적인 검토 사례

- [ ] 문자열 입력이 공백으로만 이루어진 경우도 검증해야 하지 않는지 묻는다. (설계 질문)
  - 조건: 검토 대상에는 @NotEmpty가 사용되어 있다. 작성자는 @NotBlank를 사용하면 공백도 검증할 수 있겠다고 답했으나, 실제 적용이나 검증 결과는 제시되지 않았다.

- [ ] 클라이언트가 공백만으로 이루어진 문자열을 요청할 때도 입력 검증이 이루어지는지 질문했다. (설계 질문)
  - 조건: 작성자는 @NotNull로는 공백 문자열을 막지 못한다고 이해하고 @NotBlank로 수정했다고 보고했다. 질문을 재현된 결함으로 단정하거나 수정 결과를 별도로 확인한 것은 아니다.

- [ ] 방 이름과 비밀번호를 입력하지 않아도 방이 생성되는 문제를 지적했다. (문제 보고)
  - 조건: 리뷰어가 보고한 입력 검증 문제이며, 작성자 답변이나 수정 결과는 제공되지 않았다.
