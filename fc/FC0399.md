# FC0399 · 로직을 검증하는 테스트가 없으므로 테스트를 추가하면 좋겠다고 제안했다.

[소속 분야: 테스트 대상·검증](../21-test-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0402](FC0402.md) · [다음 FC: FC0407 →](FC0407.md)

- [ ] 로직을 검증하는 테스트가 없으므로 테스트를 추가하면 좋겠다고 제안했다. (개선 제안)
  - 조건: 사람 참여자 pika96가 직접 제기한 관심사다. 코드를 받아 실행했을 때 잘 동작했다고 평가하면서도 로직 테스트의 부재를 별도로 언급했다. 테스트 대상과 검증 사례는 구체화하지 않았으며, 봇의 커버리지 수치나 승인을 테스트 추가의 증거로 사용하지 않는다.

- [ ] 작성한 검증 로직에 대한 테스트를 추가하자는 제안이다. (개선 제안)
  - 조건: 작성자는 다음 단계에서 추가하겠다고 답했으며, 이 대화에는 테스트 구현 결과가 제시되지 않았다.

- [ ] Service의 비즈니스 로직 검증과 전체 연동 검증의 목적을 구분하여 Controller와 Service의 테스트 수준을 정할 기준을 세워보도록 제안한다. (토론)
  - 조건: 리뷰 참여자는 유지관리 부담 때문에 두 계층 중 한 곳에서 SpringBootTest를 수행하며, 개인적으로 Service는 mock 테스트, Controller는 통합 테스트를 선호한다고 설명했다. 작성자는 현재는 Service 통합 테스트와 Controller 슬라이스 테스트를 사용하지만 다음에는 제안한 방향을 택하고 싶다고 답했다. 현재 구성이 결함이라고 확정하거나 변경을 의무화한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
assertEquals(0, discount.apply(0));
assertEquals(90, discount.apply(100));
```

**적용 설명:** 계산 정책의 정상·경계 동작을 직접 검증하는 예다. 숫자는 이 가상 10% 정책에 한정된다.
