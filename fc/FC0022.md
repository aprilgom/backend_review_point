# FC0022 · 불필요한 위임 래퍼의 제거

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0024](FC0024.md)

## 검토 질문

- [ ] 기존 API를 그대로 전달하는 래퍼가 소유권·검증·공통 정책 등 실제 책임을 추가하는가?

**직접 작성한 예시**

```java
connection.setAutoCommit(false);
try { write(connection); connection.commit(); }
catch (SQLException failure) { connection.rollback(); throw failure; }
```

**적용 설명:** 직접 호출로도 흐름이 충분히 보이는지 비교하는 조각이다. 전용 커넥션을 소유한 범위라는 전제이며 복원·해제와 롤백 실패 처리는 별도 필요하다.

## 구체적인 검토 사례

- [ ] **상황:** 래퍼가 자원 API를 그대로 전달한다.
  - **판단 기준:** 소유권이나 공통 정책을 추가하는지 확인한다.

- [ ] **상황:** 래퍼가 해제 책임을 감춘다.
  - **판단 기준:** 직접 호출보다 수명 계약을 더 명확히 해야 한다.
