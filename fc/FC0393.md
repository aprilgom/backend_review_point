# FC0393 · 저장한 User와 ID로 다시 조회한 객체의 동일성을 확인하는 테스트인지, 해당 검증의 의도가 무엇인지 설명을 요청했다.

[소속 분야: 테스트 대상·검증](../21-test-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0394](FC0394.md) · [다음 FC: FC0395 →](FC0395.md)

- [ ] 저장한 User와 ID로 다시 조회한 객체의 동일성을 확인하는 테스트인지, 해당 검증의 의도가 무엇인지 설명을 요청했다. (설계 질문)
  - 조건: 리뷰어가 테스트 의도를 이해하지 못했다고 밝힌 질문이며, 테스트가 잘못되었다거나 불필요하다고 확정한 것은 아니다. 답변은 제공되지 않았다.

- [ ] 상품 조회 테스트에서 응답 데이터를 검증하지 않으면 잘못된 데이터가 반환되어도 테스트가 통과하지 않는지 질문했다. (설계 질문)
  - 조건: 작성자는 서비스에 의존하지 않는 테스트를 위해 MockMvc를 사용해 보았다고 답하면서 사용 방식에 대한 불확실성을 표현했다. 응답값 검증이 실제로 추가되었는지는 이 답변만으로 확인할 수 없다.

- [ ] TableGroup 생성 테스트에서 생성된 TableGroup의 ID도 검증하면 좋겠다. (개선 제안)
  - 조건: 작성자는 ID 검증을 추가하겠다고 답했으며, 실제 반영 여부는 이 대화에서 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
User saved = users.save(new User("reader"));
User loaded = users.get(saved.id());
assertEquals(saved.id(), loaded.id());
assertEquals("reader", loaded.name());
```

**적용 설명:** 동일 인스턴스 여부가 아니라 저장·복원된 데이터 계약을 확인한다. assertSame이 필요한 테스트와 구분한다.
