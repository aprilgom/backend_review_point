# FC0217 · 도메인 생성 경계의 불변식

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0216](FC0216.md) · [다음 FC: FC0220 →](FC0220.md)

## 검토 질문

- [ ] HTTP 외의 생성 경로에서도 유효한 객체만 만들어지도록 도메인 자체에서 필요한 제약을 보장하는가?

**직접 작성한 예시**

```java
record Name(String value) {
    Name { if (value == null || value.isBlank()) throw new IllegalArgumentException(); }
}
```

**적용 설명:** HTTP 외의 생성 경로에서도 도메인 불변식이 유지되도록 한다.

## 구체적인 검토 사례

- [ ] 요청 객체뿐 아니라 도메인 객체에서도 값을 검증해야 하는지 검토하도록 질문했다. (설계 질문)
  - 조건: 레벨 1 미션에서 배운 내용을 떠올리도록 유도했다. 구체적인 도메인 검증 구현이나 이후 반영 결과는 제시되지 않았다.

- [ ] 요청 단계에서 검증한 값을 도메인 객체가 그대로 신뢰해도 되는지, 도메인 생성 시 검증을 생략해도 되는지 묻는다. (설계 질문)
  - 조건: 도메인 앞단이 달라질 수 있다는 조건에서 검증 신뢰 경계를 검토하는 질문이다. 현재 도메인 검증이 실제로 누락되었거나 결함이 발생했다고 단정하지 않는다.

- [ ] 컨트롤러에서 값을 검증했다는 이유로 도메인에서는 검증을 생략해도 되는지 질문했다. (설계 질문)
  - 조건: 작성자는 동일한 검증을 반복하라는 의미인지 추가 검증을 뜻하는지 되물었고, 이미 값 검증을 마친 것을 전제로 도메인을 사용했다고 설명했다. 필요한 검증의 구체적인 범위나 후속 결론은 제시되지 않았다.
