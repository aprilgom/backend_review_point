# FC0443 · 실행 중인 앱과 테스트의 격리

## 검토 질문

- [ ] 개발 서버가 떠 있어도 포트·DB·캐시 충돌 없이 테스트를 실행할 수 있는가?

**직접 작성한 예시**

```java
TestServer server = TestServer.startOnAvailablePort();
try { assertEquals(200, server.client().get("/health").status()); }
finally { server.close(); }
```

**적용 설명:** 개발 서버와 다른 포트를 확보하는 가상 도우미다. DB·캐시도 함께 격리해야 두 서버가 서로 영향을 주지 않는다.

## 구체적인 검토 사례

**혼합·경계:** 실행 중인 앱과 테스트의 격리 문제는 다른 프레임워크에도 적용 가능.

- [ ] 애플리케이션을 실행한 상태에서도 테스트를 실행할 수 있는지 확인하도록 질문했다. (설계 질문)
  - 조건: 작성자는 애플리케이션 실행 중 테스트가 동작하지 않았고, RANDOM_PORT 설정만 적용했을 때는 테스트 단독 실행이 실패했다고 설명했다. RestAssured가 여전히 8080 포트로 요청하던 부분을 랜덤 포트로 변경해 해결했다고 보고했으며, 실제 결과에 대한 별도 검증은 제시되지 않았다.

- [ ] 서버가 실행 중인 상태에서 테스트를 실행하면 어떤 일이 생기는지 확인하도록 질문한다. (설계 질문)
  - 조건: 작성자는 서버가 사용하는 8080 포트와 충돌해 테스트가 실패한다고 설명하고 RANDOM_PORT로 변경했다고 보고했다. 포트 충돌과 변경 결과는 작성자의 설명이며, 리뷰 참여자의 최초 발언은 발생 상황을 묻는 질문이다.

- [ ] 테스트가 동작하지 않는 문제를 우선 확인하도록 요청한다. (문제 보고)
  - 조건: 리뷰어는 테스트가 동작하지 않는다고 보고한 뒤, 후속 댓글에서 테스트 동작을 확인했다고 명시했다. 실패 원인과 수정 내용은 제공되지 않았으며, 후속 확인을 전체 테스트의 충분성이나 다른 코멘트의 해결 근거로 확대하지 않는다.
