# FC0011 · TEMPLATES_PATH 정의가 RequestDispatcher에도 중복되어 있다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0027](FC0027.md) · [다음 FC: FC0030 →](FC0030.md)

- [ ] TEMPLATES_PATH 정의가 RequestDispatcher에도 중복되어 있다. (관찰)
  - 조건: 작성자는 중복 제거를 잊고 있었다고 인정했다. 답변만으로 실제 중복 제거가 완료되었다고 확인할 수는 없다.

- [ ] View를 인터페이스에서 추상 클래스로 변경할 필요가 있었는지 묻는다. (설계 질문)
  - 조건: 변경의 필요성에 대한 질문이며, 추상 클래스 사용이 결함이라고 확정한 것은 아니다.

- [ ] 공통 상위 클래스인 QnaEntity를 구상 클래스로 만든 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 구상 클래스로 만든 것이 실수였으며 추상 클래스로 변경했다고 답했다. 변경 결과를 별도로 확인한 내용은 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
final class TemplatePaths {
    static final Path ROOT = Path.of("views");
    private TemplatePaths() {}
}
```

**적용 설명:** 같은 의미의 경로가 여러 곳에 흩어졌을 때 공유한다. 배포 환경마다 다르면 상수 대신 설정으로 주입한다.
