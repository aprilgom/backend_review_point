## 검토 질문

- [ ] 조회 메서드 이름에서 반환 대상과 수행 동작을 명확히 알 수 있는가?

**직접 작성한 예시**

```java
List<BookingReply> getBookings() { return bookings.list(); }
```

**적용 설명:** 조회 대상과 동작을 드러낸 메서드 이름이다.

## 구체적인 검토 사례

- [ ] 예약 조회 컨트롤러 메서드 이름을 getReservations처럼 동작이 명확하게 드러나도록 바꾸자는 제안이다. (개선 제안)
  - 조건: 작성자는 화면 반환 메서드인 AdminPageController#reservations와 이름이 겹쳐 혼동할 수 있다는 점에 동의하고 이름을 수정했다고 보고했다.

- [ ] 예약 시간 ID 목록을 담는 변수명을 foundReservations에서 reservationTimeIds로 바꾸는 코드를 제안했다. (개선 제안)
  - 조건: 설명 문장 없이 제시된 코드 제안에서 확인되는 명명 변경이다.

- [ ] 예약 생성 메서드 create를 wait와 대응되는 reserve 또는 reserveSuccess 같은 이름으로 바꾸자고 제안했다. (개선 제안)
  - 조건: 작성자는 wait 추가 시 이름 변경을 고려했으나 누락했다며 수정했다고 보고했다. 최종적으로 어떤 이름을 선택했는지는 이 대화만으로 확인되지 않는다.
