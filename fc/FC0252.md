# FC0252 · 정적 리소스 요청을 검증하고 올바르지 않은 경우 404를 응답하는 방안을 제안했다.

[소속 분야: 예외·실패 계약](../13-errors.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0249](FC0249.md) · [다음 FC: FC0245 →](FC0245.md)

- [ ] 정적 리소스 요청을 검증하고 올바르지 않은 경우 404를 응답하는 방안을 제안했다. (개선 제안)
  - 조건: 사람 참여자는 검증과 404 응답을 직접 제안했지만, '이 경우'가 가리키는 검증 범위를 구체적으로 구분하지 않았다. 따라서 봇이 열거한 확장자 문제와 경로 탐색 위험 전체를 사람의 지적으로 확장하지 않았다. 작성자는 확장자 구분자 index가 -1이면 예외를 던지도록 변경했다고 보고했으며, 실제 404 응답으로 이어지는지는 확인되지 않는다.

- [ ] 조회 대상 리소스가 없을 때 400 대신 404 Not Found로 응답하도록 예외 처리를 보완하자고 제안했다. (개선 제안)
  - 조건: 작성자가 404 처리의 의미를 묻자, 리뷰 참여자는 lines/1 조회 시 해당 ID의 노선이 없는 경우를 예로 설명했다. 실제 반영 여부는 대화에서 확인되지 않는다.

- [ ] 요청 경로를 찾지 못할 때는 404 응답을 반환하도록 하자는 의견을 제시했다. (개선 제안)
  - 조건: 경로를 찾지 못하는 경우에 적용되는 제안이다. 작성자는 에러 처리를 추가했다고 보고했지만 실제 응답 동작은 확인되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Path target = root.resolve(relative).normalize();
if (!target.startsWith(root) || !Files.isRegularFile(target)) return notFound();
```

**적용 설명:** root는 절대 정규화 경로라는 전제다. 심볼릭 링크 탈출까지 막으려면 실경로 확인과 링크 정책이 추가로 필요하다.
