# FC0247 · 단건 조회 결과가 없을 때 null을 반환하면 호출자에게 의도하지 않은 NullPointerException이 발생할 수 있으므로 다른 처리 방식을 검토하자고 제안했다.

[소속 분야: 예외·실패 계약](../13-errors.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0244](FC0244.md) · [다음 FC: FC0250 →](FC0250.md)

- [ ] 단건 조회 결과가 없을 때 null을 반환하면 호출자에게 의도하지 않은 NullPointerException이 발생할 수 있으므로 다른 처리 방식을 검토하자고 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 특정 대안을 지정하지 않았다. 작성자는 데이터가 반드시 존재해야 하는 상황이라고 판단하여, 결과가 없으면 예외를 던지도록 수정했다고 보고했다.

- [ ] 지원하지 않는 요청에 null을 반환하기보다 예외나 오류 응답으로 처리하는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 null이 응답으로 전달될 수 있음을 인정하고 수정을 예고한 뒤 관련 리팩터링 커밋을 공유했다. 예외와 오류 응답 중 어떤 방식으로 구현했는지는 확인되지 않는다.

- [ ] queryForObject의 조회 결과가 없을 때 null을 반환하는 이유를 묻고, 이 경우도 예외로 처리하는 것이 자연스럽지 않은지 제안했다. (토론)
  - 조건: 작성자는 조회 결과 부재에 대한 예외 처리는 서비스 로직의 선택이라고 생각했다고 설명했다. 다만 결과가 2개 이상이면 예외를 던지면서 0개이면 null을 반환하는 차이도 고민 중이며, 최종 결정이나 변경은 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
assertTrue(users.find(missingId).isEmpty());
```

**적용 설명:** Optional을 쓰는 저장소의 부재 동작 검증이다. 호출자가 get을 무조건 호출하지 않도록 사용부도 확인한다.
