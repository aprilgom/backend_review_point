# FC0296 · MenuProduct 생성 시 이미 조회한 Product를 가격 검증 과정에서 다시 조회할 필요가 있는지 검토해 달라는 질문이다.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0271](FC0271.md) · [다음 FC: FC0275 →](FC0275.md)

- [ ] MenuProduct 생성 시 이미 조회한 Product를 가격 검증 과정에서 다시 조회할 필요가 있는지 검토해 달라는 질문이다. (설계 질문)
  - 조건: 리뷰 참여자는 JPA가 추가 쿼리를 보내지는 않는다고 명시하면서도 중복 조회 호출의 필요성을 고민해 보자고 했다. 실제 추가 SQL이나 성능 저하가 발생했다는 지적은 아니다.

- [ ] 메뉴 저장 과정에서 MenuProduct INSERT 쿼리와 menu_id UPDATE 쿼리가 두 번씩 실행된다고 지적했다. (문제 보고)
  - 조건: 중복 쿼리 실행은 리뷰 참여자의 보고이며, 실행 로그나 원인 분석, 수정 결과는 대화에 없다.

- [ ] 생성자에서 모두 List를 받으므로 menuProducts 필드에 ArrayList를 미리 생성할 필요가 없어 보인다고 지적했다. (관찰)
  - 조건: 모든 생성자에서 목록을 전달받는다는 리뷰 참여자의 설명을 전제로 한 불필요한 초기 생성에 대한 의견이다. 성능 측정이나 전체 생성자 구현은 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Product product = products.get(id);
requireAllowedPrice(product.price());
return new MenuItem(product, quantity);
```

**적용 설명:** 이미 조회한 객체를 검증과 생성에 재사용한다. 최신 상태 재검증이 필요한 경우는 별개다.
