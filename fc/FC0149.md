# FC0149 · 컨트롤러 인스턴스를 매번 새로 생성해야 하는지 검토하고, 싱글턴으로 재사용하는 방식을 고려해볼 것을 제안했다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0146](FC0146.md) · [다음 FC: FC0155 →](FC0155.md)

- [ ] 컨트롤러 인스턴스를 매번 새로 생성해야 하는지 검토하고, 싱글턴으로 재사용하는 방식을 고려해볼 것을 제안했다. (개선 제안)
  - 조건: 리뷰어는 반드시 반영할 필요는 없는 고민거리라고 명시했다. 작성자는 생성 로직을 변경하겠다고 답했으며, 실제 변경 방식이나 결과는 이 대화에서 확인되지 않는다.

- [ ] 컨트롤러 등록 시 리플렉션으로 인스턴스를 다시 생성하지 말고 ControllerScanner가 생성하여 보관한 컨트롤러 인스턴스를 사용하도록 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 스캐너가 반환한 controllers 맵을 사용하지 않고 registerController()에서 객체를 새로 만드는 점을 지적했다. 작성자는 스캐너가 생성한 인스턴스를 사용하도록 수정했다고 보고했으며, 실제 반영 결과는 별도로 확인되지 않는다.

- [ ] 여러 HandlerExecution이 컨트롤러 인스턴스를 공유할지 별도로 가질지, 싱글톤이 적절한 조건을 검토해보도록 제안했다. (토론)
  - 조건: 현재 코드를 반드시 바꾸라는 요구가 아니라 선택적인 학습 리뷰라고 명시했다. 작성자는 상태가 없는 컨트롤러에는 공유의 이점이 있지만 상태가 있으면 의도하지 않은 결과가 생길 수 있다고 설명했다. 이 설명의 정확성이나 모든 상황에 대한 적용 가능성이 검증된 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
router.register("/tasks", new TaskController(service));
// 요청별 값은 컨트롤러 필드 대신 메서드 지역 변수로 둔다.
```

**적용 설명:** 공유 인스턴스를 재사용하려면 요청 간 가변 상태가 섞이지 않아야 한다.
