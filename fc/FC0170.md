# FC0170 · 도메인과 요청 DTO의 의존

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0165](FC0165.md) · [다음 FC: FC0157 →](FC0157.md)

## 검토 질문

- [ ] 요청 형식 변경이 도메인 모델까지 전파되지 않도록 입력 변환을 바깥 경계에 두었는가?

**직접 작성한 예시**

```java
Order order = new Order(new CustomerId(input.customerId()), toLines(input.lines()));
```

**적용 설명:** 요청 DTO 해석은 바깥에서 하고 도메인은 자신의 값 타입만 받는다.

## 구체적인 검토 사례

- [ ] 도메인 객체가 요청 DTO에 의존하면 DTO 변경이 도메인에도 영향을 줄 가능성이 있는데, 이 의존 관계가 적절한지 질문했다. (설계 질문)
  - 조건: Line이 LineRequest를 받는 생성자에 대한 변경 영향 우려이며, 실제 문제가 발생했다고 보고한 것은 아니다. 작성자는 변경하겠다고 답했으나 변경 결과는 확인되지 않는다.

- [ ] Line 도메인이 요청 DTO에 의존하기보다 DTO가 도메인에 의존하도록 방향을 바꾸는 방안을 제안했다. (개선 제안)
  - 조건: Line이 LineRequest를 받는 생성자에 대한 제안이다. 작성자는 반영했다고 답했으나 변경된 구현은 이 대화에서 확인되지 않는다.

- [ ] 도메인이 DTO를 아는 설계의 이유를 검토하고, DTO의 변경에 도메인이 영향을 받는 의존 방향을 피하자는 의견이다. (토론)
  - 조건: 리뷰 참여자는 처음에는 설계 이유와 바람직한 관계를 질문한 뒤 도메인에서 DTO로 향하는 의존을 피하자고 설명했다. 작성자는 급하게 구현하며 놓쳤고 도메인이 DTO를 알 필요가 없다는 의견에 동의했으나, 실제 변경 여부는 제시되지 않았다.
