# FC0426 · 합성 테스트 데이터의 구성

## 검토 질문

- [ ] 실제 사용자·운영 데이터 대신 검증에 필요한 최소 조건의 합성 데이터를 사용하는가?

**직접 작성한 예시**

```java
User testUser = User.register("sample-user");
users.save(testUser);
```

**적용 설명:** 실제 사용자 자료 대신 합성 데이터를 만든다. 테스트가 필요로 하는 최소 조건만 준비한다.

## 구체적인 검토 사례

- [ ] 현재 사용하는 데이터가 테스트용 데이터가 아니라는 점을 들어 다음 단계에서 테스트 데이터 구성을 변경해 보자고 제안했다. (개선 제안)
  - 조건: 현재 단계에서 즉시 변경하라는 요구는 아니다. 작성자는 다음 단계에 반영하겠다고 답했으며, 구체적인 대체 방식이나 구현 결과는 제시되지 않았다.

- [ ] 각 테스트의 준비 과정에서 데이터가 삽입되므로 테스트 사이에 DB 데이터를 정리하지 않으면 검증에 영향을 줄 수 있다는 점을 관찰했다. (관찰)
  - 조건: 리뷰 참여자는 값을 출력한 뒤 기존의 DB 초기화에 대한 이해를 수정했다고 설명했다. 이미 추가된 테스트 후 정리 코드에 대한 학습성 발언이며, 현재 구현에 정리 처리가 없다는 결함 보고는 아니다. 본문은 'drop'이라고 표현하지만 제시된 코드는 TRUNCATE TABLE과 식별자 재설정을 사용한다.

- [ ] 조회 테스트에서 초기 데이터를 활용해 저장 과정 없이 조회만 검증하도록 구성할 수 있는지 제안했다. (개선 제안)
  - 조건: 작성자는 초기 데이터 의존을 피하고 초기 데이터가 없어도 테스트가 실행되도록 직접 저장했다고 설명했다. 조회 관심사 분리가 제안의 의도인지 되물었으나, 이에 대한 후속 답변은 없다.
