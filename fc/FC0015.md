# FC0015 · 커지는 메서드의 책임 분리

## 검토 질문

- [ ] 기능 추가로 커지는 메서드를 입력 변환·정책 판단·출력 변경처럼 의미 있는 단위로 나눌 수 있는가?

**직접 작성한 예시**

```java
void attachSession(HttpReply reply, Session session) {
    String value = sessionCookie(session.id());
    reply.addHeader("Set-Cookie", value);
}
```

**적용 설명:** 쿠키 문자열 구성과 응답 추가를 분리한다. sessionCookie는 인코딩·Secure·HttpOnly·SameSite 정책을 구현해야 한다.

## 구체적인 검토 사례

- [ ] 세션 처리 보완으로 addCookie()가 커질 수 있으므로 함수를 분리하는 방안을 제안했다. (조건부 제안)
  - 조건: 앞서 제안한 세션 조회·검사·쿠키 발급 로직을 추가하면서 함수가 커지는 경우를 고려한 제안이다.

- [ ] 여러 곳에서 자주 사용하는 HTTP 구분 문자열을 별도의 상수용 클래스로 분리하는 방식을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 톰캣의 Constants 클래스를 예로 들었다. 작성자는 상수의 반복 사용 때문에 이미 분리를 고민하고 있었으며 제안을 반영했다고 보고했다. 실제 변경 내용은 이 대화만으로 검증하지 않았다.

- [ ] findAll, findById, findByAccount에서 반복되는 사용자 매핑 람다를 상수로 분리해 관리할 것을 제안한다. (개선 제안)
  - 조건: 작성자는 중복을 인정하며 감사했지만, 이 답변만으로 상수 추출이 실제 반영되었다고 판단하지 않는다.
