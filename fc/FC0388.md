# FC0388 · 인증 대상 경로의 기본 정책

[소속 분야: 인증·보안·비밀값](../20-security.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0387](FC0387.md) · [다음 FC: FC0389 →](FC0389.md)

## 검토 질문

- [ ] 새 API 추가 시 인증 설정이 빠지지 않도록 기본 정책과 공개 예외를 명확히 관리하는가?

**직접 작성한 예시**

```java
AccessPolicy access = route.isPublic() ? PUBLIC : AUTHENTICATED;
if (access == AUTHENTICATED) requireAuthenticated(request);
```

**적용 설명:** 공개 경로만 명시적으로 예외 처리하는 기본 거절 접근이다. 인증 뒤 자원별 인가도 별도로 수행한다.

## 구체적인 검토 사례

- [ ] API를 추가할 때마다 로그인 필요 여부를 설정에 수동으로 반영하다가 누락하지 않도록 인증 대상 경로 관리 방식을 개선해보자는 제안이다. (개선 제안)
  - 조건: 작성자는 /user 또는 /admin 접두사를 사용하는 방안을 제시하고 추가 의견을 들은 뒤 반영하겠다고 했다. 리뷰어는 서비스 특성에 따라 대부분의 기능에 로그인이 필요하면 현재처럼 제외 경로를 지정하는 방식도 좋고, 그렇지 않으면 인증이 필요한 API의 접두사를 통일하면 관리하기 편하다고 설명했다. 특정 방식으로의 변경을 일률적으로 요구한 것은 아니며, 실제 반영 여부는 확인되지 않는다.

- [ ] 관리자에게도 인증·인가가 필요한지, 필요하다면 상품 API 사용을 관리자에게만 제한할 방법을 고민하도록 제안한다. (개선 제안)
  - 조건: 리뷰 참여자는 미션 요구사항이 아니라는 점을 명시했다. 인증·인가 필요성과 구현 방법을 탐색하는 제안이며, 필수 요구사항 위반으로 단정하지 않는다.

- [ ] 사용자 이름으로 관리자 여부를 검사하는 부분은 우선 URL 구분으로 바꾸고 인증·인가는 추후 구현하도록 요청했다. (학습 제약)
  - 조건: 현재 단계의 구현 범위를 정한 요청이다. URL 구분 자체의 보안성을 보장하거나 인증·인가가 불필요하다고 일반화한 발언은 아니다. 실제 변경 결과는 제시되지 않았다.
