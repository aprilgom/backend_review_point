# FC0452 · JDBC 자원의 해제 범위

[소속 분야: 트랜잭션·자원 수명](../23-transaction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0451](FC0451.md)

## 검토 질문

- [ ] ResultSet·Statement·Connection 각각의 소유자와 종료 범위를 정하고 예외에도 안전하게 해제하는가?

**직접 작성한 예시**

```java
try (PreparedStatement ps = connection.prepareStatement(sql);
     ResultSet rows = ps.executeQuery()) {
    while (rows.next()) consume(rows);
}
```

**적용 설명:** ResultSet과 Statement를 범위에 포함해 역순 해제한다. 이 조각은 호출자가 소유한 connection을 닫지 않는다.

## 구체적인 검토 사례

- [ ] try-with-resources 밖에서 생성한 ResultSet을 수동으로 닫아야 하는지 확인을 요청했다. (설계 질문)
  - 조건: 리뷰어가 자원 종료 필요성을 질문한 것으로, 실제 자원 누수 여부나 후속 변경은 확인되지 않는다.

- [ ] BufferedReader를 사용한 뒤 닫아야 하며, try-with-resources를 활용할 수 있다고 제안했다. (개선 제안)
  - 조건: 리뷰어는 AutoCloseable 구현을 근거로 자동 자원 해제 방식을 제시했다. 작성자는 적용하겠다고 답했지만 실제 적용 결과나 입력 스트림 소유권에 관한 논의는 없다.

- [ ] 예외 발생 시에도 ResultSet이 닫히도록 finally 또는 try-with-resources에서 종료를 처리하자고 제안했다. (개선 제안)
  - 조건: 현재처럼 처리 로직 뒤에서 close()를 호출할 때 예외 경로에서도 닫히는지 질문하며 제안했다. 실제 누수 발생이나 변경 완료는 확인되지 않는다.
