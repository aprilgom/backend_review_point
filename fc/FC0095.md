# FC0095 · 결제 API 클라이언트의 연결 타임아웃을 5초, 읽기 타임아웃을 30초로 설정한 이유를 질문했다.

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0081](FC0081.md) · [다음 FC: FC0073 →](FC0073.md)

- [ ] 결제 API 클라이언트의 연결 타임아웃을 5초, 읽기 타임아웃을 30초로 설정한 이유를 질문했다. (설계 질문)
  - 조건: 설정으로 분리한 점은 긍정적으로 평가했으며, 타임아웃 값이 잘못되었다고 단정한 것은 아니다. 해당 값을 선택한 근거에 대한 작성자 답변은 제공되지 않았다.

- [ ] 연결 타임아웃과 읽기 타임아웃의 역할을 알아보고 각각 5초와 30초로 설정한 값이 적절한지 검토해보자는 제안이다. (개선 제안)
  - 조건: 현재 값이 잘못되었다고 단정하거나 대체 값을 지정한 것은 아니다. 작성자의 설명이나 후속 변경 보고는 없다.

- [ ] Connection Timeout과 Read Timeout을 각각 어떤 근거로 설정했는지, 특히 서로 역할이 다른 두 타임아웃을 동일하게 30초로 둔 이유를 질문했다. (설계 질문)
  - 조건: 리뷰 참여자는 최초의 1ms·30초 언급을 후속 커밋의 30초·30초로 정정했으며 질문 자체를 철회하지는 않았다. 작성자는 결제 승인 여부와 사용자 대기 시간을 고려했다고 답했다. 리뷰 참여자는 인용된 문서의 30~60초 권고가 Read Timeout에 관한 것임을 짚고 두 타임아웃의 역할을 다시 물었다. 작성자는 이후 Connection Timeout을 10초로 변경했다고 보고했으나, 그 값의 적절성이 확인된 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
HttpClient client = HttpClient.newBuilder()
    .connectTimeout(Duration.ofSeconds(2)).build();
HttpRequest request = HttpRequest.newBuilder(endpoint)
    .timeout(Duration.ofSeconds(5)).GET().build();
```

**적용 설명:** JDK HTTP 클라이언트의 연결·요청 제한 예시다. 숫자는 예시이며 읽기 타임아웃과 요청 전체 제한의 의미를 혼동하지 않는다.
