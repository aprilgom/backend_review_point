# FC0027 · 여러 조회 메서드에 중복된 User 매핑 코드를 RowMapper 구현 클래스로 분리하도록 제안했다.

[소속 분야: 추상화·중복](../01-abstraction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0025](FC0025.md) · [다음 FC: FC0011 →](FC0011.md)

**혼합·경계:** RowMapper 활용 사례와 일반적인 결과 매핑·중복 제거가 겹침.

- [ ] 여러 조회 메서드에 중복된 User 매핑 코드를 RowMapper 구현 클래스로 분리하도록 제안했다. (개선 제안)
  - 조건: 리뷰어는 코드 전반의 매핑 중복을 근거로 별도 클래스 추출을 제안했다. 작성자의 답변이나 변경 여부는 이 단위에 없다.

- [ ] 반복될 것으로 예상되는 RowMapper 생성 로직을 메서드로 추출해 재사용하거나 상수로 두는 방안을 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 저장소의 매핑 로직이 반복될 것으로 추측하며 재사용을 제안했고, 매번 생성하지 않도록 상수화하는 대안도 제시했다. 작성자는 원래 계획했던 작업이라며 RowMapper 상수화를 반영했다고 보고했으나 실제 변경 결과는 이 대화만으로 확인되지 않는다.

- [ ] 조회 결과를 Reservation 객체로 매핑하는 중복 코드를 RowMapper로 추출해 재사용하자는 제안이다. (개선 제안)
  - 조건: 원문 맥락 확인

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
User mapUser(ResultSet row) throws SQLException {
    return new User(row.getLong("id"), row.getString("name"));
}
```

**적용 설명:** 순수 JDBC 결과 매핑을 재사용한다. 조회 컬럼 별칭·NULL 처리 계약이 다른 쿼리에는 그대로 적용하지 않는다.
