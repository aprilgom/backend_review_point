# FC0255 · 로그인 실패 시 401.html로 리다이렉트한다는 요구사항 대신 401 응답으로 구현한 이유를 묻는다.

[소속 분야: 예외·실패 계약](../13-errors.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0253](FC0253.md)

- [ ] 로그인 실패 시 401.html로 리다이렉트한다는 요구사항 대신 401 응답으로 구현한 이유를 묻는다. (설계 질문)
  - 조건: 작성자는 앞서 로그인 처리와 오류 응답 책임을 분리하기 위해 추후 ExceptionHandler를 둘 계획이며 현재는 변경 범위 때문에 미뤘다고 설명했다. 리뷰 참여자의 직접 관심사는 책임 분리 제안이 아니라 실패 시 리다이렉트 요구사항과의 차이였다. 작성자는 이 차이에 별도 이유가 없으며 정적 응답 리팩터링 중 잘못 적용했다고 답하고 수정했다고 보고했다. 후속 이미지 첨부 내용과 실제 수정 결과는 확인하지 않았다.

- [ ] 로그인 실패 시 401.html로 리다이렉트해야 한다는 미션 요구사항과 현재 응답 처리가 다르다고 지적한다. (문제 보고)
  - 조건: 리뷰어는 로그인 실패 시 리다이렉트한다는 요구사항을 직접 인용했다. 작성자는 리다이렉션하도록 수정했다고 보고했으나 변경된 코드나 동작 검증 결과는 제공되지 않았다.

- [ ] 로그인 실패 시 404.html로 리다이렉트하는 동작 대신 미션 요구사항에 맞게 401로 응답할 것을 제안했다. (문제 보고)
  - 조건: 리뷰 참여자가 현재 동작을 문제로 보고하면서 다음 미션 진행 중 확인하도록 요청했다. 해당 리뷰의 승인 여부와 별개로, 이 오류 처리의 수정 결과는 대화에서 확인되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```http
HTTP/1.1 303 See Other
Location: /login-error
```

**적용 설명:** 실패 안내 화면으로 이동하는 계약 예다. 인증 실패 상태를 반환하는 API 계약과 리다이렉트 화면 흐름을 혼동하지 않는다.
