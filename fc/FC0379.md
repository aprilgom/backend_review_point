# FC0379 · 서비스가 컨트롤러와 소통할 때 도메인 객체를 그대로 노출하면 어떤 문제가 생길 수 있는지 질문했다.

[소속 분야: 책임·계층 경계](../19-responsibility.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0383](FC0383.md) · [다음 FC: FC0384 →](FC0384.md)

- [ ] 서비스가 컨트롤러와 소통할 때 도메인 객체를 그대로 노출하면 어떤 문제가 생길 수 있는지 질문했다. (설계 질문)
  - 조건: 계층 경계에서 도메인을 노출하는 설계에 대한 질문이다. 구체적인 문제나 대안은 본문에 제시되지 않았고 작성자의 답변도 없다.

- [ ] 컨트롤러가 도메인을 알지 않아야 한다고 판단한 이유와 서비스에서 Response 객체를 생성해도 된다고 판단한 이유를 설명해 달라는 질문이다. (설계 질문)
  - 조건: 작성자는 다른 크루와 논의한 뒤 도메인 처리와 Response 객체 생성을 서비스로 옮겨 컨트롤러에는 URI와 서비스의 매핑만 남겼다고 설명했다. 리뷰 참여자는 그 결론의 근거를 요청했으며, 컨트롤러의 도메인 접근 금지나 서비스의 응답 객체 생성을 보편 규칙으로 확정한 것은 아니다.

- [ ] 도메인 객체가 Controller에 노출될 때 어떤 문제가 생길 수 있는지 질문했다. (설계 질문)
  - 조건: 리뷰어는 발생 가능한 문제를 묻는 형식으로 제기했다. 작성자는 조사 후 컨트롤러의 엔티티 내부 접근이 비즈니스 규칙 분산이나 캡슐화 문제로 이어질 수 있다고 설명했지만, 이는 작성자의 학습 답변이며 해당 문제가 실제 발생했다는 확인은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
record OrderSummary(long id, long total) {}
OrderSummary getOrder(long id) { return summarize(orders.get(id)); }
```

**적용 설명:** 컨트롤러에 가변 도메인 객체·지연 로딩 상태가 새어 나가지 않게 결과를 제한한다.
