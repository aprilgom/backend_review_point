# FC0473 · 사용자 언어로 표현하는 실패

[소속 분야: UI 동작·사용성](../25-ui-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0470](FC0470.md) · [다음 FC: FC0469 →](FC0469.md)

## 검토 질문

- [ ] 내부 ID나 구현 용어 대신 사용자가 이해할 대상과 행동으로 오류를 설명하는가?

**직접 작성한 예시**

```java
throw new UserVisibleFailure("상품을 찾을 수 없습니다. 목록을 새로고침해 주세요.");
```

**적용 설명:** 내부 ID 같은 구현 용어 대신 사용자 행동을 설명한다. 로그에서는 별도 추적 식별자를 유지한다.

## 구체적인 검토 사례

- [ ] 상품 조회 실패 메시지에서 사용자에게 id라는 내부 용어를 알릴 필요가 있는지 묻는다. (설계 질문)
  - 조건: 작성자는 사용자가 id 값을 알 필요는 없다고 답하며 동작 성공·실패를 기준으로 메시지를 수정했다고 보고했다. 수정된 문구 자체는 제공되지 않았다.

- [ ] 현재 장바구니 화면과 요구사항 화면 사이에 어떤 차이가 있는지 확인하도록 질문했다. (설계 질문)
  - 조건: 구체적인 화면 차이는 첨부 이미지에만 제시되어 본문만으로 어떤 요소가 다른지 확인할 수 없다. 작성자는 화면을 변경했다고 보고했으나 변경 내용과 요구사항 충족 여부는 확인되지 않았다.

- [ ] 상품 관리 요청에서 예외가 발생하면 브라우저 사용자에게도 경고창 등으로 알려주는 방안을 제안한다. (개선 제안)
  - 조건: 인라인 코드에서는 오류를 콘솔에 출력하고 있다. 작성자는 반영했다고 답했으나 실제 경고 표시 동작은 확인되지 않았다.
