# FC0264 · 로그를 남겨야 하는 상황과 목적, 현재 로깅을 적용한 판단 기준을 설명해 달라고 질문했다.

[소속 분야: 로그·관측](../15-observability.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0262](FC0262.md) · [다음 FC: FC0263 →](FC0263.md)

- [ ] 로그를 남겨야 하는 상황과 목적, 현재 로깅을 적용한 판단 기준을 설명해 달라고 질문했다. (토론)
  - 조건: 작성자는 모든 요청과 완료를 기록하다 로그가 많아져 상태 변경 작업 위주로 줄였으며, 로그인·로그아웃은 예외적으로 포함했다고 설명했다. 리뷰 참여자는 정상 응답이어도 추적이 필요한 엣지 케이스처럼 꼭 확인할 상황에 기록하는 자신의 기준을 소개하고, 운영 경험을 통해 기준을 세우도록 권했다. 특정 로그의 삭제나 현재 로그량의 부적절성을 확정하지는 않았다.

- [ ] 어떤 정보를 로그로 남기며 로깅 범위를 어떤 기준으로 선택했는지 설명을 요청했다. (설계 질문)
  - 조건: 작성자는 디버깅을 목적으로 하되 과도한 정보가 중요한 정보를 가리지 않도록 예외와 요청 내용 및 성공 여부로 로깅 범위를 최소화했다고 설명했다. 리뷰어가 이 기준의 적절성을 확인한 후속 발언은 없다.

- [ ] 로그에 어떤 정보를 남겨야 하며 각 정보를 남기는 목적이 무엇인지 검토하도록 제안했다. (개선 제안)
  - 조건: 작성자는 문제 추적과 사용자 문의 대응을 목적으로 들고 타임스탬프, 로그 레벨, 이벤트 메시지, 요청 정보를 예시로 제시했다. 이는 작성자의 설명이며 기록 내용의 충분성이 검증된 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
logger.info("export completed: jobId={}, count={}", jobId, count);
metrics.recordDuration("export", elapsed);
```

**적용 설명:** 완료 이력·장애 진단·성능 관측의 목적을 구분한다. 반복 호출량과 보관 비용도 고려한다.
