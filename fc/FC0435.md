# FC0435 · 다른 테스트와 유사하게 @BeforeEach를 사용하지 않고 준비 코드를 별도 메서드로 분리한 판단 과정을 묻는다.

[소속 분야: 테스트 준비·격리](../22-test-isolation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0438](FC0438.md) · [다음 FC: FC0441 →](FC0441.md)

- [ ] 다른 테스트와 유사하게 @BeforeEach를 사용하지 않고 준비 코드를 별도 메서드로 분리한 판단 과정을 묻는다. (설계 질문)
  - 조건: 리뷰 참여자는 테스트 작성 방식의 통일성도 고려할 수 있다고 언급했다. 작성자는 준비 코드가 테스트 관심사에 속하는지로 분리 여부를 정하고, 클래스 내 약 70% 이상의 테스트에서 필요한 변수라면 @BeforeEach를 쓰는 개인 기준이 있다고 설명했다. 해당 준비 코드는 한 번만 필요해 메서드로 분리했다고 답했으며, 이 비율은 리뷰 참여자가 요구한 규칙이 아니다.

- [ ] 모든 테스트에서 반복되는 준비 코드를 @BeforeEach로 분리하는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 제안에 동의했지만, 실제 변경 여부는 이 대화에서 확인되지 않는다.

- [ ] MenuGroupService와 ProductGroupService 테스트에도 @BeforeEach를 활용하면 좋겠다고 제안하며, 사용하지 않은 이유가 테스트 수가 적어서인지 묻는다. (개선 제안)
  - 조건: 작성자는 앞서 작성한 테스트들의 설정을 @BeforeEach로 옮기는 것을 잊었다고 답하고 다음 단계에 반영하겠다고 밝혔다. 실제 반영은 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
@BeforeEach void prepare() {
    repository = new MemoryRepository();
}
```

**적용 설명:** 모든 테스트에 필요한 공통 준비만 둔다. 특정 시나리오의 중요한 준비 조건은 테스트 안에 남긴다.
