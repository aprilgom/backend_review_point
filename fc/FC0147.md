# FC0147 · Caffeine을 Redis 및 다른 로컬 캐시 구현체와 비교해 선택 근거와 특징을 설명하도록 요청한다.

[소속 분야: 의존성·교체 가능성](../09-dependency.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0162](FC0162.md) · [다음 FC: FC0165 →](FC0165.md)

- [ ] Caffeine을 Redis 및 다른 로컬 캐시 구현체와 비교해 선택 근거와 특징을 설명하도록 요청한다. (토론)
  - 조건: 작성자는 단일 서버에서 Redis가 인프라 복잡도를 늘리며, 직접 구현보다 라이브러리의 안정성과 TTL 지원을 활용하려고 Caffeine을 선택했다고 설명했다. 리뷰 참여자는 단일 서버에서 Redis가 불필요할 수 있다는 의견에 동의하고, Spring 기본 캐시와 여러 로컬 캐시 구현체도 비교해 보라고 제안했다. Caffeine의 성능이 좋다는 언급은 참여자의 설명이며 실제 비교 측정 결과는 제시되지 않았다.

- [ ] 토큰 필드와 이름이 Provider 외부에서도 사용되는지, id를 user_id로 바꾸거나 token 이름을 변경할 때 다른 코드에 영향이 없는지 확인해 보자는 제안이다. (개선 제안)
  - 조건: 리뷰어는 해당 정보가 Provider 안에서만 쓰인다면 괜찮다는 조건을 제시했다. 작성자는 claim 사용처가 많아 시간상 수정하지 못했고, token prefix는 상수화했으며 생성과 파싱을 해당 클래스에서만 하면 큰 문제가 없다고 생각한다고 답했다. 리뷰어는 후속으로 제어하기 어려운 변경 지점도 고려해 보라고 권했다.

- [ ] 다른 서버와 통신하는 구조가 MSA를 가정한 것인지 묻고, 이번 미션에는 과할 수 있다는 의견을 밝혔다. (토론)
  - 조건: 리뷰어는 단일 모듈에서의 의존성 관리가 쉽지 않을 수 있다고 언급하면서 구현을 긍정적으로 평가했다. 과도하다는 평가는 개인 의견이며 서버 분리를 제거하라는 명시적 요구나 작성자의 설계 의도 확인은 없다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Cache cache = new LocalCache(maxEntries, ttl);
// 다른 서버 인스턴스의 쓰기는 이 로컬 캐시에 자동 반영되지 않는다.
```

**적용 설명:** 로컬 캐시와 원격 공유 캐시를 지연·일관성·메모리·장애 처리로 비교한다. LocalCache는 가상 타입이다.
