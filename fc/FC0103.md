# FC0103 · 동시 중복 삽입의 방어

## 검토 질문

- [ ] 사전 조회를 동시에 통과해도 DB 제약 등 최종 저장 경계에서 중복을 막을 수 있는가?

**직접 작성한 예시**

```sql
ALTER TABLE subscription
ADD CONSTRAINT unique_subscription UNIQUE (account_id, topic_id);
```

**적용 설명:** 사전 존재 확인만으로 막을 수 없는 동시 중복 삽입을 제약으로 방어한다. 제약 위반을 응답 계약에 맞게 처리한다.

## 구체적인 검토 사례

- [ ] **상황:** 두 요청이 모두 중복 검사를 통과한다.
  - **판단 기준:** 최종 저장 경계에 유일성 제약을 둔다.

- [ ] **상황:** 제약 위반이 내부 오류로 노출된다.
  - **판단 기준:** 업무에 맞는 중복 결과로 변환한다.
