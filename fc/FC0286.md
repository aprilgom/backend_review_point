# FC0286 · 역마다 개별 조회 쿼리를 실행하는 대신 역들을 한 번에 조회해 처리하여 쿼리 수를 줄이는 방안을 고려하자.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0265](FC0265.md) · [다음 FC: FC0287 →](FC0287.md)

- [ ] 역마다 개별 조회 쿼리를 실행하는 대신 역들을 한 번에 조회해 처리하여 쿼리 수를 줄이는 방안을 고려하자. (개선 제안)
  - 조건: 리뷰 참여자는 실제 서비스라면 다수의 조회 쿼리로 DB 부하가 커질 수 있다고 우려했다. 측정된 부하에 대한 보고는 아니며, 작성자는 findAll로 가져온 뒤 처리하도록 수정했다고 보고했다.

- [ ] 노선 순회마다 역 조회 쿼리를 실행하지 말고 필요한 정보를 일괄 조회한 뒤 처리해 반복 조회를 줄이도록 제안한다. (개선 제안)
  - 조건: 리뷰어는 반복문 안의 DB 조회가 반복 횟수만큼 실행될 수 있다는 점과 성능상 이점을 설명했다. 작성자는 전체 역과 노선을 두 번의 쿼리로 조회하고 Line에서 역 목록을 매핑하도록 변경했다고 보고했다. 실제 쿼리 횟수나 성능 측정 결과는 제시되지 않았다.

- [ ] 역 ID를 각각 조회하기보다 여러 ID를 묶어 하나의 쿼리로 조회하는 방식을 고려하자는 제안. (개선 제안)
  - 조건: 역 삽입 과정에서 두 ID를 각각 조회하는 코드에 대한 쿼리 수 감소 제안이다. 성능 측정 결과나 실제 적용 여부는 제시되지 않았다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
List<Station> stations = stationStore.findAllByIds(stationIds);
```

**적용 설명:** 역별 반복 조회 대신 일괄 조회한다. 반환 순서는 입력 순서와 다를 수 있어 필요하면 ID로 다시 배치한다.
