# FC0266 · 저장 결과의 불필요한 재조회

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0268](FC0268.md) · [다음 FC: FC0276 →](FC0276.md)

## 검토 질문

- [ ] 저장 API가 필요한 값을 반환한다면 같은 객체를 즉시 다시 조회할 필요가 있는가?

**직접 작성한 예시**

```java
Payment saved = payments.save(payment);
return new PaymentReply(saved.id(), saved.amount());
```

**적용 설명:** save가 필요한 생성 ID·DB 기본값을 반영한 객체를 반환한다는 계약일 때 재조회를 줄인다.

## 구체적인 검토 사례

- [ ] 저장한 Payment 객체를 그대로 사용해 ID로 다시 조회하는 불필요한 조회를 없애자는 제안이다. (개선 제안)
  - 조건: 리뷰 참여자는 저장 후 객체를 사용하면 재조회가 필요하지 않을 것으로 보았다. 작성자는 PaymentService.savePayment가 Payment 객체를 직접 반환하도록 수정했다고 보고했다. 실제 조회 횟수 감소를 측정하거나 검증한 내용은 없다.

- [ ] 매 요청마다 RequestMapping을 초기화하지 말고 애플리케이션 실행 시 한 번 초기화해 재사용하자고 제안했다. (개선 제안)
  - 조건: 요청별 입출력을 처리하는 process 안에서 초기화가 반복되는 점을 근거로 한 제안이다. 성능 측정 결과나 재사용 구현의 적용 결과는 제시되지 않았다.

- [ ] 저장 성공 후 DB를 다시 조회하지 않고, 확보한 ID와 필드 정보로 객체를 만들어 반환하는 방안을 제안했다. (개선 제안)
  - 조건: 저장에 성공했고 반환 객체 구성에 필요한 ID와 필드 정보를 가지고 있는 상황을 전제로 한 제안이다. 실제 변경 여부는 제시되지 않았다.
