## 검토 질문

- [ ] 깊은 OFFSET의 비용과 키셋 방식의 제약을 이해하고 이동·정렬·동시 변경 요구에 맞게 선택했는가?

**직접 작성한 예시**

```sql
SELECT id, title FROM post
WHERE id > :last_id ORDER BY id LIMIT 50;
```

**적용 설명:** 깊은 OFFSET을 피하는 키셋 페이지 예다. 임의 페이지 이동·복합 정렬·동시 변경의 의미는 다르다.

## 구체적인 검토 사례

- [ ] **상황:** 페이지가 깊어질수록 조회가 느려진다.
  - **판단 기준:** OFFSET과 키셋 비용을 비교한다.

- [ ] **상황:** 키셋으로 바꾼 뒤 임의 페이지 이동이 필요하다.
  - **판단 기준:** 기능 요구와 안정적인 정렬 기준을 함께 정한다.
