# FC0278 · enum을 순회해 값을 찾는 대신 미리 만든 Map으로 조회하는 대안을 소개하고, 메모리 비용을 고려해 필요한 곳에만 적용하는 방향을 논의한다.

[소속 분야: 성능·측정](../16-performance.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0289](FC0289.md) · [다음 FC: FC0290 →](FC0290.md)

- [ ] enum을 순회해 값을 찾는 대신 미리 만든 Map으로 조회하는 대안을 소개하고, 메모리 비용을 고려해 필요한 곳에만 적용하는 방향을 논의한다. (토론)
  - 조건: 리뷰 참여자는 Spring의 HttpMethod 구현을 예로 들었지만 현재 원소 수와 로직 규모에서는 필수 변경이 아니라 대안 소개라고 명시했다. 작성자는 순회하던 enum에 Map을 적용했다고 보고하면서 모든 enum에 적용하면 메모리를 차지한다는 우려를 제기했다. 리뷰 참여자는 메모리가 부족한 환경에서는 일괄 적용이 위험할 수 있다며 필요한 곳에만 적용하자는 데 동의했다. 최초 대안을 철회한 것은 아니다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```java
Map<String, State> byCode = Arrays.stream(State.values())
    .collect(Collectors.toUnmodifiableMap(State::code, Function.identity()));
```

**적용 설명:** 반복 조회가 충분히 많을 때 사전 인덱스가 이득인지 비교한다. 코드 중복과 모르는 코드의 처리도 정한다.
