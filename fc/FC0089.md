# FC0089 · 특정 테스트 클래스에만 있는 프로파일 설정을 application.yml로 옮겨 설정을 명시적으로 관리하도록 제안했다.

[소속 분야: 빌드·환경·배포](../04-build-config.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0076](FC0076.md) · [다음 FC: FC0082 →](FC0082.md)

**혼합·경계:** 설정 파일 형식·중복 관리와 Spring 프로파일 설정이 섞임.

- [ ] 특정 테스트 클래스에만 있는 프로파일 설정을 application.yml로 옮겨 설정을 명시적으로 관리하도록 제안했다. (개선 제안)
  - 조건: 리뷰 참여자는 설정 분산과 코드 파악의 어려움을 이유로 들고, 파일 관리가 유지보수에 효과적이라는 의견과 향후 환경별 설정 학습 맥락을 덧붙였다. 작성자는 테스트 쪽 application.yml에 spring.profiles.active를 추가했다고 보고했다.

- [ ] 설정 파일을 application.properties에서 application.yml로 변경한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 properties에서는 반복해서 작성해야 하는 경로를 yml에서는 중복 없이 표현할 수 있어 더 간편하다고 설명했다. 변경을 문제로 확정하거나 원래 형식으로 되돌리라고 요구한 것은 아니다.

- [ ] application.yml과 properties 파일에 동일한 설정 정보를 중복해서 둔 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 실수로 파일을 삭제하지 못했다며 삭제하겠다고 답했다. 실제 삭제 여부는 이 대화에서 확인되지 않는다.

**직접 작성한 예시 · 첫 번째 백엔드 항목**

```properties
# 애플리케이션이 읽는 단일 설정 파일 예
db.pool.max=8
feature.export=false
```

**적용 설명:** 동일 키를 여러 형식의 파일에 중복하지 않는 예시다. 프로파일은 실제 환경 차이를 표현하며 로딩 우선순위를 문서화한다.
