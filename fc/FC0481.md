# FC0481 · 변경 후 파생 화면 상태의 갱신

[소속 분야: UI 동작·사용성](../25-ui-behavior.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0479](FC0479.md)

## 검토 질문

- [ ] 삭제·취소 뒤 순번·합계·정렬 같은 파생 상태를 최신 서버 결과와 일치시키는가?

**직접 작성한 예시**

```javascript
await cancelWaiting(waitingId);
const updated = await fetchMyWaiting();
renderWaiting(updated);
```

**적용 설명:** 취소한 DOM만 제거하지 않고 서버 기준 순번을 갱신한다. 재조회 실패·경쟁 요청의 오래된 응답 처리도 설계한다.

## 구체적인 검토 사례

- [ ] 대기 취소 시 해당 DOM 항목만 제거하면 같은 슬롯의 남은 대기 순번이 화면에서 갱신되지 않을 수 있으므로, 취소 성공 후 목록을 다시 조회하거나 순번을 재계산하는 방안을 제안했다. (위험 지적)
  - 조건: 여러 명이 같은 슬롯에 대기하는 상태에서 앞 순번 대기가 취소되는 경우에 대한 우려다. 리뷰어는 서버가 조회 시 순번을 다시 계산한다는 전제로 loadMyReservations() 재호출 또는 현재 목록의 같은 슬롯 순번 재계산을 대안으로 제시했다. 작성자는 DOM 항목만 제거하는 대신 loadMyReservations()를 재호출하도록 변경하여 서버가 재계산한 waitingNumber를 렌더링한다고 보고했으나, 실제 변경 결과나 동작 검증은 이 대화에서 확인되지 않는다.
