# FC0009 · 테스트 준비 절차의 재사용

## 검토 질문

- [ ] 반복되는 객체 생성과 저장 준비를 공통화하면서 시나리오별 중요한 차이는 호출부에 남겼는가?

**직접 작성한 예시**

```java
private User savedUser(String name) {
    return users.save(new User(name));
}
User owner = savedUser("owner");
```

**적용 설명:** 여러 테스트의 동일한 저장 준비를 묶은 예시다. 테스트마다 저장소를 격리한다.

## 구체적인 검토 사례

- [ ] 여러 테스트에서 반복되는 코드를 메서드로 분리해 이후 테스트 추가에도 재사용할 수 있도록 제안했다. (개선 제안)
  - 조건: 테스트의 검증 내용 변경보다는 공통 코드 추출과 재사용에 관한 제안이다.

- [ ] 테스트에서 공통으로 반복되는 코드를 메서드로 분리하는 방안을 제안했다. (개선 제안)
  - 조건: 작성자는 메서드를 분리했다고 답했다. 실제 변경 결과는 이 대화만으로 확인되지 않는다.

- [ ] 인수테스트에서 자주 사용하는 API 요청을 의미 있는 메서드로 분리해 시나리오가 한눈에 보이도록 리팩터링하자는 제안이다. (개선 제안)
  - 조건: 리뷰어는 한글 요청 메서드를 예로 들며 시간이 괜찮을 때 적용해볼 팁으로 제시했다. 작성자는 이 방식을 사용하니 테스트 코드가 더 깔끔해졌다고 보고하고 시나리오를 추가해보겠다고 답했다. 실제 변경 내용은 이 대화만으로 검증되지 않는다.
