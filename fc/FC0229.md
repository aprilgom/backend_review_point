# FC0229 · 사용 중인 자원의 삭제 제한

[소속 분야: 도메인 검증](../12-validation.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0233](FC0233.md) · [다음 FC: FC0235 →](FC0235.md)

## 검토 질문

- [ ] 참조·사용 중인 자원 삭제를 막는 정책이 실제 데이터 관계와 일치하고 경쟁 조건에도 유지되는가?

**직접 작성한 예시**

```java
if (bookings.usesTheme(themeId)) throw new ThemeInUse();
themes.delete(themeId);
```

**적용 설명:** 사용 중 삭제 금지 규칙을 드러낸다. 검사 후 삽입 경쟁은 외래 키·트랜잭션 정책으로 보완한다.

## 구체적인 검토 사례

- [ ] 사용 중이지 않은 테마만 삭제할 수 있다는 규칙에 맞게 테마 삭제 로직을 수정해 달라고 요청했다. (개선 제안)
  - 조건: 참여자는 이 로직을 수정하면 다음 단계로 넘어가도 좋겠다고 했다. 구체적인 구현 문제와 수정 방식은 이 대화에 제시되지 않았으며, 이후 머지 안내만으로 해결 여부를 확정하지 않는다. 작성자가 별도로 언급한 사전 검증과 DB 예외 처리 논의는 직접 확인된 리뷰 요구로 확장하지 않는다.

- [ ] Theme의 검증 로직은 정적 팩토리 메서드보다 생성자에서 호출하는 편이 안전하다고 제안했다. (개선 제안)
  - 조건: 제시된 코드에서는 정적 팩토리 메서드에서 null 검증을 호출하고 있었다. 작성자는 정적 팩토리 메서드의 장점을 느끼지 못해 제거했다고 답했지만, 생성자 검증이 실제로 추가되었는지는 이 대화에서 확인되지 않는다.

- [ ] 진행 중인 체스방은 삭제할 수 없다는 요구사항이 삭제 로직에서 누락된 것인지 질문했다. (설계 질문)
  - 조건: 리뷰어가 누락으로 보인다고 확인을 요청한 상태이며, 작성자의 설명이나 후속 수정은 제공되지 않았다.
