# FC0451 · 커넥션 소유권과 해제 계약

[소속 분야: 트랜잭션·자원 수명](../23-transaction.md) · [전체 목차](../README.md) · [FC 번호별 목차](../FC_INDEX.md) · [← 이전 FC: FC0453](FC0453.md) · [다음 FC: FC0452 →](FC0452.md)

## 검토 질문

- [ ] 연결 상태만으로 소유권을 추측하지 않고 빌린 자원과 소유한 자원을 구분해 해제하는가?

**직접 작성한 예시**

```java
if (lease.ownedByCaller()) lease.connection().close();
// 트랜잭션에 빌린 커넥션은 소유한 경계가 해제한다.
```

**적용 설명:** autoCommit 값만으로 소유권을 판별하지 않는 대안이다. lease는 자체 자원 계약이며 풀 반환·예외 경로도 정의한다.

## 구체적인 검토 사례

**혼합·경계:** 직접 구현한 DataSourceUtils의 커넥션 해제 계약도 포함됨.

- [ ] DataSourceUtils.releaseConnection에서 connection.getAutoCommit()이 true일 때만 커넥션을 닫도록 한 이유를 질문했다. (설계 질문)
  - 조건: KJungW는 해당 조건이 어색하다고 느껴 이유를 물었으며, 결함으로 확정하지는 않았다. 작성자는 JdbcTemplate의 종료 로직을 DataSourceUtils로 옮기면서 꼬인 것 같다고 설명하고, 해당 DataSource의 커넥션이 존재할 때는 닫지 않도록 변경했다고 보고했다. 변경의 기술적 타당성과 실제 자원 해제 결과는 확인되지 않는다.

- [ ] unbindResource()도 고려했을 때, releaseConnection()에서 트랜잭션 진행 중인 커넥션을 해제하지 않도록 한 이유를 질문했다. (설계 질문)
  - 조건: 작성자는 releaseConnection()은 커넥션 단위 작업 후, unbindResource()는 트랜잭션 단위 작업 후 호출된다고 설명했다. 커넥션 단위 처리에서 트랜잭션에 속한 커넥션을 해제하면 트랜잭션 무결성을 해칠 수 있어 역할을 넘는 해제를 막았다는 설계 설명이며, 리뷰어가 결함을 확정하거나 변경을 요구한 것은 아니다.

- [ ] DataSourceUtils의 커넥션 획득 과정에서 bind를 제거한 이유가 비트랜잭션 호출에서 커넥션이 닫히지 않는 문제를 피하기 위한 것인지 질문했다. (설계 질문)
  - 조건: 작성자는 그 의도가 맞으며, 획득할 때마다 등록하면 일반 조회에서도 releaseConnection이 연결을 닫지 않으므로 획득과 등록을 분리했다고 설명했다. 추가로 등록과 해제를 TransactionTemplate으로 옮겼다고 보고했다. 현재 구현에 누수가 남아 있다는 지적으로 해석하지 않는다.
